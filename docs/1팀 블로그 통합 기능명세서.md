## 1. 개요

### 1.1 목적

세 사람은 각자 다른 언어로 각자의 블로그 서비스를 만든다. 이 문서는 그 세 서비스가 모두 '티스토리 같은 블로그'가 되도록 기준을 맞춘다.

| 이 문서가 맞추는 것 (What) | 각자 정하는 것 (How) |
| --- | --- |
| 필요한 기능과 우선순위 | 언어·프레임워크·DB·인증 방식 |
| 사용자가 확인할 수 있는 동작 규칙 | 화면 구성, 디자인, 화면 문구 |
| 방향이 갈리는 항목의 선택지 | 선택지 중 무엇을 고를지, 구현 수치 |

이 문서는 개발 범위를 정하는 기준이자, 서로의 서비스를 같은 기준으로 테스트하고 비교하는 체크리스트로 쓴다.

### 1.2 범위

**포함 범위**: 회원·인증, 블로그, 글, 카테고리, 태그, 댓글·방명록, 반응(공감·공유·저장), 구독·피드·알림, 검색, 홈·탐색, 블로그 관리, 서비스 관리, 공통 정책의 13개 영역

**제외 범위**

- 광고·수익화, 결제
- 모바일 앱, 이메일·푸시 알림
- 개인 도메인 연결, 스킨 HTML·CSS 직접 편집
- 기술 스택, 화면 목록·흐름, UI·문구 (각자의 개인 설계 문서에 둔다)

### 1.3 통합 원칙

**판단 기준**: "이 규칙을 서비스 밖에서 사용자로서 확인할 수 있는가?" 확인할 수 있으면 이 문서에, 확인할 수 없으면 개인 설계 문서에 둔다.

| 구분 | 의미 | 이 문서에서의 표기 |
| --- | --- | --- |
| 공통 | 세 서비스 모두 같은 규칙으로 구현한다 | 기능과 동작 규칙을 그대로 적는다 |
| 선택 | 허용된 방식 중 하나를 고른다 | 관련 기능의 6장 설명 바로 아래에 선택지와 방식별 규칙을 적고, 7장에 한 표로 모은다. 고른 방식은 개인 설계 문서에 밝힌다 |
| 자율 | 각자 자유롭게 정한다 | 적지 않는다 |

**제외 대상**: 특정 도메인 전용 내용, 서비스 개성(테마 등), UI와 화면 문구, 구현 수치, 세 문서의 방향이 충돌해 뺀 항목. 목록은 부록 B에 있다.

### 1.4 문서 보는 법

**기능 ID**: `영역코드-두 자리 번호`(예: `POST-03`). 번호는 영역 안에서 01부터 매기고, 기능이 추가되면 끝에 붙인다. 삭제된 번호는 다시 쓰지 않는다. 각자의 개인 설계 문서도 이 ID를 그대로 쓴다.

| 코드 | 영역 | 코드 | 영역 |
| --- | --- | --- | --- |
| AUTH | 회원·인증 | SUB | 구독·피드·알림 |
| BLOG | 블로그 | SRCH | 검색 |
| POST | 글 | HOME | 홈·탐색 |
| CAT | 카테고리 | MNG | 블로그 관리 (블로그 주인용) |
| TAG | 태그 | ADMIN | 서비스 관리 (서비스 관리자용) |
| CMT | 댓글·방명록 | COM | 공통 |
| SOC | 반응(공감·공유·저장) |  |  |

**우선순위**: 언제 만들지는 각자 일정에 맞추므로, 시기(1차·2차)는 정하지 않는다.

| 등급 | 의미 |
| --- | --- |
| P0 | 필수. 없으면 '티스토리 같은 블로그'라고 부르기 어렵다. 세 사람 모두 구현한다 |
| P1 | 권장. 있어야 쓸 만하다 |
| P2 | 확장. 여유가 있을 때 한다 |

**구분**: 기능 목록의 '공통'은 규칙이 하나인 기능, '선택(7.n)'은 7장의 해당 선택 항목에 따라 동작이 달라지는 기능이다.

**출처**: 원래 문서의 ID를 `지원 POST-01 / 민주 FR-13 / 서현 FR-04` 형태로 남긴다. 없는 문서는 적지 않는다.

## 2. 용어 정의

문서마다 다르게 쓰던 말을 하나로 고정한다. 이후 장에서는 아래 표현만 쓴다.

### 2.1 사용자

| 용어 | 정의 | 비고 |
| --- | --- | --- |
| 비회원 | 로그인하지 않고 서비스를 이용하는 사용자 | 민주·서현 문서의 '방문자'와 같다 |
| 회원 | 가입하고 로그인한 사용자 |  |
| 블로그 주인 | 어떤 블로그를 개설한 회원. 그 블로그의 글과 설정을 관리한다 | 블로그마다 판단한다. 자기 블로그에서는 주인, 남의 블로그에서는 회원이다 |
| 서비스 관리자 | 플랫폼을 운영하는 계정 | 가입으로는 될 수 없다 |

### 2.2 블로그와 글

| 용어 | 정의 | 비고 |
| --- | --- | --- |
| 플랫폼 | 여러 블로그를 담는 서비스 전체 | '블로그'와 구분한다 |
| 블로그 | 회원이 개설한 개인 공간. 이름, 주소, 소개, 글, 카테고리를 가진다 |  |
| 블로그 주소 | 블로그를 구분하는 고유한 영문 식별자 | 개설 후 바꿀 수 없다(4.2) |
| 블로그 이름 | 화면에 보이는 블로그 제목 | 언제든 바꿀 수 있다. 서현 문서의 '블로그 제목'과 같다 |
| 글 | 제목과 본문을 가진 블로그 게시물 |  |
| 본문 | 에디터로 작성한 글의 내용 | 저장 형식은 에디터 선택(7.4)에 따른다 |
| 발행 | 글을 저장해 공개 범위에 맞는 사람에게 보이게 하는 것 |  |
| 공개 · 비공개 | 공개는 누구나, 비공개는 블로그 주인만 볼 수 있다 | 4.1 |
| 임시저장 | 발행하지 않고 작성 중인 글을 보관하는 것 | 블로그 주인에게만 보인다 |
| 대표 이미지 | 목록에서 글을 대표하는 이미지(썸네일) | 지정하지 않으면 본문 첫 이미지 |
| 조회수 | 글이 열린 횟수 |  |

### 2.3 분류: 주제·카테고리·태그

| 용어 | 누가 정하나 | 정의 | 개수 |

| 태그 | 글쓴이 | 글에 붙이는 키워드 | 글 하나에 여러 개 |
| 미분류 | 플랫폼 | 카테고리가 없는 글이 들어가는 자리 | 이름 변경·삭제 불가 |

## 3. 사용자·권한

### 3.1 역할 정의

회원이 가질 수 있는 역할은 '일반 회원'과 '서비스 관리자' 두 가지뿐이다. 비회원과 블로그 주인은 역할이 아니라 요청마다 판단하는 상태다.

| 역할 | 판단 기준 | 설명 |
| --- | --- | --- |
| 비회원 | 로그인하지 않음 | 공개된 내용을 읽고 검색한다 |
| 회원 | 로그인함 | 댓글·공감·구독을 하고 블로그를 개설한다 |
| 블로그 주인 | 로그인한 회원이 그 블로그를 개설한 사람임 | 자기 블로그의 글·카테고리·댓글·설정을 관리한다 |
| 서비스 관리자 | 로그인한 계정의 역할이 서비스 관리자임 | 플랫폼을 운영한다(ADMIN). 자기 블로그에서는 일반 블로그 주인과 같다 |

- 가입하면 항상 일반 회원이다. 서비스 관리자는 화면이나 가입으로 될 수 없고, 운영자가 따로 지정한다.
- 블로그 주인은 블로그 하나당 한 명이다.

### 3.2 행동별 권한

○ 가능, ✕ 불가. '자기 것'은 자기 블로그나 자기가 쓴 것만 가능하다는 뜻이다.

| 행동 | 비회원 | 회원 | 블로그 주인 | 서비스 관리자 |
| --- | --- | --- | --- | --- |
| 공개 글 읽기, 홈·검색 | ○ | ○ | ○ | ○ |
| 비공개 글 읽기 | ✕ | ✕ | 자기 것 | 제재에 필요한 범위 |
| 댓글 쓰기 | ✕ | ○ | ○ | ○ |
| 댓글 수정 | ✕ | 자기 것 | 자기 것 | 자기 것 |
| 댓글 삭제 | ✕ | 자기 것 | 자기 블로그의 모든 댓글 | 숨김 처리(ADMIN-03) |
| 공감·구독·저장 | ✕ | ○ | ○ | ○ |
| 블로그 개설 | ✕ | ○ | ○ | ○ |
| 글 쓰기·수정·삭제 | ✕ | ✕ | 자기 블로그 | 자기 블로그 |
| 카테고리·태그·블로그 설정 | ✕ | ✕ | 자기 블로그 | 자기 블로그 |
| 블로그 관리(MNG) | ✕ | ✕ | 자기 블로그 | 자기 블로그 |
| 서비스 관리(ADMIN) | ✕ | ✕ | ✕ | ○ |

서비스 관리자도 남의 글·댓글 내용을 수정할 수 없다. 제재는 숨김으로만 한다(6.12).

### 3.3 접근 실패 처리

| 상황 | 처리 |
| --- | --- |
| 비회원이 로그인이 필요한 행동을 함 | 로그인으로 안내하고, 로그인하면 원래 보던 화면으로 돌아간다 |
| 로그인했지만 권한이 없음 (남의 블로그 관리, 일반 회원의 서비스 관리 접근) | 권한이 없다고 알린다(403) |
| 없는 블로그·글·카테고리, 삭제된 글 | 없는 글이라고 알린다(404) |
| 남의 비공개 글 | 403이 아니라 404로 처리해 글이 있다는 사실도 숨긴다 |
| 이용이 제한된 회원이 로그인함 | 로그인을 막고 제한 사유와 기한을 알린다(ADMIN-02) |
| 로그인이 만료됨 | 다시 로그인하면 원래 화면으로 돌아간다. 쓰던 글이 있으면 잃지 않는다(8.3) |

화면에서 버튼을 숨기는 것만으로는 부족하다. 주소를 직접 입력하거나 요청을 직접 보내도 같은 결과가 나와야 한다.

## 4. 공통 정책

### 4.1 공개 범위

1. 모든 글은 공개 또는 비공개다. 기본값은 공개다.
2. 비공개 글은 블로그 주인만 볼 수 있다. 다른 사람이 주소로 열면 없는 글(404)로 처리한다.
3. 비공개 글은 블로그 글 목록, 카테고리·태그 목록, 검색, 홈, 인기 글, 피드, 사이드바, 글 개수에서 모두 빠진다. 블로그 주인 본인에게만 보인다.
4. 발행한 뒤에도 공개 범위를 바꿀 수 있다.
5. 보호글·구독자 공개 같은 확장 범위는 선택 항목이다(7.8).

### 4.2 블로그 주소

1. 블로그 주소는 개설할 때 회원이 직접 입력한다. 블로그 이름과는 별개다.
2. 영문 소문자·숫자·하이픈(-)만 쓸 수 있고, 4\~32자다. 하이픈으로 시작하거나 끝낼 수 없다.
3. 다른 블로그가 쓰는 주소와 서비스가 쓰는 예약어(예: login, admin, api)는 쓸 수 없다. 규칙에 어긋나면 이유를 알려 준다.
4. **주소는 개설 후 바꿀 수 없다.** 개설 화면에서 이 사실을 안내한다. 블로그 이름은 언제든 바꿀 수 있다.
5. 한 번 쓴 주소는 블로그가 삭제돼도 다른 사람이 다시 쓸 수 없다. 이미 공유된 링크가 남의 블로그로 연결되는 것을 막기 위함이다.
6. 주소를 바꾸고 싶으면 새 블로그를 열고 이사한다(BLOG-06, 블로그를 여러 개 허용하는 경우).
7. 주소를 링크에 넣는 방식(경로 또는 서브도메인)은 선택 항목이다(7.3).

### 4.3 글 주소

1. 글 주소는 처음 발행할 때 정해지고, 제목이나 내용을 수정해도 바뀌지 않는다. 이미 공유한 링크가 깨지지 않게 하기 위함이다.
2. 다른 블로그의 주소를 붙여 글에 접근하면(글이 그 블로그 소속이 아님) 없는 글(404)로 처리한다. 단, 블로그 이사(BLOG-06)로 옮긴 글은 지금 소속 블로그의 주소로 이동시킨다.
3. 주소 형식(번호 또는 제목)은 선택 항목이다(7.5).

### 4.4 목록과 페이지네이션

1. 글 목록은 기본적으로 최신순이다. 기준은 처음 발행한 시각이고, 글을 수정해도 순서는 바뀌지 않는다. 발행 시각이 같으면 나중에 만든 글이 위에 온다.
2. 블로그 글 목록(카테고리·태그·검색 결과 포함)은 페이지를 나눠 보여 준다. 한 페이지 10개를 권장한다.
3. 홈 최신 글·피드처럼 계속 쌓이는 목록은 더보기나 무한 스크롤로 보여 줘도 된다. 이때 같은 글이 두 번 나오거나 빠지면 안 된다.
4. 마지막 페이지를 넘어서 요청하면 오류가 아니라 빈 목록을 보여 준다.
5. 목록과 글 개수는 보는 사람이 볼 수 있는 글만 센다.
6. 목록이 비면 빈 상태임을 알려 준다(문구는 자율).

### 4.5 글자 수 제한

앞뒤 공백을 잘라낸 뒤 길이를 잔다. 두 문서의 값이 다른 항목은 아래 기준안을 두고 9.2에서 확정한다.

### 4.6 파일 업로드

1. 이미지 파일(jpg, png, gif, webp)만 올릴 수 있다. 이미지가 아니면 거절하고 기존 상태를 유지한다.
2. 파일 크기에는 상한이 있다. 넘으면 거절하고 이유를 알린다. 상한 값과 줄이는 크기·품질은 자율이다.
3. 업로드가 실패하면 기존 이미지·본문을 그대로 둔다.
4. 이미지 비율은 유지한다. GIF는 움직임이 유지돼야 한다.
5. 휴대폰 사진은 찍힌 방향대로 바르게 보여야 한다.

### 4.7 삭제 처리

삭제는 모두 확인을 한 번 더 받은 뒤 진행한다.

| 대상 | 함께 처리되는 것 |
| --- | --- |
| 글 | 댓글·공감·저장·알림이 함께 사라진다. 삭제된 글 주소로 들어오면 없는 글(404)로 안내한다 |
| 댓글 | 답글이 달린 댓글은 '삭제된 댓글'로 표시하고 답글은 남긴다(답글 기능이 있는 경우) |
| 카테고리 | 소속 글은 '미분류'로 옮겨진다. 하위 카테고리가 있으면 먼저 옮기거나 지워야 한다 |
| 태그 | 글과의 연결만 끊기고 글은 그대로 둔다 |
| 블로그(P2) | 사용자에게는 사라지지만 주소는 영구히 예약된다(4.2). 옮기지 않은 글도 함께 사라진다 |
| 회원 탈퇴(P2) | 블로그·글·댓글을 어떻게 처리할지 미결정(9.2) |
| 서비스 관리자의 제재 | 삭제하지 않고 숨긴다. 해제하면 원래대로 보인다(6.12) |

## 6. 기능 상세

기능마다 동작 규칙을 ①②③으로 적는다. 영역 순서는 5장과 같다. 방향이 갈리는 선택 항목은 관련 기능 바로 아래에 '▸ 선택 7.n'으로 함께 적어, 이 장만 읽어도 기능 하나를 끝까지 볼 수 있게 했다.

### 6.1 AUTH 회원·인증

**AUTH-01 가입·로그인** (P0)

1. 로그인 방식은 아래 선택 7.1에서 고른다. 어느 방식이든 가입하면 일반 회원이 된다.
2. 로그인에 성공하면 로그인 전에 보던 화면으로 돌아간다. 보던 화면이 없으면 홈으로 간다.
3. 로그인에 실패하거나 취소하면 아무것도 바뀌지 않고 이유를 알린다.
4. 닉네임은 회원마다 가지며, 댓글 작성자 등으로 표시된다.

**▸ 선택 7.1 로그인 방식**

| 선택지 | 지원 | 민주 | 서현 |
| --- | --- | --- | --- |
| 소셜 / 이메일 / 둘 다 | 둘 다(소셜은 P1) | 소셜(제공사 미정) | 카카오 |

방식별 추가 규칙: 이메일 방식을 고르면 비밀번호는 어디에도 그대로 보이지 않는다(8.1). 이메일 인증·비밀번호 재설정은 이메일 방식을 고른 사람만 정한다.

**AUTH-02 로그아웃** (P0)

1. 로그아웃하면 비회원 상태가 되고 홈이나 보던 공개 화면으로 간다.
2. 로그아웃 후에는 글쓰기·관리 화면에 들어갈 수 없다(3.3).

**AUTH-03 로그인 상태 유지** (P1)

1. 브라우저를 닫았다 열어도 로그아웃하기 전까지는 로그인이 유지된다. 유지 기간은 자율이다.
2. 로그인이 만료되면 다시 로그인한 뒤 원래 위치로 돌아온다.

**AUTH-04 첫 로그인 후 블로그 개설 안내** (P1)

1. 블로그가 없는 회원이 글쓰기를 누르면 블로그 개설(BLOG-01)로 안내한다.
2. 이미 블로그가 있으면 글쓰기로 바로 간다.

**AUTH-05 회원정보 수정** (P1)

1. 닉네임과 프로필 이미지를 바꿀 수 있다. 프로필 이미지 업로드는 4.6을 따른다.
2. 다른 회원이 쓰는 닉네임인지는 자율로 정한다.

**AUTH-06 회원 탈퇴** (P2)

1. 탈퇴 전에 한 번 더 확인한다.
2. 탈퇴한 회원의 블로그·글·댓글 처리는 미결정이다(9.2).

### 6.2 BLOG 블로그

**BLOG-01 블로그 개설** (P0)

1. 블로그 주소와 이름을 입력해 만든다. 소개는 비워 둘 수 있다.
2. 주소는 4.2의 규칙을 따르고, 중복이면 입력 단계에서 알려 준다.
3. 개설 화면에서 '주소는 나중에 바꿀 수 없다'는 사실을 알린다.
4. 회원당 몇 개까지 만들 수 있는지는 아래 선택 7.2를 따른다. 한도를 넘으면 개설을 막는다.
5. 개설이 끝나면 새 블로그나 글쓰기로 간다.

**▸ 선택 7.2 회원당 블로그 수**

| 선택지 | 지원 | 민주 | 서현 |
| --- | --- | --- | --- |
| 1개 / 여러 개(상한을 정함) | 최대 5개 | 1개 | 1개 |

방식별 추가 규칙: 여러 개를 고르면 블로그 이사(BLOG-06), 삭제(BLOG-07), 대표 블로그(BLOG-08) 규칙을 따른다. 1개를 고르면 이 세 기능은 구현할 필요 없다.

**▸ 선택 7.3 블로그 주소 방식**

| 선택지 | 지원 | 민주 | 서현 |
| --- | --- | --- | --- |
| 경로(`서비스주소/블로그주소`) / 서브도메인(`블로그주소.서비스주소`) | 서브도메인 | 경로 | 서브도메인 |

방식별 추가 규칙: 주소 규칙 자체는 4.2와 같다. 한 블로그의 모든 화면(메인, 글, 카테고리, 태그, 검색 결과)은 그 블로그 주소 아래에 있고, 여러 블로그를 오가도 로그인 상태가 유지된다.

**BLOG-02 블로그 정보 수정** (P0)

1. 블로그 이름, 소개, 프로필 이미지를 바꾼다. 주소는 바꿀 수 없다.
2. 프로필 이미지가 없으면 기본 이미지를 보여 준다.
3. 소개가 비어 있으면 소개 자리를 비워 두지 않고 숨긴다.

**BLOG-03 블로그 메인** (P0)

1. 그 블로그의 글을 최신순으로 보여 준다(4.4).
2. 각 글은 최소한 제목, 발행일, 카테고리, 본문 요약을 보여 준다.
3. 글이 없으면 아직 글이 없다고 알린다.
4. 없는 블로그 주소로 들어오면 404다.

**BLOG-04 사이드바** (P0)

1. 블로그의 모든 화면(메인, 글 상세, 카테고리·태그 목록)에 같은 사이드바가 붙는다.
2. 필수 구성: 블로그 이름·프로필(누르면 블로그 메인), 카테고리 목록과 카테고리별 글 수.
3. 카테고리 목록에는 '전체 글'이 맨 위에, '미분류'가 맨 아래에 온다. 미분류 글이 없으면 미분류는 숨긴다.
4. 선택 구성(P1 이후): 태그 목록, 최근 글, 최근 댓글, 인기 글, 방문자 수.
5. 비공개 글은 주인이 아니면 글 수에서도 빠진다.

**BLOG-05 블로그 꾸미기** (P2)

1. 미리 만든 스킨 중 하나를 고르거나, 상단 배경 이미지를 올리고 지울 수 있다.
2. 배경 이미지를 지우면 스킨 기본 배경으로 돌아간다.
3. HTML·CSS 직접 편집은 범위 밖이다.

**BLOG-06 블로그 이사** (P2, 7.2에서 여러 개를 고른 경우)

1. 내 블로그끼리 글을 옮길 수 있다. 댓글·공감은 글과 함께 옮겨가고, 카테고리는 '미분류'가 된다.
2. 옛 블로그에 이사 간 블로그를 지정하면, 옛 블로그 메인으로 들어온 사람을 새 블로그로 보낸다.
3. 옮긴 글의 옛 주소는 새 블로그의 같은 글로 연결된다.
4. 이사 대상은 같은 회원의 다른 블로그만 가능하다. A→B 후 B→C로 이사하면 A도 C로 연결된다.

**BLOG-07 블로그 삭제** (P2)

1. 확인 후 삭제하며, 옮기지 않은 글이 함께 사라진다는 것을 알린다.
2. 사용자에게는 사라지지만 주소는 영구히 예약되고, 이사 안내는 계속 동작한다.
3. 대표 블로그는 다른 블로그를 대표로 바꾼 뒤에만 삭제할 수 있다.

**BLOG-08 대표 블로그 지정** (P2, 7.2에서 여러 개를 고른 경우)

1. 처음 만든 블로그가 대표 블로그다. 나중에 바꿀 수 있다.
2. '내 블로그' 바로가기와 댓글 작성자 링크는 대표 블로그로 간다.

### 6.3 POST 글

**POST-01 글 작성·발행** (P0)

1. 새 글 쓰기는 빈 상태에서 시작한다. 이전에 쓰던 내용이 섞여 나오지 않는다(임시저장은 POST-08).
2. 제목·본문은 필수다. 발행할 때 제목 → 본문 순서로 확인하고, 첫 번째 문제를 알린다. 제목은 앞뒤 공백을 뺀 뒤 판단한다.
3. 카테고리(하나), 태그(여러 개), 공개 범위를 정한다. 카테고리를 고르지 않으면 '미분류'다.
4. 본문은 문단 제목, 굵게, 목록, 인용, 코드 블록, 링크, 이미지를 표현할 수 있어야 한다. 에디터 방식은 아래 선택 7.4를 따른다.
5. 발행하면 쓴 글의 상세 화면으로 간다. 공감·댓글·조회수는 0에서 시작한다.
6. 발행 버튼을 연달아 눌러도 글은 하나만 생긴다(8.3).

**▸ 선택 7.4 에디터**

| 선택지 | 지원 | 민주 | 서현 |
| --- | --- | --- | --- |
| 마크다운 / WYSIWYG(보이는 대로 편집) / 둘을 함께 제공 | 마크다운 | WYSIWYG | 혼합 |

방식별 추가 규칙: 어느 방식이든 위 ④의 표현 요소를 지원하고, 본문의 스크립트는 실행되지 않는다(8.1). 저장한 글을 다시 수정하러 열면 서식이 그대로 남아 있다.

**▸ 선택 7.5 글 주소 형식**

| 선택지 | 지원 | 민주 | 서현 |
| --- | --- | --- | --- |
| 번호(`/123`) / 제목 기반(`/글-제목`) | 번호 | 번호 | 제목 기반 |

방식별 추가 규칙: 어느 방식이든 발행 후 주소는 바뀌지 않는다(4.3). 같은 블로그 안에서 글 주소는 겹치지 않으므로, 제목 기반이면 같은 제목의 글도 서로 다른 주소를 가진다. 한글 제목도 깨지지 않고 주소로 열린다.

**POST-02 글 수정** (P0)

1. 블로그 주인만 수정할 수 있다.
2. 수정해도 글 주소, 처음 발행일, 공감·댓글·조회수, 목록에서의 순서는 그대로다.
3. 발행 때와 같은 확인(제목·본문 필수)을 거친다.
4. 수정한 시각은 따로 남길 수 있다(표시 여부는 자율).

**POST-03 글 삭제** (P0)

1. 블로그 주인만 삭제할 수 있고, 확인을 한 번 더 받는다.
2. 함께 처리되는 것은 4.7을 따른다.
3. 삭제 후에는 블로그 메인이나 글 관리 화면으로 간다.

**POST-04 글 상세 조회** (P0)

1. 제목, 발행일, 카테고리, 본문, 태그, 공감 수, 댓글을 보여 준다.
2. 본문의 스크립트는 실행되지 않는다(8.1).
3. 글을 볼 수 있는지는 존재 → 소속 → 블로그 주인 여부 → 공개 범위 순서로 판단한다. 볼 수 없으면 404다(4.1, 4.3).
4. 블로그 주인에게는 수정·삭제가 보인다.

**POST-05 본문 이미지 넣기** (P0)

1. 쓰는 위치에 이미지를 넣는다. 여러 장을 고르면 고른 순서대로 들어간다.
2. 업로드 규칙은 4.6을 따른다.

**POST-06 공개·비공개 설정** (P0)

1. 발행할 때 고르고, 발행 후에도 바꿀 수 있다. 기본값은 공개다.
2. 공개 범위에 따른 노출 규칙은 4.1을 따른다.

**POST-07 대표 이미지** (P1)

1. 본문 이미지 중 하나를 고르거나 따로 올린다.
2. 고르지 않으면 본문 첫 이미지를 쓰고, 이미지가 없으면 대표 이미지 없이 보여 준다.

**POST-08 임시저장** (P1)

1. 쓰던 글을 발행하지 않고 저장해 두고, 나중에 불러와 이어 쓸 수 있다. 블로그 주인에게만 보인다.
2. 새 글 쓰기를 열 때 임시저장된 글이 있으면 이어 쓸지 묻는다.
3. 발행하면 그 글의 임시저장은 지워진다.
4. 자동 저장 여부와 간격, 보관 개수는 자율이다.

**POST-09 조회수** (P1)

1. 글을 열면 조회수가 오른다.
2. 같은 사람이 짧은 시간 안에 다시 열었을 때 중복으로 셀지는 미결정이다(9.2).

**POST-10 이전·다음 글** (P1)

1. 같은 블로그 안에서 발행 순서로 앞뒤 글을 보여 준다.
2. 보는 사람이 볼 수 없는 글(남의 비공개 글)은 건너뛴다.

**POST-11 주제 지정** (P1)

1. 플랫폼이 정한 주제 목록에서 하나를 고른다. 지정 단위(글/블로그)는 아래 선택 7.7을 따른다.
2. 고르지 않으면 '주제 없음'이고 홈 주제별 글에서 빠진다.

**▸ 선택 7.7 주제 지정 단위**

| 선택지 | 지원 | 민주 | 서현 |
| --- | --- | --- | --- |
| 글마다 / 블로그마다 | 글마다 | 미정 | 블로그마다 |

방식별 추가 규칙: 주제는 블로그 카테고리와 별개다(2.3). 블로그마다를 고르면 그 블로그의 모든 공개 글이 그 주제로 묶인다.

**POST-12 확장 공개 범위** (P2)

1. 아래 선택 7.8에서 고른 방식(보호글 또는 구독자 공개)을 따른다.

**▸ 선택 7.8 확장 공개 범위**

| 선택지 | 지원 | 민주 | 서현 |
| --- | --- | --- | --- |
| 없음 / 보호글(비밀번호를 아는 사람만) / 구독자 공개(구독자만) | 보호글 | 없음 | 구독자 공개 |

방식별 추가 규칙: 공개·비공개는 어느 방식이든 필수다(4.1). 확장 범위의 글은 본문을 볼 수 없는 사람에게 검색, 홈, 인기 글, 피드에서 빠진다. 블로그 목록에서 '볼 수 없는 글'로 표시할지 아예 뺄지는 개인 설계 문서에 밝힌다.

**POST-13 예약 발행** (P2)

1. 정한 날짜·시각이 되면 자동으로 공개된다. 그 전까지는 블로그 주인에게만 보인다.
2. 목록에서는 실제로 공개된 시각을 발행일로 본다.

### 6.4 CAT 카테고리

**CAT-01 카테고리 추가·이름 변경·삭제** (P0)

1. 블로그 주인만 관리한다. 같은 단계 안에서는 이름이 겹칠 수 없다.
2. 삭제하면 그 카테고리의 글은 '미분류'로 옮겨진다.
3. '전체 글'과 '미분류'는 이름을 바꾸거나 지울 수 없다.
4. 새 블로그는 카테고리 없이 시작한다. 기본 카테고리를 만들어 둘지는 자율이다.

**CAT-02 카테고리별 글 목록** (P0)

1. 카테고리를 누르면 그 카테고리의 글만 최신순으로 보여 준다(4.4).
2. 카테고리마다 고유한 주소가 있다.
3. 상위 카테고리를 고르면 하위 카테고리 글까지 함께 보여 주고, 글 수도 합친 값이다(CAT-03이 있는 경우).

**CAT-03 하위 카테고리** (P1)

1. 하위 카테고리는 한 단계까지만 둔다.
2. 하위가 있는 상위 카테고리는 바로 지울 수 없고, 하위를 먼저 옮기거나 지우라고 알린다.
3. 상위가 다르면 같은 이름을 쓸 수 있다.

**CAT-04 카테고리 순서 변경** (P1)

1. 블로그 주인이 정한 순서대로 사이드바에 보인다. 방법(끌어놓기 등)은 자율이다.

**CAT-05 카테고리 비공개** (P2)

1. 비공개 카테고리와 그 글은 주인에게만 보인다.

### 6.5 TAG 태그

**TAG-01 글에 태그 달기** (P0)

1. 글 하나에 태그를 최대 10개까지 단다. 같은 태그는 한 번만 달린다.
2. 태그는 블로그 단위로 관리한다. 블로그에 없던 이름을 입력하면 새 태그가 된다.
3. 태그는 블로그 내 검색(SRCH-01)에도 쓰인다.

**TAG-02 태그별 글 목록** (P0)

1. 태그를 누르면 같은 블로그에서 그 태그가 붙은 글만 보여 준다.
2. 태그마다 고유한 주소가 있다.

**TAG-03 태그 목록** (P1)

1. 블로그에서 쓴 태그를 모아 보여 주고, 누르면 TAG-02로 간다.
2. 많이 쓴 태그를 더 크게 보여 줄지(태그 클라우드)는 자율이다.

**TAG-04 태그 관리** (P2)

1. 블로그 주인이 태그 이름을 바꾸거나 지울 수 있다. 지워도 글은 남는다(4.7).

### 6.6 CMT 댓글·방명록

**CMT-01 댓글 쓰기·삭제** (P0)

1. 회원만 댓글을 쓸 수 있다. 비회원이 쓰려고 하면 로그인으로 안내한다.
2. 댓글마다 작성자 닉네임과 작성 시각(날짜와 시각)을 보여 준다.
3. 댓글은 작성순으로 보여 주고, 글마다 댓글 수를 보여 준다.
4. 자기 댓글은 확인 후 지울 수 있다.
5. 등록 버튼을 연달아 눌러도 댓글은 한 번만 올라간다(8.3).

**CMT-02 블로그 주인의 댓글 삭제** (P0)

1. 블로그 주인은 자기 블로그 글에 달린 모든 댓글을 지울 수 있다. 남의 댓글을 수정할 수는 없다.

**CMT-03 댓글 수정** (P1)

1. 자기 댓글만 수정할 수 있다.

**CMT-04 방명록** (P1)

1. 회원이 블로그에 방명록을 남긴다. 쓰기·삭제 규칙은 댓글과 같다.
2. 블로그 주인은 모든 방명록을 지울 수 있다.

**CMT-05 답글** (P2)

1. 댓글에 한 단계까지 답글을 단다.
2. 답글이 달린 댓글을 지우면 '삭제된 댓글'로 표시하고 답글은 남긴다.

**CMT-06 비밀댓글** (P2)

1. 비밀로 쓴 댓글은 블로그 주인과 댓글 작성자만 볼 수 있다.

**CMT-07 댓글 허용 설정** (P2)

1. 글마다 댓글을 막을 수 있다. 막은 글에는 새 댓글을 쓸 수 없고 기존 댓글은 남는다.

### 6.7 SOC 반응

**SOC-01 공감** (P0)

1. 회원은 글마다 한 번 공감을 누르고, 다시 누르면 취소한다.
2. 공감 수는 바로 반영되고, 새로고침해도 실제 개수와 같다(8.3).
3. 비회원이 누르면 로그인으로 안내한다.
4. 내 글에 내가 공감할 수 있는지는 미결정이다(9.2).

**SOC-02 공유** (P1)

1. 글 주소를 복사할 수 있다. SNS로 보내기는 자율이다.
2. 공유되는 주소는 4.3의 바뀌지 않는 글 주소다.

**SOC-03 저장** (P2)

1. 회원이 글을 저장하면 저장한 글만 모아 볼 수 있다. 다시 누르면 해제된다.
2. 저장한 글이 비공개로 바뀌거나 삭제되면 목록에서 빠진다.

### 6.8 SUB 구독·피드·알림

**SUB-01 블로그 구독·해제** (P1)

1. 회원은 다른 블로그를 구독하고 해제할 수 있다. 자기 블로그는 구독할 수 없다.
2. 구독 중인지 아닌지가 버튼에 보인다.
3. 내가 구독한 블로그 목록을 볼 수 있고, 거기서 해제할 수 있다.

**SUB-02 구독 피드** (P1)

1. 구독한 블로그의 새 글을 최신순으로 모아 보여 준다. 볼 수 없는 글은 빠진다.
2. 더 불러올 때 같은 글이 두 번 나오거나 빠지지 않는다.
3. 구독한 블로그가 없으면 그 사실을 알리고, 다른 블로그를 둘러볼 수 있게 한다.

**SUB-03 구독자 수** (P1)

1. 블로그에 구독자 수를 보여 준다. 새로고침해도 실제 개수와 같다.

**SUB-04 알림** (P2)

1. 내 글에 댓글·공감이 생기거나, 누군가 나를 구독하거나, 구독한 블로그에 새 글이 올라오면 알림이 생긴다.
2. 읽지 않은 알림 수를 보여 주고, 알림을 누르면 해당 화면으로 가고 읽음 처리된다.
3. 내가 한 행동으로는 나에게 알림이 오지 않는다.

**SUB-05 맞구독** (P2)

1. 서로 구독하면 요청·수락 없이 맞구독이 된다.
2. 구독 버튼은 네 상태(서로 안 함 / 상대만 나를 구독 / 나만 구독 / 서로 구독)를 구분해 보여 준다.
3. 맞구독 상태에서 해제하면 확인을 받고, 내 구독만 취소된다. 상대에게 알림은 가지 않는다.

**SUB-06 추천 블로그** (P2)

1. 아직 구독하지 않은 인기 블로그를 추천한다. 자기 블로그는 빠진다.
2. 추천 기준(주제, 구독자 수 등)은 개인 설계 문서에 밝힌다.

### 6.9 SRCH 검색

**SRCH-01 블로그 내 검색** (P0)

1. 한 블로그 안에서 제목·본문·태그로 글을 찾는다. 영문 대소문자는 구분하지 않는다.
2. 검색어의 앞뒤 공백은 빼고 판단한다. 공백만 입력하면 검색하지 않는다.
3. 결과는 최신순이고 페이지를 나눠 보여 준다(4.4). 보는 사람이 볼 수 없는 글은 빠진다(4.1).
4. 결과가 없으면 없다고 알리고, 입력한 검색어는 그대로 남겨 둔다.
5. 검색 결과에도 주소가 있어, 새로고침하거나 공유해도 같은 결과가 나온다.

**SRCH-02 통합 검색** (P1)

1. 플랫폼 전체에서 글과 블로그(이름·소개)를 찾는다. 공개 글과 이용 제한되지 않은 블로그만 대상이다.
2. 글 결과에는 어느 블로그의 글인지 함께 보여 준다.
3. 검색어 처리와 빈 결과 처리는 SRCH-01과 같다. 정렬 기준(최신순·정확도순)은 자율이다.

### 6.10 HOME 홈·탐색

**HOME-01 홈 최신 글** (P0)

1. 플랫폼 전체의 공개 글을 최신순으로 보여 준다. 비공개 글과 서비스 관리자가 숨긴 글·블로그는 빠진다.
2. 각 글은 최소한 제목, 블로그 이름, 발행일, 본문 요약을 보여 주고, 누르면 글 상세로 간다.
3. 비회원도 볼 수 있다.
4. 더 불러올 때 같은 글이 두 번 나오거나 빠지지 않는다(4.4).

**HOME-02 인기 글** (P1, 선택 7.6)

1. 아래 선택 7.6에서 고른 기준으로 순위를 매겨 보여 준다. 공개 글만 대상이다.
2. 인기 글이 하나도 없으면 빈 상태를 알리거나 최신 글로 대신한다.

**▸ 선택 7.6 인기 글 기준**

| 선택지 | 지원 | 민주 | 서현 |
| --- | --- | --- | --- |
| 각자 정의(집계 기간, 점수 계산 방식, 갱신 주기) | 최근 7일 조회·공감·댓글 가중 합산 | 최근 1시간 조회수, 정각 집계 | 최근 7일 공감+댓글 |

방식별 추가 규칙: 숨긴 글은 빠진다. 기준(기간, 계산 방식, 갱신 주기)을 개인 설계 문서에 밝힌다.

**HOME-03 주제별 글** (P1, 선택 7.7)

1. 주제를 고르면 그 주제의 공개 글을 최신순으로 보여 준다.
2. 주제가 없는 글은 어느 주제에도 나오지 않는다(POST-11).
3. 주제마다 고유한 주소가 있다.

**HOME-04 인기 블로거** (P2)

1. 블로그 단위로 순위를 매겨 보여 준다. 공개 글이 없는 블로그는 빠진다.
2. 순위 기준은 개인 설계 문서에 밝힌다.

**HOME-05 랭킹 전체보기** (P2)

1. 홈에서는 인기 글·인기 블로거의 상위 일부만 보여 주고, 전체보기에서 나머지 순위를 이어서 본다.
2. 홈과 전체보기의 순위는 같은 기준, 같은 시점의 값이다.

### 6.11 MNG 블로그 관리

블로그 관리는 블로그 주인만 쓸 수 있다. 블로그를 여러 개 가진 경우(7.2) 블로그마다 따로 관리한다.

**MNG-01 내 글 관리** (P1)

1. 내 블로그의 발행 글(공개·비공개)과 임시저장 글을 한곳에서 모아 본다. 각 글의 상태가 구분돼 보인다.
2. 여기서 글을 수정·삭제하고 공개 범위를 바꿀 수 있다. 규칙은 POST-02·03·06과 같다.
3. 서비스 관리자가 숨긴 글은 숨김 상태와 사유가 보인다(ADMIN-03).
4. 여러 글을 한 번에 처리하는 기능은 자율이다.

**MNG-02 댓글 관리** (P1)

1. 내 블로그의 모든 글에 달린 댓글과 방명록을 최신순으로 모아 본다. 각 댓글이 어느 글에 달렸는지 보인다.
2. 여기서 댓글을 지울 수 있다. 규칙은 CMT-02와 같다.

**MNG-03 방문자 수·통계** (P2)

1. 오늘, 어제, 전체 방문자 수를 보여 준다. 사이드바에 방문자 수를 보여 주는 경우 같은 값이다.
2. 기간 안에 많이 읽힌 내 글 순위를 보여 준다.
3. 같은 사람의 반복 방문을 어떻게 셀지는 개인 설계 문서에 밝힌다.

**MNG-04 스팸·차단** (P2)

1. 블로그 주인이 특정 회원을 차단하면, 그 회원은 이 블로그에 댓글과 방명록을 쓸 수 없다. 차단을 풀 수 있다.
2. 차단된 회원에게는 댓글을 쓸 수 없다는 사실만 알린다.
3. 블로그 주인이 정한 금칙어가 들어간 댓글은 등록되지 않는다.

### 6.12 ADMIN 서비스 관리

**공통 원칙**: 모든 ADMIN 기능에 적용한다.

1. 서비스 관리자는 가입이나 화면으로 될 수 없고, 운영자가 따로 지정한다(3.1).
2. 제재는 삭제가 아니라 숨김·제한이다. 해제하면 원래 상태(위치, 수치, 주소)로 돌아간다.
3. 남의 글·댓글·블로그 내용을 수정할 수 없다.
4. 제재할 때는 사유를 반드시 남기고, 제재를 받은 사람은 그 사유를 볼 수 있다.
5. 서비스 관리자는 다른 서비스 관리자를 제재할 수 없다.

**ADMIN-01 관리자 역할과 전용 영역** (P0)

1. 서비스 관리자 역할이 있고, 서비스 관리자만 들어갈 수 있는 관리 영역이 있다.
2. 일반 회원이 관리 영역에 들어가면 권한 없음(403), 비회원이면 로그인 안내다(3.3). 주소를 직접 입력해도 같다.
3. 서비스를 처음 시작할 때 서비스 관리자 계정이 하나 이상 있다.
4. P0에서는 역할과 영역 보호까지만 필수다. 실제 관리 기능은 ADMIN-02부터다.

**ADMIN-02 회원 이용 제한** (P1)

1. 서비스 관리자가 기간(정한 날짜까지 또는 영구)과 사유를 정해 회원의 이용을 제한한다.
2. 제한된 회원은 로그인할 수 없고, 로그인을 시도하면 사유와 기한을 알린다(3.3). 이미 로그인한 상태였다면 다음 행동부터 막힌다.
3. 기한이 지나면 자동으로 풀리고, 서비스 관리자가 미리 풀 수도 있다.
4. 제한 기간 동안 그 회원의 블로그와 글을 보이게 둘지는 미결정이다(9.2).

**ADMIN-03 게시물 숨김** (P1)

1. 서비스 관리자가 사유를 정해 글이나 댓글을 숨기고, 다시 되돌릴 수 있다.
2. 숨긴 글은 목록·검색·홈·피드·글 개수에서 빠지고, 다른 사람이 주소로 열면 없는 글(404)이다. 글쓴이에게는 숨김 사실과 사유가 보인다.
3. 숨긴 댓글은 다른 사람에게 '관리자가 숨긴 댓글'로 표시되고, 답글은 남는다.

**ADMIN-04 신고** (P2)

1. 회원은 남의 글·댓글을 사유를 골라 신고한다. 같은 대상은 한 번만 신고할 수 있고, 자기 것은 신고할 수 없다.
2. 서비스 관리자는 신고 목록을 보고 숨김(ADMIN-03) 또는 기각으로 처리한다. 처리 결과가 신고 목록에 남는다.
3. 신고가 쌓인다고 자동으로 숨겨지지 않는다.

**ADMIN-05 블로그 이용 제한** (P2)

1. 회원은 그대로 두고 특정 블로그만 숨긴다. 그 블로그의 메인과 모든 글이 다른 사람에게 없는 블로그(404)가 된다.
2. 블로그 주인에게는 제한 사실과 사유가 보인다. 그 회원의 다른 블로그와 댓글 활동에는 영향이 없다.

**ADMIN-06 공지·관리 이력·대시보드** (P2)

1. 서비스 관리자가 올린 공지는 모든 사용자가 볼 수 있다. 보이는 위치는 자율이다.
2. 모든 제재와 해제는 누가, 언제, 무엇을, 왜 했는지 기록에 남고, 그 기록은 수정하거나 지울 수 없다.
3. 대시보드에서 회원 수, 블로그 수, 글 수, 처리를 기다리는 신고 수를 본다.

### 6.13 COM 공통

**COM-01 접근 제어** (P0)

1. 모든 행동은 3.2의 권한표를 따른다. 권한이 없으면 3.3대로 처리한다.
2. 버튼을 숨기는 것만으로는 부족하다. 주소를 직접 입력하거나 요청을 직접 보내도 같은 결과가 나와야 한다.
3. 로그인 안내를 거쳐 로그인하면 원래 하려던 화면으로 돌아간다.

**COM-02 오류 처리** (P0)

1. 없는 주소는 404, 권한 없음은 403으로 각각 알리고, 홈이나 이전 화면으로 돌아갈 길을 준다.
2. 입력이 잘못되면 어느 항목이 왜 잘못됐는지 알리고, 입력한 내용은 지우지 않는다.
3. 예상하지 못한 오류가 나도 내부 정보(오류 위치, 서버 구성 등)는 보여 주지 않는다. 사용자에게는 잠시 후 다시 시도하라고 알린다.

## 8. 비기능 요구사항

사용자가 체감하고 확인할 수 있는 기준만 적는다.

### 8.1 보안

1. 사용자가 입력한 내용(글 제목·본문, 댓글, 블로그 이름·소개, 닉네임)에 들어 있는 스크립트는 어디에 보여도 실행되지 않는다.
2. 주소를 직접 입력하거나 요청을 직접 보내도 3.2의 권한이 지켜진다. 남의 비공개 글은 있다는 사실도 드러나지 않는다(404).
3. 로그인한 사용자가 다른 사이트를 방문해도, 그 사이트가 사용자 대신 글을 쓰거나 지우는 등의 행동을 할 수 없다.
4. 로그인 정보와 비밀번호는 주소창, 화면, 오류 메시지 어디에도 그대로 드러나지 않는다.
5. 이미지로 위장한 파일은 거절한다(4.6).
6. 오류가 나도 내부 정보는 보여 주지 않는다(COM-02).

### 8.2 성능

1. 목록은 페이지 단위로 불러온다. 글이 많아져도 한 화면에서 모든 글을 한꺼번에 불러오지 않는다(4.4).
2. 목록에서는 이미지를 작게 보여 주고, 원본 크기 이미지는 글 상세에서만 불러온다.
3. 공감·구독 버튼은 누르는 즉시 바뀐 상태를 보여 준다.
4. 목록과 글 상세는 기다린다는 느낌 없이 열려야 한다. 측정 환경과 목표 수치는 개인 설계 문서에 밝힌다.

### 8.3 신뢰성

1. 같은 요청을 연달아 보내도 한 번만 처리한다. 글 발행, 댓글 등록, 공감, 구독이 대상이다.
2. 공감 수, 댓글 수, 구독자 수, 글 수는 새로고침하면 언제나 실제 값과 같다.
3. 저장에 실패하면 실패를 알리고, 쓰던 내용(제목, 본문, 댓글)을 잃지 않는다. 로그인이 만료된 경우도 같다(3.3).
4. 여러 단계가 함께 처리되는 작업(글 삭제, 카테고리 삭제, 블로그 이사)은 중간에 실패해도 일부만 처리된 상태로 남지 않는다.
5. 서비스를 다시 시작해도 글, 이미지, 댓글이 그대로 남아 있다.

### 8.4 사용성

1. 휴대폰 화면 폭에서도 모든 P0 기능을 쓸 수 있고, 가로로 스크롤하지 않아도 내용이 다 보인다.
2. 입력이 잘못되면 어느 항목이 왜 잘못됐는지 알리고, 입력한 내용은 그대로 둔다.
3. 되돌릴 수 없는 작업(삭제, 탈퇴, 이사)은 실행 전에 한 번 더 확인한다(4.7).
4. 처리 중인 작업은 처리 중임을 알 수 있고, 끝나면 결과(성공·실패)를 알린다.
5. 날짜와 시각은 한국 시간 기준으로 보여 준다.
6. 최신 버전의 주요 브라우저(크롬, 사파리, 엣지)에서 같은 기능이 동작한다.

### C. 개인 설계 문서 작성 안내

이 문서는 무엇을 만들지 정하고, 어떻게 만들지는 각자의 개인 설계 문서가 정한다. 개인 설계 문서에는 아래를 적는다.

1. **선택 항목**: 7장의 8개 항목에서 고른 방식. 표 하나로 정리한다.
2. **기술 스택**: 언어, 프레임워크, DB, 인증 방식, 에디터 라이브러리 등.
3. **화면**: 화면 목록, 화면 흐름, 디자인, 화면 문구.
4. **기능 ID별 구현**: 이 문서의 통합 ID를 그대로 쓰고, 기능마다 구현 방식과 일정을 적는다.
5. **자율로 둔 값**: 업로드 크기 상한, 로그인 유지 기간, 인기 글·추천·인기 블로거 기준, 방문자 집계 방식, 성능 목표 수치 등.
6. **차이**: 이 문서와 다르게 하는 부분이 있으면 그 이유.
