# 기능 명세 (Feature Specification): 티스토리형 블로그 플랫폼

> **이 문서는?** 지원 블로그 서비스의 기능 명세다. 사용자가 서비스 밖에서 확인할 수 있는 동작(무엇을)을 담는다. 유저 스토리와 수용 시나리오로 무엇을 만들지, 기능 요구사항(FR)으로 지켜야 할 규칙을, 명확화로 아직 안 정해진 것을 정리한다. 기술과 구조(어떻게)는 [구현 계획](./plan.md)에 있다. 전체 문서 안내는 [README](../../README.md)에 있다.

**기능 브랜치**: `001-tistory-blog`
**작성일**: 2026-10-07
**상태**: 초안
**입력**: `docs/기능명세서_지원 (개인 설계 문서).md` (2026-10-01)

> **우선순위 표기**: 유저 스토리 우선순위 P1~P3은 기능 등급과 이렇게 대응한다.
> 스토리 **P1 = P0(필수)**, 스토리 **P2 = P1(권장)**, 스토리 **P3 = P2(확장)**.
> 각 요구사항(FR) 끝의 `[POST-01 · P0]`는 기능 ID와 등급이다. 기능 ID는 `영역코드-두 자리 번호`이고, 삭제된 번호는 다시 쓰지 않는다.

## 개요

누구나 회원가입 후 자기 블로그를 개설하고, 글을 발행하고, 다른 블로그를 구독·공감·댓글로 소통할 수 있는 멀티 유저 블로그 플랫폼이다. 기준 모델은 티스토리다. 2주 안에 P0 기능 전부로 "가입 → 블로그 개설 → 글 발행 → 다른 사람이 홈에서 발견 → 읽기·댓글·공감" 한 바퀴를 완성한다.

### 주요 방식

| 항목 | 결정 |
| --- | --- |
| 로그인 | 이메일 가입·로그인(P0) + 카카오·구글 소셜 로그인(P1) |
| 회원당 블로그 수 | 여러 개, 활성 블로그 최대 5개. 처음 만든 블로그가 대표 블로그 |
| 블로그 주소 | 서브도메인 `{주소}.blog.com` (예: myblog.blog.com) |
| 에디터 | WYSIWYG (보이는 대로 편집, 티스토리 기본 모드와 같은 방식) |
| 글 주소 | 번호 `{주소}.blog.com/{글 번호}`, 글 번호는 플랫폼 전체에서 하나 |
| 인기 글 | 최근 1시간 조회수 순, 공개 글 상위 10개, 5분마다 갱신 |
| 주제 | 글마다 하나. 고정 목록 10개 |
| 공개 범위 | 공개 / 비공개 / 구독자 공개(그 블로그를 구독한 회원과 주인만 열람) |

### 범위

- **포함**: 회원·인증, 블로그, 글, 카테고리, 태그, 댓글·방명록, 반응(공감·공유), 구독·피드·알림, 검색, 홈·탐색, 블로그 관리, 서비스 관리, 공통 동작, 자체 기능(이메일 인증, 비밀번호 재설정, 소셜 계정 연동, 같은 카테고리 다른 글, 비슷한 글 추천)
- **제외**: 광고·수익화·결제, 모바일 앱, 이메일·푸시 알림(가입 인증·비밀번호 재설정 메일 제외), 개인 도메인 연결, 스킨 HTML·CSS 직접 편집, 사이드바 구성 변경
- **보류**: 비회원 댓글 (넣을지 미정, Q5)

## 사용자 시나리오와 테스트 (User Scenarios & Testing) *(필수)*

### 유저 스토리 1 - 가입하고 내 블로그 열기 (우선순위: P1)

비회원이 이메일로 가입·로그인한 뒤 주소와 이름을 정해 블로그를 만들고, 블로그 메인과 사이드바를 확인한다.

**이 우선순위인 이유**: 블로그가 없으면 다른 어떤 기능도 시작할 수 없다. 한 바퀴의 출발점이다.

**독립 테스트**: 새 계정으로 가입 → 블로그 개설 → 블로그 메인에서 빈 상태와 사이드바 확인 → 로그아웃.

**수용 시나리오**:

1. **전제** 비회원, **행동** 이메일 인증 코드를 확인하고 비밀번호·닉네임을 입력해 가입한다, **결과** 일반 회원이 되고, 로그인하면 로그인 전에 보던 화면(없으면 홈)으로 돌아간다.
2. **전제** 비밀번호가 7자이거나 숫자가 없음, **행동** 가입한다, **결과** 어느 항목이 왜 틀렸는지 알리고 입력은 그대로 남는다.
3. **전제** 틀린 비밀번호 또는 없는 이메일, **행동** 로그인한다, **결과** 둘 다 "이메일 또는 비밀번호가 맞지 않습니다"로 같은 안내를 받는다.
4. **전제** 블로그가 없는 회원, **행동** 주소 `myblog`와 이름을 입력해 개설한다, **결과** `myblog.blog.com`이 생기고 대표 블로그가 된다. 개설 화면에서 "주소는 나중에 바꿀 수 없다"는 안내를 봤다.
5. **전제** 다른 블로그가 쓰거나 예전에 쓰였던 주소, 예약어(`admin`, `www` 등), 규칙에 어긋난 주소(`-ab`, 3자, 대문자), **행동** 개설을 시도한다, **결과** 입력 단계에서 이유와 함께 거절된다.
6. **전제** 활성 블로그가 5개인 회원, **행동** 6번째를 개설한다, **결과** 거절된다.
7. **전제** 글이 없는 새 블로그, **행동** 블로그 메인을 연다, **결과** 아직 글이 없다는 빈 상태와, 블로그 이름·소개, 카테고리 목록('전체 글'), 최근 글, 최근 댓글이 있는 사이드바가 보인다.
8. **전제** 로그인한 회원, **행동** 로그아웃한다, **결과** 비회원 상태가 되고 글쓰기·관리 화면에 들어갈 수 없다.

### 유저 스토리 2 - 글 쓰고 발행·수정·삭제하기 (우선순위: P1)

블로그 주인이 WYSIWYG 에디터로 제목·본문·이미지를 넣어 글을 쓰고, 카테고리·태그·공개 범위를 정해 발행하고, 수정·삭제한다.

**이 우선순위인 이유**: 글이 블로그의 핵심 콘텐츠다.

**독립 테스트**: 이미지가 든 글을 카테고리·태그와 함께 발행 → 상세 확인 → 수정 후 주소·순서 불변 확인 → 비공개 전환 → 삭제.

**수용 시나리오**:

1. **전제** 블로그 주인, **행동** 제목·본문(문단 제목, 굵게, 목록, 인용, 코드 블록, 링크, 이미지)·카테고리·태그 3개·공개로 발행한다, **결과** `myblog.blog.com/{글 번호}`로 이동하고 공감·댓글·조회수는 0이다. 다시 수정하러 열어도 서식이 그대로다.
2. **전제** 제목이 공백뿐이고 본문도 빈 글, **행동** 발행한다, **결과** 첫 번째 문제(제목)만 알리고 입력은 그대로 남는다.
3. **전제** 카테고리를 고르지 않은 글, **행동** 발행한다, **결과** '미분류'에 들어간다.
4. **전제** 발행 버튼을 빠르게 두 번 누름, **행동** 요청이 처리된다, **결과** 글은 하나만 생긴다.
5. **전제** 발행된 글, **행동** 제목과 본문을 고친다, **결과** 글 주소, 처음 발행일, 공감·댓글·조회수, 목록 순서는 그대로다.
6. **전제** 10MB 이하 이미지 3장, **행동** 본문에 넣는다, **결과** 고른 순서대로 들어간다. 10MB를 넘거나 이미지가 아닌 파일(이미지로 위장한 파일 포함)은 이유와 함께 거절되고 본문은 그대로다.
7. **전제** 공개 글, **행동** 비공개로 바꾼다, **결과** 다른 사람에게는 목록·검색·홈·글 수에서 사라지고 주소로 열면 404다.
8. **전제** 댓글·공감이 달린 글, **행동** 확인을 거쳐 삭제한다, **결과** 댓글·공감이 함께 사라지고 그 주소는 404다.
9. **전제** 카테고리 'A'에 글 2개, **행동** 'A'를 삭제한다, **결과** 두 글은 '미분류'로 옮겨진다. '전체 글'과 '미분류'는 이름 변경·삭제가 안 된다.
10. **전제** 태그 'java'가 붙은 글, **행동** 태그를 누른다, **결과** `myblog.blog.com/tag/java`에서 같은 블로그의 'java' 글만 보인다.

### 유저 스토리 3 - 독자가 홈에서 발견하고 읽고 반응하기 (우선순위: P1)

다른 회원(또는 비회원)이 홈 최신 글에서 글을 발견해 읽고, 블로그 안에서 검색하고, 회원이면 댓글과 공감을 남긴다.

**이 우선순위인 이유**: 한 바퀴의 끝. 이것이 돌아야 "티스토리 같은 블로그"다.

**독립 테스트**: 계정 A가 글 발행 → 비회원으로 홈에서 그 글 발견·열람 → 계정 B로 로그인해 댓글·공감 → A가 B의 댓글 삭제.

**수용 시나리오**:

1. **전제** 여러 블로그의 공개·비공개 글, **행동** 비회원이 `blog.com` 홈을 연다, **결과** 공개 글만 최신순으로 제목·블로그 이름·발행일·요약과 함께 20개씩 보인다.
2. **전제** 홈에서 더보기 중 새 글이 올라옴, **행동** 다음 묶음을 불러온다, **결과** 같은 글이 두 번 나오거나 빠지지 않는다.
3. **전제** 본문에 `<script>`나 `onerror` 속성이 든 글, **행동** 글 상세를 연다, **결과** 스크립트는 실행되지 않는다.
4. **전제** 블로그 안 검색창, **행동** " Java "를 검색한다, **결과** 앞뒤 공백은 무시되고 대소문자 구분 없이 제목·본문·태그가 일치하는 볼 수 있는 글만 최신순·10개씩 나온다. 결과 주소를 새로고침해도 같다.
5. **전제** 결과가 없는 검색어, **행동** 검색한다, **결과** 결과가 없다고 알리고 검색어는 입력창에 남아 있다.
6. **전제** 비회원, **행동** 댓글을 쓰거나 공감을 누른다, **결과** 로그인으로 안내되고 로그인 후 원래 글로 돌아온다.
7. **전제** 회원, **행동** 댓글을 쓴다, **결과** 닉네임과 작성 날짜·시각이 보이고 댓글은 작성순, 글의 댓글 수가 1 오른다. 등록을 연달아 눌러도 한 번만 올라간다.
8. **전제** 회원, **행동** 공감을 누르고 다시 누른다, **결과** 공감 수가 바로 +1, -1 되고 새로고침해도 실제 값과 같다.
9. **전제** 블로그 주인, **행동** 자기 글에 달린 남의 댓글을 지운다, **결과** 지워진다. 남의 댓글을 수정할 수는 없다.

### 유저 스토리 4 - 접근 제어, 오류, 관리자 전용 영역 (우선순위: P1)

누가 무엇을 할 수 있는지가 화면뿐 아니라 직접 요청에서도 지켜지고, 서비스 관리자만 들어가는 영역이 있다.

**이 우선순위인 이유**: 다른 P1 스토리의 안전장치다. 이게 없으면 비공개·권한 규칙이 무의미하다.

**독립 테스트**: 회원 B로 A의 글 수정 요청·비공개 글 주소·관리자 API를 직접 보내고, 비회원으로 글쓰기 주소를 직접 연다.

**수용 시나리오**:

1. **전제** 비회원, **행동** 글쓰기 주소를 직접 연다, **결과** 로그인으로 안내되고 로그인 후 그 화면으로 돌아간다.
2. **전제** 회원 B, **행동** A 블로그의 글 수정 요청을 직접 보낸다, **결과** 403이다.
3. **전제** 회원 B, **행동** A의 비공개 글 주소를 연다, **결과** 403이 아니라 404다.
4. **전제** A 블로그의 15번 글을 B 블로그 주소로 연다(`b.blog.com/15`), **행동** 연다, **결과** 볼 수 있는 글이면 `a.blog.com/15`로 이동(301)하고, 볼 수 없으면 404다.
5. **전제** 일반 회원, **행동** `blog.com/admin`이나 `/api/admin/**`에 접근한다, **결과** 403이다. 서비스 관리자로는 들어가진다.
6. **전제** 예상하지 못한 서버 오류, **행동** 화면에 오류가 보인다, **결과** 오류 위치·서버 구성 같은 내부 정보 없이 잠시 후 다시 시도하라는 안내와 돌아갈 길만 보인다.

### 유저 스토리 5 - 글쓰기와 블로그 정리를 편하게 (우선순위: P2)

블로그 주인이 임시저장, 대표 이미지, 하위 카테고리·순서, 태그 목록, 주제를 쓰고, 독자는 조회수와 이전·다음 글을 본다. 회원은 로그인 유지, 개설 안내, 회원정보 수정, 이메일 인증, 비밀번호 재설정을 쓴다.

**이 우선순위인 이유**: 없어도 한 바퀴는 돌지만, 있어야 실제로 쓸 만하다.

**독립 테스트**: 글을 임시저장 → 새 글 쓰기에서 불러오기 → 발행 후 임시저장 소멸 확인 → 하위 카테고리를 만들어 상위 목록에 합산되는지 확인.

**수용 시나리오**:

1. **전제** 글을 쓰는 중, **행동** 1분이 지나거나 저장을 누른다, **결과** 임시저장되고, 임시저장 목록에서 불러와 이어 쓸 수 있다. 발행하면 그 임시저장은 사라진다. 다른 사람에게는 보이지 않는다.
2. **전제** 대표 이미지를 고르지 않고 이미지가 든 글, **행동** 목록을 본다, **결과** 본문 첫 이미지가 대표 이미지다.
3. **전제** 상위 'A'와 하위 'A-1', **행동** 'A'를 누른다, **결과** 'A-1' 글도 함께 나오고 글 수도 합친 값이다. 하위가 있는 'A'는 바로 지울 수 없다.
4. **전제** 같은 블로그 글 1·2·3 중 2가 비공개, **행동** 다른 사람이 1에서 다음 글로 간다, **결과** 3으로 간다.
5. **전제** 같은 사용자, **행동** 같은 글을 짧은 시간 안에 여러 번 연다, **결과** 조회수는 한 번만 오른다.
6. **전제** 블로그가 없는 회원, **행동** 글쓰기를 누른다, **결과** 블로그 개설로 안내된다.
7. **전제** 비밀번호를 잊은 회원, **행동** 재설정을 요청한다, **결과** 이메일로 30분 동안 유효한 재설정 링크를 받는다.

### 유저 스토리 6 - 구독하고 피드로 모아 읽기, 구독자 공개 (우선순위: P2)

회원이 블로그를 구독하고, 구독한 블로그의 새 글을 피드로 모아 보고, 글 주소를 공유한다. 블로그 주인은 구독자에게만 보이는 글을 쓴다.

**이 우선순위인 이유**: 재방문을 만드는 핵심 기능이지만 한 바퀴에는 없어도 된다. 구독자 공개(P2)는 구독이 있어야 만들 수 있어 여기에 묶었다.

**독립 테스트**: B가 A 블로그 구독 → A 새 글 발행 → B 피드에 노출 → A 구독자 수 1 확인 → A가 구독자 공개 글 발행 → B만 열람 가능, C는 404.

**수용 시나리오**:

1. **전제** 회원 B, **행동** A 블로그를 구독한다, **결과** 버튼이 구독 중으로 바뀌고 A의 구독자 수가 1 오르며 새로고침해도 같다.
2. **전제** 블로그 주인, **행동** 자기 블로그를 구독하려 한다, **결과** 할 수 없다.
3. **전제** 구독한 블로그가 없는 회원, **행동** 피드를 연다, **결과** 빈 상태를 알리고 다른 블로그를 둘러볼 길을 준다.
4. **전제** 구독자 공개 글, **행동** 구독자 B와 비구독자 C가 연다, **결과** B와 주인은 본문을 보고, C는 404다. C의 검색·홈·인기 글·피드에서도 빠진다.
5. **전제** 글 상세, **행동** 주소를 복사한다, **결과** 수정해도 바뀌지 않는 글 주소가 복사된다.

### 유저 스토리 7 - 인기·주제·전체 검색으로 탐색하고 소통 넓히기 (우선순위: P2)

방문자가 인기 글, 주제별 글, 플랫폼 전체 검색으로 새 글과 블로그를 찾고, 회원은 댓글을 고치고 방명록을 남긴다.

**이 우선순위인 이유**: 발견 경로를 넓히는 권장 기능.

**독립 테스트**: 최근 1시간 조회수가 많은 공개 글이 인기 글 상위에 나오는지, 주제 탭에서 그 주제 글만 나오는지, 전체 검색에서 글(소속 블로그 표시)과 블로그가 함께 찾아지는지 확인.

**수용 시나리오**:

1. **전제** 최근 1시간 동안 조회가 많은 공개 글들, **행동** 홈 인기 글을 본다, **결과** 조회수 순 상위 10개가 보인다. 순위는 5분마다 바뀐다. 비공개·숨긴 글은 없다.
2. **전제** 주제 'IT·개발' 글과 주제 없는 글, **행동** 'IT·개발' 탭을 고른다, **결과** 그 주제의 최근 인기 글 6개만 보인다.
3. **전제** 전체 검색, **행동** 검색한다, **결과** 공개 글과 이용 제한되지 않은 블로그(이름·소개)만 나오고, 글 결과에는 소속 블로그가 보인다.
4. **전제** 내 댓글, **행동** 수정한다, **결과** 바뀐다. 남의 댓글에는 수정이 없다.
5. **전제** 회원, **행동** 남의 블로그에 방명록을 쓴다(비밀·답글 가능), **결과** 남고, 블로그 주인은 모든 방명록을 지울 수 있다.

### 유저 스토리 8 - 내 블로그를 한곳에서 관리하기 (우선순위: P2)

블로그 주인이 `{주소}.blog.com/manage`에서 내 글과 받은 댓글·방명록을 모아 보고 처리한다.

**이 우선순위인 이유**: 글과 댓글이 쌓이면 꼭 필요하다.

**독립 테스트**: 관리 화면에서 상태·카테고리 필터와 검색이 되는지, 여러 글을 한 번에 비공개로 바꾸는지, 댓글이 어느 글 소속인지 보이는지 확인.

**수용 시나리오**:

1. **전제** 공개·비공개·구독자 공개·임시저장 글, **행동** 내 글 관리를 연다, **결과** 상태가 구분돼 20개씩 보이고, 상태·카테고리로 거르고 검색할 수 있다.
2. **전제** 여러 글 선택, **행동** 공개 범위를 바꾸거나 삭제한다, **결과** 한 번에 처리된다.
3. **전제** 관리자가 숨긴 내 글, **행동** 내 글 관리를 연다, **결과** 숨김 상태와 사유가 보이고, 수정은 안 되지만 삭제는 된다.
4. **전제** 여러 글의 댓글과 방명록, **행동** 댓글 관리를 연다, **결과** 어느 글에 달렸는지와 함께 보이고, 지우거나 답글을 바로 쓸 수 있다.
5. **전제** 블로그를 여러 개 가진 회원, **행동** 관리 화면을 쓴다, **결과** 블로그마다 따로 관리된다.

### 유저 스토리 9 - 서비스 관리자가 회원과 게시물을 제재하기 (우선순위: P2)

서비스 관리자가 문제 회원을 정지하고, 문제 글·댓글을 사유와 함께 숨기고 되돌린다.

**이 우선순위인 이유**: 운영 가능한 서비스의 최소 조건이지만 한 바퀴에는 영역 보호(US4)만 필수다.

**독립 테스트**: 관리자로 회원 C를 7일 정지 → C 로그인 시 사유·기한 안내 → C의 블로그가 다른 사람에게 404 → 관리자가 다른 글을 숨김 → 다른 사람에게 404, 작성자에게는 사유 표시 → 해제 후 원래대로.

**수용 시나리오**:

1. **전제** 관리자가 회원을 이메일·닉네임으로 찾음, **행동** 상세를 연다, **결과** 가입일, 보유 블로그, 받은 신고 수, 제재 이력이 보인다.
2. **전제** 관리자가 회원 C를 7일 / 30일 / 영구 중 하나와 사유로 정지함, **행동** C가 로그인한다, **결과** 막히고 사유와 기한이 보인다. 이미 로그인 중이었다면 다음 행동부터 막힌다. 정지 기간 동안 C의 모든 블로그는 다른 사람에게 404다.
3. **전제** 정지 기한이 지남, **행동** C가 로그인한다, **결과** 자동으로 풀려 있고 블로그도 다시 보인다.
4. **전제** 관리자가 글을 숨김, **행동** 다른 사람이 목록·검색·홈·피드를 보거나 주소로 연다, **결과** 빠지거나 404다. 작성자는 숨김 사실과 사유를 본다.
5. **전제** 관리자가 댓글을 숨김, **행동** 다른 사람이 글을 본다, **결과** '관리자가 숨긴 댓글'로 보이고 답글은 남는다.
6. **전제** 숨김 해제, **행동** 다시 본다, **결과** 위치, 수치, 주소가 원래대로다.
7. **전제** 서비스 관리자, **행동** 다른 서비스 관리자를 제재하거나 남의 글 내용을 고치려 한다, **결과** 할 수 없다.

### 유저 스토리 10 - 블로그 여러 개, 이사, 꾸미기, 소셜 연동, 탈퇴 (우선순위: P3)

회원이 블로그를 여러 개 운영하고, 대표 블로그를 정하고, 글을 옮기고 블로그를 이사·삭제하고, 스킨을 바꾸고, 소셜 계정을 연동하고, 탈퇴한다.

**이 우선순위인 이유**: 확장 기능. 소셜 로그인·연동(P1)은 계정 규칙이 함께 움직여서 여기에 묶었다.

**독립 테스트**: 블로그 A의 15번 글을 B로 옮김 → `a.blog.com/15`가 `b.blog.com/15`로 301 → A의 이사 대상을 B로 → `a.blog.com` 301 → A 삭제 후 주소 `a`로 개설 불가.

**수용 시나리오**:

1. **전제** 같은 회원의 블로그 A·B, **행동** A의 글을 골라 B로 옮긴다, **결과** 댓글·공감도 함께 옮겨지고 카테고리는 '미분류', 태그는 이름으로 B의 태그에 다시 연결된다. 옛 주소는 B의 같은 글로 301 연결된다. 옮기지 않은 글은 A에 남는다.
2. **전제** A의 이사 대상을 B로, 그 뒤 B의 이사 대상을 C로, **행동** A 주소로 들어온다, **결과** 한 번에 C로 연결된다.
3. **전제** 블로그 삭제, **행동** 진행한다, **결과** "옮기지 않은 글 N개가 함께 삭제됩니다" 경고 후 사용자에게 사라진다. 누구도 그 주소로 다시 개설할 수 없다. 이사 안내는 계속 동작한다.
4. **전제** 이사 간 새 블로그 B를 삭제함, **행동** 옛 블로그 A 주소로 들어온다, **결과** 없는 블로그(404)다.
5. **전제** 대표 블로그, **행동** 삭제하려 한다, **결과** 다른 블로그를 대표로 바꾼 뒤에만 된다.
6. **전제** 블로그 주인, **행동** 스킨(2~3종)과 메인 글 목록 형태(리스트/썸네일)를 고른다, **결과** 바로 반영된다.
7. **전제** 이메일로 가입한 회원, **행동** 마이페이지에서 카카오를 연동한다, **결과** 이후 카카오로도 로그인된다. 이미 다른 회원에 연결된 카카오 계정이거나 이미 카카오가 연결돼 있으면 거절된다.
8. **전제** 소셜로만 가입한 회원, **행동** 마지막 남은 소셜 연동을 해제한다, **결과** 거절된다.
9. **전제** 탈퇴, **행동** 비밀번호 또는 소셜 재인증 후 진행한다, **결과** 한 번 더 확인하고, 같은 소셜 계정을 다른 회원에 다시 연동할 수 있게 된다. 블로그·글·댓글 처리는 [NEEDS CLARIFICATION: Q1].

### 유저 스토리 11 - 글과 댓글의 세부 제어 (우선순위: P3)

블로그 주인이 예약 발행, 카테고리 비공개, 태그 관리, 답글·비밀댓글·댓글 막기를 쓴다.

**이 우선순위인 이유**: 확장 기능. 답글은 2주차에 앞당겨 만든다.

**독립 테스트**: 예약 발행한 글이 시각 전에는 주인에게만 보이고 시각 후 발행일이 실제 공개 시각인지 확인. 답글이 달린 댓글 삭제 시 '삭제된 댓글입니다' 표시 확인.

**수용 시나리오**:

1. **전제** 내일 10시 예약 글, **행동** 그 전에 다른 사람이 본다, **결과** 보이지 않는다. 10시에 공개로 바뀌고 발행일은 실제 공개 시각이다.

4. **전제** 댓글을 막은 글, **행동** 회원이 댓글을 쓰려 한다, **결과** 쓸 수 없고 기존 댓글은 남는다.
5. **전제** 비공개 카테고리, **행동** 다른 사람이 블로그를 본다, **결과** 그 카테고리와 글은 보이지 않는다.
6. **전제** 태그 이름 변경·삭제, **행동** 진행한다, **결과** 같은 블로그에 같은 이름은 둘 수 없고, 태그를 지워도 글은 남는다.

### 유저 스토리 13 - 방문 통계와 스팸 차단 (우선순위: P3)

### 유저 스토리 14 - 신고, 블로그 제한, 공지, 관리 이력 (우선순위: P3)

회원이 글·댓글·블로그를 신고하고, 서비스 관리자가 신고를 처리하고, 블로그 단위로 제한하고, 공지를 올리고, 제재 이력과 운영 현황을 본다.

**이 우선순위인 이유**: 확장 운영 기능.

**독립 테스트**: 회원이 글 신고 → 관리자가 처리 대기 목록에서 블라인드 처리 → 그 대상의 신고가 모두 처리 완료 → 관리 이력에 누가·언제·무엇을·왜가 남고 수정·삭제 불가.

**수용 시나리오**:

1. **전제** 회원, **행동** 남의 글을 신고한다, **결과** 사유(스팸·광고, 음란·유해, 욕설·비방, 저작권 침해, 기타)를 고르고, 기타면 설명을 써야 한다. 같은 대상은 한 번만, 자기 것은 신고할 수 없다.
2. **전제** 처리 대기 신고, **행동** 관리자가 목록을 본다, **결과** 대상별로 묶여 신고 수가 많은 순이다. 신고가 쌓여도 자동으로 숨겨지지 않는다.
3. **전제** 관리자가 결과(블라인드, 블로그 이용 제한, 작성자 정지, 기각)를 고름, **행동** 처리한다, **결과** 그 대상의 신고가 모두 처리 완료되고 관리 이력에 남는다.
4. **전제** 블로그 E 이용 제한, **행동** 다른 사람이 E의 메인·글을 연다, **결과** 404다. 주인은 관리 화면에서 사유를 보고, 그 회원의 다른 블로그와 댓글 활동에는 영향이 없다.
5. **전제** 공지, **행동** 누구나 홈을 연다, **결과** 상단에 최신 공지 1개가 보이고 목록 페이지에서 전체를 본다.
6. **전제** 대시보드, **행동** 연다, **결과** 오늘 가입자 수, 새 글 수, 처리 대기 신고 수, 최근 제재 이력이 보인다.

### 예외 상황 (Edge Cases)

- 마지막 페이지를 넘는 페이지를 요청하면 오류가 아니라 빈 목록이다. 음수 페이지는 첫 페이지로 본다.
- 발행 시각이 같은 글은 나중에 만든 글이 위에 온다. 글을 수정해도 목록 순서는 바뀌지 않는다. 임시저장 후 나중에 발행한 글은 발행 시각 기준으로 놓인다.
- 더보기 목록(홈 최신 글, 구독 피드, 댓글)에서 중간에 새 글이 생겨도 중복·누락이 없다.
- 공백만 입력한 검색어는 검색하지 않는다. 글자 수는 앞뒤 공백을 뺀 뒤 잰다.
- 이미지로 위장한 파일은 거절한다. 업로드 실패 시 기존 이미지·본문은 그대로다. GIF는 움직임이, 모든 이미지는 비율이, 휴대폰 사진은 찍힌 방향이 유지된다.
- 다른 블로그 주소에 글 번호를 붙여 접근하면, 볼 수 있는 글은 지금 소속 블로그로 301, 볼 수 없으면 404다.
- 로그인이 만료된 채 글을 저장하면 다시 로그인한 뒤 원래 화면으로 돌아오고 쓰던 내용을 잃지 않는다.
- 글 삭제·카테고리 삭제·블로그 이사가 중간에 실패하면 일부만 처리된 상태로 남지 않는다.
- 미분류 글이 없으면 사이드바에서 '미분류'를 숨긴다.
- 같은 단계에서는 카테고리 이름이 겹칠 수 없지만, 상위가 다르면 하위 이름은 같아도 된다.
- 정지된 회원이 이미 로그인 중이면 다음 행동부터 막힌다.
- 소셜로 처음 로그인한 사람과 같은 사람이 나중에 이메일로 가입하면 별도 회원이 된다(소셜 회원은 이메일이 없으므로 중복이 아님). 정리는 사용자가 한다.

## 요구사항 (Requirements) *(필수)*

### 사용자와 권한

저장되는 역할은 **일반 회원(USER)**과 **서비스 관리자(ADMIN)** 두 가지뿐이다. **비회원**(로그인 안 함)과 **블로그 주인**(그 블로그를 개설한 회원)은 요청마다 판단하는 상태다. 가입하면 항상 일반 회원이고, 서비스 관리자는 화면이나 API로 될 수 없다. 블로그 주인은 블로그 하나당 한 명이다.

### 기능 요구사항 (Functional Requirements)

#### 공통 정책 (모든 기능에 적용)

- **FR-001**: 모든 글은 공개, 비공개, 구독자 공개 중 하나여야 하며 기본값은 공개다. 발행 후에도 바꿀 수 있어야 한다.
- **FR-002**: 보는 사람이 볼 수 없는 글(남의 비공개 글, 비구독자에게 구독자 공개 글, 숨긴 글)은 블로그 목록, 카테고리·태그 목록, 검색, 홈, 인기 글, 피드, 사이드바, 이전·다음 글, 글 개수에서 빠져야 하며, 주소로 열면 404여야 한다. 구독자 공개 글을 비구독자의 블로그 목록에 "구독자 공개 글"로 보여 줄지는 [NEEDS CLARIFICATION: Q4].
- **FR-003**: 블로그 주소는 영문 소문자·숫자·하이픈만, 4~32자, 하이픈으로 시작·끝 불가여야 한다. 사용 중인 주소, 예약어(www, api, admin, static, mail, login 등), 삭제된 블로그가 썼던 주소는 거절하고 이유를 알려야 한다.
- **FR-004**: 블로그 주소는 개설 후 바꿀 수 없어야 하고, 블로그 이름은 언제든 바꿀 수 있어야 한다. 플랫폼 주소(`blog.com`, `www.blog.com`)는 홈·로그인·서비스 관리 화면이고, `{주소}.blog.com`은 그 블로그의 모든 화면이다.
- **FR-005**: 글 주소 `{주소}.blog.com/{글 번호}`는 처음 발행할 때 정해지고 수정해도 바뀌지 않아야 한다. 글이 요청한 블로그 소속이 아니면, 볼 수 있으면 지금 소속 블로그 주소로 301, 아니면 404여야 한다.
- **FR-006**: 글 목록은 처음 발행 시각 기준 최신순이어야 하며, 같은 시각이면 나중에 만든 글이 위다. 블로그 글 목록(카테고리·태그 포함)과 블로그 내 검색은 10개, 내 글 관리는 20개씩 페이지로 나눈다. 페이지 번호는 10개씩 묶어 보여 준다. 마지막 페이지를 넘으면 빈 목록이다.
- **FR-007**: 홈 최신 글·구독 피드(20개)와 댓글(20개, 답글은 부모에 포함)은 더보기로 불러오며, 같은 항목이 두 번 나오거나 빠지지 않아야 한다.
- **FR-008**: 글자 수는 앞뒤 공백을 뺀 뒤 재야 한다. 글 제목 1~200자(비면 발행 불가), 본문 필수, 댓글 1~1,000자, 블로그 주소 4~32자, 블로그 이름 1~50자, 카테고리 이름 1~30자, 글당 태그 최대 10개.
- **FR-009**: 이미지(jpg, png, gif, webp)만 파일당 10MB 이하로 업로드할 수 있어야 하고, 이미지가 아니거나 위장 파일이거나 10MB를 넘으면 거절하고 이유를 알려야 한다. 실패해도 기존 이미지·본문은 유지돼야 한다. 비율, GIF 움직임, 사진 방향이 유지되고, 목록에는 작은 이미지(썸네일)를 쓴다.
- **FR-010**: 되돌릴 수 없는 작업(글·카테고리·블로그 삭제, 탈퇴, 이사)은 확인을 한 번 더 받아야 한다. 글을 삭제하면 댓글·공감·알림이 함께 사라진다. 관리자 제재는 삭제가 아닌 숨김이다(FR-076).

#### 회원·인증 (AUTH)

- **FR-011**: 이메일·비밀번호·닉네임으로 가입할 수 있어야 한다. 이메일 인증 코드를 확인해야만 회원이 만들어지고, 이메일·닉네임은 중복 확인하며, 비밀번호는 8자 이상 영문+숫자다. 로그인 성공 시 이전 화면(없으면 홈)으로, 실패 시 가입 여부를 드러내지 않는 같은 문구로 알린다. 닉네임은 댓글 작성자 등으로 표시된다. [AUTH-01 · P0]
- **FR-011a**: 카카오·구글 소셜 로그인을 지원해야 한다. 처음 보는 소셜 계정은 제공사 닉네임을 기본값으로 한 닉네임 확인 후 새 회원이 된다(제공사 이메일은 저장하지 않고 기존 회원과 비교하지 않는다). 로그인 후 원래 보던 주소로 돌아가되, 우리 서비스 주소만 허용한다. [AUTH-01 · P1]
- **FR-012**: 로그아웃하면 비회원 상태가 되고 글쓰기·관리 화면에 들어갈 수 없어야 한다. [AUTH-02 · P0]
- **FR-013**: 로그인 유지 옵션을 고르면 브라우저를 닫았다 열어도 로그인이 유지돼야 한다. 여러 블로그(서브도메인)를 오가도 로그인이 유지돼야 한다. [AUTH-03 · P1]
- **FR-014**: 블로그가 없는 회원이 글쓰기를 누르면 블로그 개설로 안내하고, 블로그가 있으면 글쓰기로 바로 가야 한다. [AUTH-04 · P1]
- **FR-015**: 회원은 닉네임, 프로필 사진, 비밀번호를 바꿀 수 있어야 한다. [AUTH-05 · P1]
- **FR-016**: 회원은 본인 확인(비밀번호 또는 소셜 재인증)과 한 번 더 확인을 거쳐 탈퇴할 수 있어야 한다. 탈퇴하면 로그인할 수 없고 연동된 소셜 계정은 다른 회원에 다시 연동할 수 있다. 블로그·글·댓글 처리는 [NEEDS CLARIFICATION: Q1]. [AUTH-06 · P2]
- **FR-016a**: 비밀번호를 잊은 회원은 이메일로 30분 유효한 재설정 링크를 받아 비밀번호를 바꿀 수 있어야 한다. [자체 · P1]
- **FR-016b**: 로그인한 회원은 마이페이지에서 소셜 계정(카카오·구글, 제공사당 하나)을 연동·해제할 수 있어야 한다. 이미 다른 회원에 연결된 소셜 계정, 같은 제공사 중복 연동은 거절한다. 해제 후 로그인 수단(이메일+비밀번호 또는 다른 소셜)이 하나도 남지 않으면 거절한다. 소셜로 가입한 회원에게 이메일 로그인을 추가하는 기능은 없다. [자체 · P1]

#### 블로그 (BLOG)

- **FR-017**: 회원은 주소와 이름을 따로 입력해 블로그를 개설할 수 있어야 한다(소개는 선택). 주소 중복은 입력 단계에서 알리고, 개설 화면에서 주소 변경 불가를 안내하며, 활성 블로그 5개를 넘으면 막는다. 처음 만든 블로그가 대표 블로그다. [BLOG-01 · P0]
- **FR-018**: 블로그 주인은 이름·소개·프로필 이미지를 바꿀 수 있어야 한다. 프로필 이미지가 없으면 기본 이미지, 소개가 비면 소개 자리를 숨긴다. [BLOG-02 · P0]
- **FR-019**: 블로그 메인은 그 블로그의 글을 최신순으로 제목·발행일·카테고리·본문 요약과 함께 보여야 하며, 글이 없으면 빈 상태를, 없는 블로그면 404를 보여야 한다. [BLOG-03 · P0]
- **FR-020**: 모든 블로그의 모든 화면에 같은 구성의 사이드바가 있어야 하며 주인이 구성을 바꿀 수 없다. 위에서부터 ① 블로그 홈 바로가기(이름·소개) ② 카테고리 2단계 트리와 글 수('전체 글' 맨 위, '미분류' 맨 아래, 미분류 글이 없으면 숨김) ③ 태그 목록 ④ 최근 글 5개 ⑤ 최근 댓글 5개. 볼 수 없는 글과 그 글의 댓글은 빠진다. [BLOG-04 · P0]

- **FR-077**: 관리자는 회원을 이메일·닉네임으로 찾고 상태로 거르며, 상세에서 가입일·보유 블로그·받은 신고 수·제재 이력을 볼 수 있어야 한다. 기간(7일 / 30일 / 영구)과 사유를 정해 정지하고 미리 해제할 수 있다. 정지된 회원은 로그인 시 사유·기한을 안내받고, 이미 로그인 중이면 다음 행동부터 막히며, 정지 기간 동안 그 회원의 모든 블로그는 다른 사람에게 404다. 기한이 지나면 자동 해제된다. [ADMIN-02 · P1]
- **FR-078**: 관리자는 사유를 정해 글·댓글을 숨기고 되돌릴 수 있어야 한다. 숨긴 글은 목록·검색·홈·피드·글 개수에서 빠지고 다른 사람에게 404, 작성자에게는 사실과 사유가 보이며 작성자는 수정할 수 없고 삭제는 할 수 있다. 숨긴 댓글은 '관리자가 숨긴 댓글'로 표시되고 답글은 남는다. [ADMIN-03 · P1]
- **FR-079**: 회원은 남의 글·댓글·블로그를 사유(스팸·광고, 음란·유해, 욕설·비방, 저작권 침해, 기타—설명 필수)를 골라 한 번만 신고할 수 있어야 한다(자기 것 불가). 관리자는 대상별로 묶여 신고 수 많은 순인 처리 대기 목록에서 블라인드, 블로그 이용 제한, 작성자 정지, 기각 중 하나로 처리하고, 그 대상의 신고는 모두 처리 완료가 된다. 신고 누적으로 자동 숨김하지 않는다. [ADMIN-04 · P2]
- **FR-080**: 관리자는 회원은 두고 특정 블로그만 제한할 수 있어야 한다. 그 블로그 메인과 글은 다른 사람에게 404, 주인은 관리 화면에서 사유를 보며, 그 회원의 다른 블로그와 댓글 활동에는 영향이 없다. [ADMIN-05 · P2]
- **FR-081**: 관리자 공지는 플랫폼 홈 상단에 최신 1개, 목록 페이지에 전체가 보여야 한다. 모든 제재·해제는 누가·언제·무엇을·왜가 기록되며 조회만 가능하고 대상·관리자·기간으로 검색된다. 대시보드는 오늘 가입자 수, 새 글 수, 처리 대기 신고 수, 최근 제재 이력을 보여야 한다. [ADMIN-06 · P2]

#### 공통 동작 (COM)

- **FR-082**: 모든 행동은 위 권한표를 따르고, 권한이 없으면 위 처리표대로 처리해야 한다. 주소 직접 입력·직접 요청에도 같은 결과여야 하고, 로그인 안내를 거치면 원래 화면으로 돌아간다. [COM-01 · P0]
- **FR-083**: 없는 주소는 404, 권한 없음은 403으로 알리고 홈이나 이전 화면으로 돌아갈 길을 줘야 한다. 입력 오류는 어느 항목이 왜 잘못됐는지 알리고 입력을 유지한다. 예상치 못한 오류에도 내부 정보를 드러내지 않고 다시 시도하라고 안내한다. [COM-02 · P0]

#### 자체 기능 (그 밖)

- **FR-084**: 글 상세 아래에 같은 카테고리의 다른 글 목록을 보여야 한다(볼 수 있는 글만). [자체 · P2]
- **FR-085**: 글 상세 아래에 내용이 비슷한 글을 추천해야 한다(볼 수 있는 글만). 2주 안에 도전한다. [자체 · P2]

#### 비기능 요구사항

- **NFR-001 (보안)**: 사용자 입력(글 제목·본문, 댓글, 블로그 이름·소개, 닉네임)의 스크립트는 어디서도 실행되지 않아야 한다. 다른 사이트가 로그인한 사용자 대신 행동할 수 없어야 한다. 로그인 정보와 비밀번호는 주소창·화면·오류 메시지에 드러나지 않고, 비밀번호는 복원할 수 없는 형태로만 저장된다.
- **NFR-002 (성능)**: 목록은 페이지 단위로 불러오고, 목록에는 작은 이미지만, 원본은 글 상세에서만 불러와야 한다. 홈의 무거운 섹션(인기 글, 주제별 글)은 미리 계산해 둔 값을 5분 동안 재사용한다. 공감·구독 버튼은 누르는 즉시 바뀐 상태를 보여야 한다.
- **NFR-003 (신뢰성)**: 발행·댓글·공감·구독은 중복 요청에도 한 번만 처리해야 한다. 각종 수치는 새로고침 시 실제 값과 같아야 한다. 저장 실패·로그인 만료에도 쓰던 내용을 잃지 않아야 한다. 여러 단계 작업은 일부만 처리된 상태로 남지 않아야 한다. 재시작 후에도 글·이미지·댓글이 남아야 한다.
- **NFR-004 (사용성)**: 휴대폰 화면(360px)부터 데스크톱까지 가로 스크롤 없이 모든 P0 기능을 쓸 수 있어야 한다. 처리 중 상태와 결과를 알려야 한다. 날짜·시각은 한국 시간이다. 최신 크롬·사파리·엣지에서 같은 기능이 동작해야 한다.

### 핵심 엔티티 (Key Entities)

- **회원**: 이메일(이메일 가입만), 닉네임, 프로필 사진, 역할(일반 회원 / 서비스 관리자), 상태(활동 / 정지 / 탈퇴), 정지 사유·기한.
- **소셜 계정**: 회원에 연결된 카카오·구글 계정. 제공사당 하나.
- **블로그**: 주소(불변, 영구 예약), 이름, 소개, 프로필 이미지, 스킨·목록 형태, 주인(회원 1명), 대표 여부, 이사 대상 블로그, 이용 제한 상태, 삭제 여부.
- **글**: 소속 블로그, 번호(불변, 플랫폼 전체에서 하나), 제목, 본문, 요약, 처음 발행 시각, 수정 시각, 공개 범위(공개 / 비공개 / 구독자 공개), 상태(임시저장 / 발행 / 예약), 카테고리(0~1), 태그(0~10), 주제, 대표 이미지, 조회수, 숨김 상태, 댓글 허용 여부.
- **조회 기록**: 누가 언제 어떤 글을 열었는지. 인기 글과 중복 조회 판정에 쓴다.
- **카테고리**: 소속 블로그, 이름, 상위 카테고리(최대 1단계), 순서, 공개 여부. '전체 글'과 '미분류'는 고정.
- **태그**: 소속 블로그, 이름. 글과 다대다.
- **댓글 / 방명록**: 글 또는 블로그, 작성자, 내용, 작성 시각, 상위 댓글(1단계), 비밀 여부, 삭제 표시, 숨김 상태.
- **공감 / 구독**: 회원과 글, 회원과 블로그의 쌍. 쌍마다 하나.
- **이미지**: 저장 위치, 원본 파일명, 크기, 썸네일.
- **알림**: 받는 회원, 종류, 대상, 읽음 여부.
- **차단 / 금칙어**: 블로그 단위.
- **신고**: 신고자, 대상(글·댓글·블로그), 사유, 처리 상태와 결과.
- **제재 기록**: 관리자, 시각, 대상, 행동, 사유. 수정·삭제 불가.
- **공지**: 관리자가 작성, 모든 사용자에게 보임.

## 성공 기준 (Success Criteria) *(필수)*

### 측정 가능한 결과

- **SC-001**: 2주 안에 P0 기능(FR 중 `· P0`)만으로 "가입 → 블로그 개설 → 글 발행 → 다른 사람이 홈에서 발견 → 읽기·댓글·공감" 시나리오(US1~US3)를 막힘 없이 끝낼 수 있다.
- **SC-002**: 남의 비공개 글·볼 수 없는 구독자 공개 글·숨긴 글·제한 블로그·정지 회원 블로그에 대한 모든 직접 접근(주소 입력, 직접 요청)이 100% 404로 응답하고, 어떤 목록·개수에도 노출되지 않는다.
- **SC-003**: 권한표의 모든 ✕ 칸을 직접 요청으로 시도했을 때 100% 로그인 안내(401) 또는 403/404로 막힌다.
- **SC-004**: 발행·댓글·공감·구독을 빠르게 연속 요청해도 중복 생성이 0건이다.
- **SC-005**: 공감 수, 댓글 수, 구독자 수, 글 수가 새로고침 후 실제 값과 100% 일치한다.
- **SC-006**: 글을 수정한 뒤에도, 글을 옮기거나 블로그를 이사한 뒤에도, 이전에 공유한 글 주소가 100% 그 글로 열린다.
- **SC-007**: 사용자 입력 필드 전체에 스크립트를 넣었을 때 실행되는 곳이 0곳이다.
- **SC-008**: 휴대폰 화면(360px)에서 모든 P0 기능을 가로 스크롤 없이 쓸 수 있고, 최신 크롬·사파리·엣지에서 같은 결과가 나온다.

## 명확화 (Clarifications)

### 확정 사항

- 남의 비공개 글, 볼 수 없는 구독자 공개 글, 숨긴 글, 제한 블로그는 403이 아니라 404다.
- 블로그 주소는 변경 불가, 삭제 후에도 영구히 다시 쓸 수 없다. 글 주소는 처음 발행 시 정해지고 불변이다.
- 목록 순서는 처음 발행 시각 기준 최신순이고, 수정해도 유지된다.
- 관리자 제재는 삭제가 아닌 숨김이며, 남의 내용은 수정할 수 없다. 블라인드 글·제한 블로그는 다른 사람에게 안내 문구 없이 404다.
- 정지 기간 동안 그 회원의 모든 블로그를 숨긴다.
- 글자 수는 제목 200자, 블로그 이름 50자, 카테고리 이름 30자다.
- 주제는 글마다 하나, 고정 목록 10개다.
- 인기 글은 최근 1시간 조회수 순 상위 10개, 5분마다 갱신이다.
- 연타 방지: 공감·구독은 회원·대상 쌍마다 하나만 저장되고, 발행·댓글은 같은 요청이 두 번 와도 한 번만 처리된다.
