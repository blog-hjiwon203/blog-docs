# 기능 명세 (Feature Specification): 티스토리형 블로그 플랫폼

## 표기

- **기능 코드**: 원본 5장의 `영역코드-두 자리 번호`(예: `POST-03`). 요구사항, 작업, 커밋, PR 모두 이 코드로 가리킨다. 삭제된 번호는 다시 쓰지 않는다.
- **자체 기능 코드**: 원본 5.14 자체 기능에는 코드가 없어서 `OWN-01`~`OWN-06`을 붙였다(이 문서에서 새로 정함).
- **등급**: P0 필수 · P1 권장 · P2 확장 (원본 그대로).
- **스토리 우선순위**: Spec Kit 표기 P1~P3은 등급과 이렇게 대응한다. 스토리 **P1 = P0**, 스토리 **P2 = P1**, 스토리 **P3 = P2**.
- **원본 위치**: `(원본 4.2)`처럼 원본 절 번호를 붙여 원문을 찾을 수 있게 했다.
- **(채움)**: 원본에 없어서 이 문서에서 채운 값. 모두 [지원이 확인할 것](./review.md)에 있다.

## 개요

누구나 회원가입 후 자기 블로그를 개설하고, 글을 발행하고, 다른 블로그를 구독·공감·댓글로 소통할 수 있는 멀티 유저 블로그 플랫폼이다. 기준 모델은 티스토리다. 2주 안에 P0 24개를 모두 만들어 "가입 → 블로그 개설 → 글 발행 → 다른 사람이 홈에서 발견 → 읽기·댓글·공감" 한 바퀴를 완성한다. (원본 1장, 7장)

### 주요 방식 (원본 2장)

| 번호 | 항목 | 선택 |
| --- | --- | --- |
| 7.1 | 로그인 방식 | 둘 다. 이메일 P0, 소셜(카카오·구글) P1 |
| 7.2 | 회원당 블로그 수 | 여러 개, 활성 블로그 최대 5개. 처음 만든 블로그가 대표 블로그 |
| 7.3 | 블로그 주소 | 서브도메인 `{주소}.blog.com` (예: myblog.blog.com) |
| 7.4 | 에디터 | WYSIWYG (보이는 대로 편집, 티스토리 기본 모드와 같은 방식) |
| 7.5 | 글 주소 | 번호 `{주소}.blog.com/{글 번호}`. 글 번호는 플랫폼 전체에서 하나. 제목 슬러그는 쓰지 않는다 |
| 7.6 | 인기 글 기준 | 최근 1시간 동안의 조회·공감·댓글에 가중치를 곱한 인기 점수 순, 공개 글 상위 10개, 5분마다 갱신 (2026-10-07 지원 결정으로 조회수만에서 바꿈) |
| 7.7 | 주제 지정 단위 | 글마다, 고정 목록 10개 |
| 7.8 | 확장 공개 범위 | 구독자 공개 (그 블로그를 구독한 회원과 주인만 열람) |

### 범위

- **2주 안에 만듦**: P0 24개 전부, 그리고 P1·P2 중 원본 7장 일정에 든 것(작업 목록 참고)과 이메일 인증(OWN-01), 비슷한 글 추천(OWN-06, 도전).
- **명세는 하되 2주 뒤로**: 나머지 P1·P2.
- **명세는 하되 2주 뒤로 (2026-10-08 추가)**: SOC-03 저장, SUB-06 추천 블로그, HOME-04 인기 블로거, HOME-05 랭킹 전체보기. 원본 5장에서 "계획 없음"(구현 방식을 정하지 않음)이던 것을 지원이 만들기로 하고 방식을 정했다(유저 스토리 16).
- **제외**: 비회원 댓글(OWN-04, 2026-10-07 지원 결정), 맞구독(SUB-05, 2026-10-08 지원 결정), 광고·수익화·결제, 모바일 앱, 이메일·푸시 알림(가입 인증·비밀번호 재설정 메일 제외), 개인 도메인 연결, 홈 구성 변경. 블로그 꾸미기는 스킨·포인트 색·목록 형태·사이드바 모듈 순서와 표시 여부까지만 한다(BLOG-05, 2026-10-08 지원 결정).
- **추후 구현(블로그 꾸미기)**: 스킨 HTML·CSS 직접 편집, 헤더 배너 이미지·파비콘, 상단 메뉴, 사이드바 모듈별 개수 바꾸기, 메인 글 목록 개수, 홈 화면 구성, 블로그 전체 댓글·방명록 설정. 지금 ERD에는 저장할 곳이 없고, 넣을 때 기능 코드를 새로 붙인다(2026-10-08 지원 결정).

## 사용자 시나리오와 테스트 (User Scenarios & Testing) *(필수)*

각 스토리 머리의 **기능**은 그 스토리가 확인하는 기능 코드다.

### 유저 스토리 1 - 가입하고 내 블로그 열기 (우선순위: P1)

**기능**: AUTH-01, AUTH-02, OWN-01, BLOG-01, BLOG-02, BLOG-03, BLOG-04

비회원이 이메일로 가입·로그인한 뒤 주소와 이름을 정해 블로그를 만들고, 블로그 메인과 사이드바를 확인한다.

**이 우선순위인 이유**: 블로그가 없으면 다른 어떤 기능도 시작할 수 없다. 한 바퀴의 출발점이다.

**독립 테스트**: 새 이메일로 인증 코드 확인 → 가입 → 블로그 개설 → 블로그 메인에서 빈 상태와 사이드바 확인 → 로그아웃.

**수용 시나리오**:

1. **전제** 비회원, **행동** 이메일 인증 코드를 확인하고 비밀번호·닉네임을 입력해 가입한다, **결과** 회원이 만들어진다. 인증 코드를 확인하지 않으면 회원이 만들어지지 않는다.
2. **전제** 이미 가입된 이메일이나 쓰이는 닉네임, 또는 7자이거나 숫자가 없는 비밀번호, **행동** 가입한다, **결과** 어느 항목이 왜 틀렸는지 알리고 입력은 그대로 남는다.
3. **전제** 틀린 비밀번호 또는 없는 이메일, **행동** 로그인한다, **결과** 둘 다 "이메일 또는 비밀번호가 맞지 않습니다"로 같은 안내를 받는다.
4. **전제** `blog.com`에서 로그인한 회원, **행동** 자기 블로그 `myblog.blog.com`의 관리 화면으로 간다, **결과** 다시 로그인하지 않아도 들어가진다.
5. **전제** 블로그가 없는 회원, **행동** 주소 `myblog`와 이름을 입력해 개설한다, **결과** `myblog.blog.com`이 생기고 대표 블로그가 된다. 개설 화면에서 "주소는 나중에 바꿀 수 없다"는 안내를 봤다.
6. **전제** 이미 쓰이거나 삭제된 블로그가 썼던 주소, 예약어(`admin`, `www` 등), 규칙에 어긋난 주소(`-ab`, 3자, 대문자), **행동** 개설을 시도한다, **결과** 이유와 함께 거절된다.
7. **전제** 활성 블로그가 5개인 회원, **행동** 6번째를 개설한다, **결과** 거절된다.
8. **전제** 글이 없는 새 블로그, **행동** 블로그 메인을 연다, **결과** 글이 없다는 빈 상태와 사이드바(블로그 이름·소개, 카테고리, 최근 글, 최근 댓글)가 보인다.
9. **전제** 로그인한 회원, **행동** 로그아웃한다, **결과** 비회원 상태가 되고 관리 화면에 들어갈 수 없다. 다른 블로그 주소로 가도 로그아웃 상태다.

### 유저 스토리 2 - 글 쓰고 발행·수정·삭제하기 (우선순위: P1)

**기능**: POST-01, POST-02, POST-03, POST-05, POST-06, CAT-01, CAT-02, TAG-01, TAG-02

블로그 주인이 WYSIWYG 에디터로 제목·본문·이미지를 넣어 글을 쓰고, 카테고리·태그·공개 범위를 정해 발행하고, 수정·삭제한다.

**이 우선순위인 이유**: 글이 블로그의 핵심 콘텐츠다.

**독립 테스트**: 이미지가 든 글을 카테고리·태그와 함께 발행 → 상세 확인 → 수정 후 주소·순서 불변 확인 → 비공개 전환 → 삭제.

**수용 시나리오**:

1. **전제** 블로그 주인, **행동** 제목·주제·본문(문단 제목, 굵게, 목록, 인용, 코드 블록, 링크, 이미지)·카테고리·태그 3개·공개로 발행한다, **결과** `myblog.blog.com/{글 번호}`로 이동한다. 다시 수정하러 열어도 서식이 그대로다.
2. **전제** 제목이 비어 있는 글, **행동** 발행한다, **결과** 발행되지 않고 이유를 알리며 입력은 그대로 남는다.
3. **전제** 발행 버튼을 빠르게 두 번 누름, **행동** 요청이 처리된다, **결과** 글은 하나만 생긴다.
4. **전제** 발행된 글, **행동** 제목과 본문을 고친다, **결과** 글 주소, 처음 발행일, 목록 순서는 그대로이고 수정 시각이 따로 남는다.
5. **전제** 다른 회원, **행동** 남의 글 수정·삭제 요청을 직접 보낸다, **결과** 403이다.
6. **전제** 10MB 이하 jpg/png/gif/webp 이미지, **행동** 본문에 넣는다, **결과** 들어간다. 10MB를 넘거나 다른 형식이면 이유와 함께 거절되고 본문은 그대로다.
7. **전제** 공개 글, **행동** 비공개로 바꾼다, **결과** 다른 사람에게는 목록·검색·홈·글 수에서 사라지고 주소로 열면 404다.
8. **전제** 글, **행동** 확인 창을 거쳐 삭제한다, **결과** 그 주소는 404다.
9. **전제** 카테고리 'A'에 글 2개, **행동** 'A'를 삭제한다, **결과** 두 글은 '미분류'로 옮겨진다.
10. **전제** 태그 'java'가 붙은 글, **행동** 태그를 누른다, **결과** `myblog.blog.com/tag/java`에서 같은 블로그의 'java' 글만 보인다.
11. **전제** 태그 11개, **행동** 발행한다, **결과** 거절된다. 처음 쓰는 태그 이름은 블로그 태그에 자동으로 추가된다.

### 유저 스토리 3 - 독자가 홈에서 발견하고 읽고 반응하기 (우선순위: P1)

**기능**: HOME-01, POST-04, SRCH-01, CMT-01, CMT-02, SOC-01

다른 회원(또는 비회원)이 홈 최신 글에서 글을 발견해 읽고, 블로그 안에서 검색하고, 회원이면 댓글과 공감을 남긴다.

**이 우선순위인 이유**: 한 바퀴의 끝. 이것이 돌아야 "티스토리 같은 블로그"다.

**독립 테스트**: 계정 A가 글 발행 → 비회원으로 홈에서 그 글 발견·열람 → 계정 B로 로그인해 댓글·공감 → A가 B의 댓글 삭제.

**수용 시나리오**:

1. **전제** 여러 블로그의 공개·비공개 글, **행동** 비회원이 `blog.com` 홈을 연다, **결과** 공개 글만 최신순으로 20개씩 보이고 더보기로 다음 20개를 불러온다.
2. **전제** 홈에서 더보기 중 새 글이 올라옴, **행동** 다음 묶음을 불러온다, **결과** 같은 글이 두 번 나오거나 빠지지 않는다.
3. **전제** 글 상세, **행동** 연다, **결과** 제목, 작성일, 카테고리, 본문, 태그, 공감 수, 댓글, 이전·다음 글이 보인다. 주인에게만 수정·삭제가 보인다.
4. **전제** 본문에 `<script>`나 `onclick` 속성을 넣어 보낸 글, **행동** 글 상세를 연다, **결과** 스크립트는 실행되지 않는다.
5. **전제** 블로그 안 검색창, **행동** 검색한다, **결과** 제목·본문·태그가 일치하는, 보는 사람이 볼 수 있는 글만 최신순·10개씩 나온다.
6. **전제** 비회원, **행동** 댓글을 쓰거나 공감을 누른다, **결과** 로그인으로 안내되고 로그인 후 원래 글로 돌아온다.
7. **전제** 회원, **행동** 댓글을 쓰고 자기 댓글을 지운다, **결과** 댓글은 작성순으로 보이고 지울 수 있다. 등록을 연달아 눌러도 댓글은 하나다.
8. **전제** 회원, **행동** 공감을 누르고 다시 누른다, **결과** 공감 수가 +1, -1 되고 새로고침해도 실제 값과 같다.
9. **전제** 블로그 주인, **행동** 자기 블로그에 달린 남의 댓글을 지운다, **결과** 지워진다.

### 유저 스토리 4 - 접근 제어, 오류, 관리자 전용 영역 (우선순위: P1)

**기능**: COM-01, COM-02, ADMIN-01

누가 무엇을 할 수 있는지가 화면뿐 아니라 직접 요청에서도 지켜지고, 서비스 관리자만 들어가는 영역이 있다.

**이 우선순위인 이유**: 다른 P1 스토리의 안전장치다.

**독립 테스트**: 회원 B로 A의 글 수정 요청·A의 비공개 글 주소·관리자 API를 직접 보내고, 비회원으로 관리 화면 주소를 직접 연다.

**수용 시나리오**:

1. **전제** 비회원, **행동** `myblog.blog.com/manage`를 직접 연다, **결과** 로그인으로 안내된다(401).
2. **전제** 회원 B, **행동** A 블로그의 관리 화면이나 글 수정 요청을 직접 보낸다, **결과** 403이다.
3. **전제** 비회원 또는 회원 B, **행동** A의 비공개 글 주소를 연다, **결과** 401·403이 아니라 404다.
4. **전제** A 블로그의 15번 글, **행동** `b.blog.com/15`로 연다, **결과** 볼 수 있는 글이면 `a.blog.com/15`로 301, 볼 수 없으면 404다.
5. **전제** 일반 회원, **행동** `blog.com/admin`이나 관리자 API에 접근한다, **결과** 403이다. 서비스 관리자는 들어가진다. 가입이나 화면으로 서비스 관리자가 될 방법은 없다.
6. **전제** 없는 주소, 권한 없음, 입력 오류, **행동** 화면을 본다, **결과** 404·403 화면, 또는 어느 항목이 잘못됐는지 안내가 보인다.

### 유저 스토리 5 - 쓰기와 읽기를 편하게 (우선순위: P2)

**기능**: AUTH-03, AUTH-04, AUTH-05, OWN-02, POST-07, POST-08, POST-09, POST-10, POST-11, CAT-03, CAT-04, TAG-03, HOME-02, HOME-03

블로그 주인은 임시저장, 대표 이미지, 하위 카테고리·순서, 태그 목록, 주제를 쓰고, 독자는 조회수, 이전·다음 글, 인기 글, 주제별 글을 본다. 회원은 로그인 유지, 개설 안내, 회원정보 수정, 비밀번호 재설정을 쓴다.

**이 우선순위인 이유**: 없어도 한 바퀴는 돌지만, 있어야 실제로 쓸 만하다.

**독립 테스트**: 글을 임시저장 → 목록에서 불러오기 → 하위 카테고리를 만들어 상위 목록에 합쳐지는지 확인 → 최근 1시간 조회가 많은 글이 홈 인기 글에 오는지 확인.

**수용 시나리오**:

1. **전제** 글을 쓰는 중, **행동** 1분이 지나거나 저장을 누른다, **결과** 임시저장되고 임시저장 목록에서 불러와 이어 쓸 수 있다.
2. **전제** 대표 이미지를 고르지 않은 이미지 든 글, **행동** 목록을 본다, **결과** 본문 첫 이미지가 대표 이미지다.
3. **전제** 상위 'A'와 하위 'A-1', **행동** 'A'를 누른다, **결과** 'A-1' 글도 함께 나오고 글 수도 합친 값이다. 카테고리는 2단계까지만 만들 수 있고 드래그로 순서·상하위를 바꾼다.
4. **전제** 같은 블로그 글 1·2·3 중 2가 비공개, **행동** 다른 사람이 1에서 다음 글로 간다, **결과** 3으로 간다.
5. **전제** 같은 사용자, **행동** 같은 글을 짧은 시간 안에 여러 번 연다, **결과** 5분 안에는 조회수가 한 번만 오른다.
6. **전제** 최근 1시간 동안 조회·공감·댓글이 많은 공개 글들, **행동** 홈 인기 글을 본다, **결과** 인기 점수(최근 1시간의 조회 수×1 + 공감 수×3 + 댓글 수×5) 순 상위 10개가 보이고 5분마다 바뀐다. 조회만 많은 글보다 공감·댓글이 함께 많은 글이 위에 온다.
7. **전제** 주제 'IT·개발' 탭, **행동** 고른다, **결과** 그 주제의 인기 글 6개가 보인다. 주제를 고르지 않은 글은 '주제 없음'이라 어느 탭에도 없다. 순서는 인기 글과 같은 인기 점수이고, 6개가 안 되면 그 주제의 최신 글로 채운다.
8. **전제** 블로그가 없는 회원, **행동** 글쓰기를 누른다, **결과** 블로그 개설로 안내된다. 블로그가 있으면 대표 블로그의 글쓰기로 간다.
9. **전제** 비밀번호를 잊은 회원, **행동** 재설정을 요청한다, **결과** 이메일로 30분 동안 유효한 재설정 링크를 받는다.
10. **전제** 로그인 유지를 고른 회원, **행동** 브라우저를 닫았다 연다, **결과** 로그인이 유지된다.

### 유저 스토리 6 - 구독, 피드, 구독자 공개, 공유 (우선순위: P2)

**기능**: SUB-01, SUB-02, SUB-03, POST-12, SOC-02

회원이 블로그를 구독하고 피드로 새 글을 모아 보며, 글을 공유한다. 블로그 주인은 구독자에게만 보이는 글을 쓴다.

**이 우선순위인 이유**: 재방문을 만들지만 한 바퀴에는 없어도 된다. 구독자 공개(P2)는 구독이 있어야 만들 수 있어 함께 묶었다.

**독립 테스트**: B가 A 블로그 구독 → A 새 글 → B 피드에 노출 → A 구독자 수 1 → A가 구독자 공개 글 발행 → B는 열람, C는 목록에서 안 보이고 링크로 열면 구독 안내.

**수용 시나리오**:

1. **전제** 회원 B, **행동** A 블로그를 구독하고 해제한다, **결과** A의 구독자 수가 1 오르고 다시 내려간다.
2. **전제** 구독한 블로그들의 새 글, **행동** 피드를 연다, **결과** 최신순 20개씩 더보기로 보이고 중복·누락이 없다.
3. **전제** 구독자 공개 글, **행동** 구독자 B와 비구독자 C가 연다, **결과** B와 주인은 본문을 본다. C에게는 블로그 목록·검색·홈·인기 글·피드·글 수에서 빠진다. C가 링크로 직접 열면 404 대신 "구독자 공개 글입니다" 안내와 구독 버튼이 보이고, 제목과 본문은 보이지 않는다. 비회원이면 로그인 안내가 함께 보인다.
4. **전제** 글 상세, **행동** 주소 복사나 SNS 공유를 누른다, **결과** 바뀌지 않는 글 주소가 공유된다.

### 유저 스토리 9 - 회원 정지와 게시물 숨김 (우선순위: P2)

**이 우선순위인 이유**: 운영의 최소 조건이지만 한 바퀴에는 영역 보호(ADMIN-01)만 필수다.

**독립 테스트**: 관리자가 회원 C를 7일 정지 → C 로그인 시 사유·기한 안내 → C의 블로그가 다른 사람에게 404 → 관리자가 글을 숨김 → 다른 사람에게 404, 작성자에게 사유 표시.

**수용 시나리오**:

1. **전제** 관리자, **행동** 회원을 이메일·닉네임으로 찾아 상세를 연다, **결과** 가입일, 보유 블로그, 받은 신고 수, 제재 이력이 보인다.
2. **전제** 관리자가 C를 7일 / 30일 / 영구 중 하나와 사유로 정지함, **행동** C가 로그인한다, **결과** 막히고 사유와 기한이 보인다. 정지 기간 동안 C의 모든 블로그는 다른 사람에게 404다. 기간이 끝나면 자동으로 풀린다.
3. **전제** 정지 전부터 로그인해 있던 C, **행동** 계속 쓴다, **결과** 다음 요청부터 막힌다.
4. **전제** 관리자가 글을 숨김, **행동** 다른 사람이 보거나 주소로 연다, **결과** 홈·검색·목록에서 빠지고 주소는 404다. 작성자는 사유를 보고, 수정은 못 하지만 삭제는 한다.
5. **전제** 관리자가 댓글을 숨김, **행동** 다른 사람이 글을 본다, **결과** '관리자가 숨긴 댓글'로 보인다.

### 유저 스토리 10 - 블로그 여러 개, 이사, 꾸미기, 소셜, 탈퇴 (우선순위: P3)

**기능**: BLOG-05, BLOG-06, BLOG-07, BLOG-08, AUTH-01(소셜), OWN-03, AUTH-06

**이 우선순위인 이유**: 확장 기능. 소셜 로그인·연동(P1)은 계정 규칙이 함께 움직여서 여기에 묶었다.

**독립 테스트**: A의 15번 글을 B로 옮김 → `a.blog.com/15`가 `b.blog.com/15`로 301 → A의 이사 대상을 B로 → `a.blog.com` 301 → A 삭제 후 주소 `a`로 개설 불가.

**수용 시나리오**:

1. **전제** 같은 회원의 블로그 A·B, **행동** A의 글을 골라 B로 옮긴다, **결과** 카테고리는 '미분류', 태그는 이름으로 B의 태그에 다시 연결되고, 옛 주소는 B의 같은 글로 301 연결된다. 옮기지 않은 글은 A에 남는다.
2. **전제** A의 이사 대상을 B로, 그 뒤 B의 이사 대상을 C로, **행동** A 주소로 들어온다, **결과** 한 번에 C로 간다. 순환은 생기지 않는다.
3. **전제** 이사한 블로그 A, **행동** 주인이 A의 관리 화면에 들어간다, **결과** 들어가진다. 방문자는 새 블로그로 301된다.
4. **전제** 블로그 삭제, **행동** 진행한다, **결과** "옮기지 않은 글 N개가 함께 삭제됩니다" 경고 후 사라진다. 누구도 그 주소로 다시 개설할 수 없고 이사 연결은 계속 동작한다.
5. **전제** 이사 간 새 블로그 B를 삭제함, **행동** 옛 블로그 A 주소로 들어온다, **결과** 없는 블로그(404)다.
6. **전제** 대표 블로그, **행동** 삭제하려 한다, **결과** 다른 블로그를 대표로 바꾼 뒤에만 된다. '내 블로그' 바로가기와 댓글 작성자 닉네임 링크는 대표 블로그로 간다.
7. **전제** 블로그 주인, **행동** 스킨(2~3종)과 메인 글 목록 형태(리스트/썸네일)를 고른다, **결과** 반영된다.
8. **전제** 처음 보는 카카오 계정, **행동** 카카오로 로그인한다, **결과** 카카오 닉네임이 채워진 닉네임 확인을 거쳐 새 회원이 되고, 로그인 전에 보던 화면으로 돌아간다.
9. **전제** 이메일로 가입한 회원, **행동** 마이페이지에서 카카오를 연동한다, **결과** 이후 카카오로도 로그인된다. 이미 다른 회원에 연결된 카카오 계정이거나 이미 카카오가 연결돼 있으면 거절된다.
10. **전제** 소셜로만 가입한 회원, **행동** 마지막 남은 소셜 연동을 해제한다, **결과** 거절된다.
11. **전제** 탈퇴, **행동** 비밀번호 또는 소셜 재인증 후 한 번 더 확인한다, **결과** 로그인할 수 없고, 같은 소셜 계정을 다른 회원에 다시 연동할 수 있다. 그 회원의 블로그·글·댓글은 모두 삭제(소프트)되어 다른 사람에게 보이지 않는다. 블로그 주소는 다시 쓸 수 없고, 답글이 달린 댓글은 '삭제된 댓글입니다'로 남는다.

4. **전제** 댓글을 막은 글, **행동** 회원이 댓글을 쓰려 한다, **결과** 쓸 수 없다.
5. **전제** 비공개 카테고리, **행동** 다른 사람이 블로그를 본다, **결과** 그 카테고리와 글은 보이지 않는다.
6. **전제** 태그 이름 변경·삭제, **행동** 진행한다, **결과** 같은 블로그에 같은 이름은 둘 수 없고, 태그를 지워도 글은 남는다.

**기능**: MNG-03, MNG-04

**수용 시나리오**:

1. **전제** 방문이 있음, **행동** 관리 홈을 연다, **결과** 오늘·어제·누적 방문자, 최근 댓글·글 요약이 보이고, 통계에서 일·주·월별 방문자 그래프, 인기 글 순위, 유입 경로를 본다.
2. **전제** 블로그 주인이 회원 B를 차단함, **행동** B가 이 블로그에 댓글이나 방명록을 쓰거나 구독하려 한다, **결과** "이 블로그에는 쓸 수 없습니다"로 거절되고, B의 기존 구독은 차단할 때 지워졌다.
3. **전제** 블로그에 금칙어가 있음, **행동** 누가 금칙어가 든 댓글이나 방명록을 쓴다(대소문자 무시), **결과** "금칙어가 포함되어 있습니다"로 등록되지 않는다. 이미 있던 댓글은 그대로다.

### 유저 스토리 14 - 신고, 블로그 제한, 공지, 관리 이력 (우선순위: P3)

**기능**: ADMIN-04, ADMIN-05, ADMIN-06

**수용 시나리오**:

1. **전제** 회원, **행동** 글·댓글·블로그를 신고한다, **결과** 사유(스팸·광고, 음란·유해, 욕설·비방, 저작권 침해, 기타)를 고르고, 기타면 설명을 써야 한다.
2. **전제** 처리 대기 신고, **행동** 관리자가 목록을 본다, **결과** 대상별로 묶여 신고 수가 많은 순이다.
3. **전제** 관리자가 결과(블라인드, 블로그 이용 제한, 작성자 정지, 기각)를 고름, **행동** 처리한다, **결과** 그 대상의 신고가 모두 처리 완료되고, 결과와 사유가 관리 이력에 남는다.
4. **전제** 블로그 E 이용 제한, **행동** 다른 사람이 E를 연다, **결과** 404다. 주인은 관리 화면에서 사유를 본다. 회원 자체는 제한되지 않는다.
5. **전제** 공지, **행동** 홈을 연다, **결과** 상단에 최신 공지 1개가 보이고 목록 페이지에서 전체를 본다.
6. **전제** 관리자, **행동** 대시보드와 관리 이력을 연다, **결과** 오늘 가입자 수, 새 글 수, 처리 대기 신고 수, 최근 제재 이력이 보이고, 이력은 대상·관리자·기간으로 검색만 된다.

**수용 시나리오**:

2. **전제** 글 상세, **행동** 아래로 내린다, **결과** 내용이 비슷한 글이 추천된다. 보는 사람이 볼 수 없는 글은 추천되지 않는다.

### 유저 스토리 16 - 저장한 글과 랭킹 (우선순위: P3)

**기능**: SOC-03, SUB-06, HOME-04, HOME-05

회원이 나중에 읽을 글을 저장해 모아 보고, 독자가 인기 블로그를 발견하고 인기 글·블로거 순위 전체를 본다.

**이 우선순위인 이유**: 원본에서 구현 방식을 정하지 않았던 P2 기능을 2026-10-08에 만들기로 정했다. 한 바퀴와 2주 일정에는 들지 않는다. 인기 블로거 순위가 추천 블로그와 랭킹 전체보기의 바탕이라 함께 묶었다.

**독립 테스트**: B가 A의 글을 저장 → 저장한 글 목록에 보임 → A가 그 글을 비공개로 바꿈 → B의 목록에 저장할 때 제목으로 "볼 수 없는 글" 표시, 누르면 안내 → B가 목록에서 저장 취소. 홈 인기 블로거 5개 → 랭킹 전체보기에서 같은 순위가 이어짐 → B의 추천 블로그에 B 자신과 이미 구독한 블로그가 없음.

**수용 시나리오**:

1. **전제** 회원 B와 볼 수 있는 글, **행동** 저장을 누르고 다시 누른다, **결과** 저장됐다가 해제된다. 연달아 눌러도 한 번으로 처리된다. 비회원에게는 로그인 안내가 보인다.
2. **전제** B가 저장한 글들, **행동** 마이페이지 "저장한 글"을 연다, **결과** 저장한 순서의 최신순으로 20개씩 더보기로 보이고, 본인 외에는 이 목록을 볼 수 없다. 각 항목에서 바로 저장 취소를 할 수 있다.
3. **전제** B가 저장한 뒤 비공개·숨김·삭제·구독 해제 등으로 B가 볼 수 없게 된 글, **행동** 저장한 글 목록을 연다, **결과** 그 글은 목록에 남고 **저장할 때의 제목과 블로그 이름**이 "볼 수 없는 글" 표시와 함께 보인다. 누르면 글로 가지 않고 "더 이상 볼 수 없는 글입니다" 안내가 나오며, 이유(삭제인지 비공개인지)는 알려 주지 않는다. 같은 글을 주소로 직접 열면 404다.
4. **전제** 3의 글이 다시 볼 수 있게 됨, **행동** 목록을 연다, **결과** 지금 제목으로 정상 표시되고 누르면 글이 열린다.
5. **전제** 여러 블로그의 최근 7일 활동, **행동** 홈을 연다, **결과** 인기 블로거 상위 5개가 보인다. 공개 글이 없거나, 삭제·이용 제한된 블로그, 주인이 정지·탈퇴한 블로그는 빠진다. 순위는 1시간마다 바뀐다.
6. **전제** 회원 B, **행동** 구독 피드를 연다(구독한 블로그가 없을 때 포함), **결과** 추천 블로그 5개가 보이고 B 자신의 블로그와 이미 구독한 블로그는 없다.
7. **전제** 홈의 인기 글·인기 블로거, **행동** 랭킹 전체보기를 연다, **결과** 홈과 같은 기준·같은 시점의 순위가 인기 글·인기 블로거 탭으로 100위까지 20개씩 더보기로 이어진다. 기준 시각이 표시되고, 더보기 중에 순위가 갱신되면 갱신 안내와 함께 처음부터 다시 보인다(중복·누락 없음).

### 예외 상황 (Edge Cases)

- 마지막 페이지를 넘는 페이지를 요청하면 오류가 아니라 빈 목록이다. 음수 페이지는 첫 페이지로 본다. (원본 4.4)
- 발행 시각이 같은 글은 나중에 만든 글이 위에 온다. 임시저장 후 나중에 발행한 글은 발행 시각 기준으로 놓인다. (원본 4.4)
- 더보기 목록(홈 최신 글, 구독 피드)에서 중간에 새 글이 생겨도 중복·누락이 없다. (원본 4.4)
- 미분류 글이 없으면 사이드바에서 '미분류'를 숨긴다. (채움)
- 소셜로 먼저 가입한 사람이 같은 이메일로 이메일 가입을 하면 별도 회원이 된다. 정리는 사용자가 한다. (원본 4.6)
- 삭제된 블로그를 쓰고 다시 개설을 반복해 주소를 선점하는 것은 우선 허용한다. (원본 4.2 ⑧)

## 요구사항 (Requirements) *(필수)*

### 권한 (원본 4.1)

저장되는 역할은 **일반 회원(USER)**과 **서비스 관리자(ADMIN)** 두 가지뿐이다. **비회원**과 **블로그 주인**은 요청마다 판단하는 상태다. 가입하면 항상 일반 회원이고, 서비스 관리자는 화면이나 API로 될 수 없다.

| 행동 | 비회원 | 회원 | 블로그 주인 | 서비스 관리자 |
| --- | --- | --- | --- | --- |
| 공개 글 읽기, 홈·검색 | ○ | ○ | ○ | ○ |
| 구독자 공개 글 읽기 | ✕ | 구독자만 | 자기 것 | ✕ (숨김 처리는 가능) |
| 비공개 글 읽기 | ✕ | ✕ | 자기 것 | ✕ (숨김 처리는 가능) |
| 댓글 쓰기, 공감, 구독 | ✕ | ○ | ○ | ○ |
| 댓글 수정 | ✕ | 자기 것 | 자기 것 | 자기 것 |
| 댓글 삭제 | ✕ | 자기 것 | 자기 블로그의 모든 댓글 | 숨김만 |
| 블로그 개설 | ✕ | ○ (활성 5개까지) | ○ | ○ |
| 글쓰기, 카테고리·태그·블로그 설정, 블로그 관리 | ✕ | ✕ | 자기 블로그 | 자기 블로그 |
| 서비스 관리 | ✕ | ✕ | ✕ | ○ |

**볼 수 없는 글**: 아래 중 하나에 해당하면 보는 사람에게 "볼 수 없는 글"이다. 이 정의는 아래 모든 요구사항에 똑같이 쓴다.

1. 없거나 삭제된 글
2. 남의 비공개 글
3. 구독하지 않은 사람에게 구독자 공개 글
4. 관리자가 숨긴 글 (작성자 본인 제외)
5. 이용 제한된 블로그, 삭제된 블로그, 정지 회원의 블로그에 속한 글 (주인 본인 제외)

| 상황 | 결과 |
| --- | --- |
| 볼 수 없는 글·블로그를 주소로 염 (로그인 여부와 상관없이) | 404 |
| 예외: 구독하지 않은 사람이 구독자 공개 글을 주소로 염 | 404 대신 "구독자 공개 글입니다" 안내와 구독 버튼 (제목·본문은 숨김). 목록·개수에서는 그대로 빠짐 |
| 볼 수 없는 글 | 모든 목록, 글 수, 검색, 홈, 인기 글, 주제별 글, 피드, 사이드바(그 글의 댓글 포함), 이전·다음 글, 추천에서 빠짐 |
| 비회원이 로그인이 필요한 행동·화면 (글쓰기, 관리, 댓글, 공감, 구독) | 401. 화면은 로그인 안내 → 로그인 후 원래 화면 |
| 로그인했지만 권한 없음 (남의 블로그 관리, 남의 글 수정, 관리자 영역) | 403 |
| 정지 회원의 로그인 | 막고 사유와 기한을 알림 |
| 탈퇴 회원의 로그인 | 없는 계정으로 취급 |

### 공통 규칙 (원본 4장)

#### 블로그 주소·이사·삭제 (원본 4.2)

- 주소는 영문 소문자·숫자·하이픈, 4~32자, 하이픈으로 시작·끝 불가. 예약어(www, api, admin, static, mail, login 등)는 거절한다.
- 주소는 개설 후 바꿀 수 없다. 블로그를 삭제해도 그 주소는 영구히 다시 쓸 수 없다.
- 플랫폼 주소(`blog.com`, `www.blog.com`)는 홈·로그인·회원가입·서비스 관리 화면이고, `{주소}.blog.com`은 그 블로그의 모든 화면(관리 화면, 글쓰기 포함)이다.
- 이사·삭제 결과는 아래 표를 따른다.

| 요청 | 결과 |
| --- | --- |
| `old.blog.com` (이사함, 삭제 여부 무관) | 새 블로그 홈으로 301 |
| `old.blog.com/15` (15번 글을 새 블로그로 옮김) | 글이 지금 속한 `new.blog.com/15`로 301 |
| `old.blog.com/16` (옮기지 않은 글, 옛 블로그 삭제됨) | 404 |
| 삭제된 블로그의 주소로 새 블로그 개설 | 거절 |

#### 글 주소 (원본 4.3)

- 글 주소는 `{주소}.blog.com/{글 번호}`이고, 글 번호는 플랫폼 전체에서 하나다. 처음 발행할 때 정해지고 수정해도 바뀌지 않는다.
- 글이 요청한 블로그 소속이 아니면, 볼 수 있는 글이면 지금 소속 블로그 주소로 301, 아니면 404다.

#### 목록과 페이지 (원본 4.4)

| 목록 | 방식 | 한 번에 | 정렬 |
| --- | --- | --- | --- |
| 블로그 메인 글 목록 (카테고리별·태그별 포함) | 페이지 번호 | 10 | 최신순 |
| 블로그 내 검색 결과 | 페이지 번호 | 10 | 최신순 |
| 홈 최신 글, 구독 피드 | 더보기 | 20 | 최신순 |
| 내 글 관리 | 페이지 번호 | 20 | 최신순 |
| 댓글 | 더보기 | 20 (답글은 부모에 포함) | 작성순 |
| 방명록 | 페이지 번호 | 20 | 최신순 |
| 인기 글 | 없음 | 상위 10 | 인기순 |
| 주제별 글 | 없음 | 6 | 인기순 |
| 사이드바 최근 글·최근 댓글 | 없음 | 각 5 | 최신순 |
| 카테고리·태그 목록 | 없음 | 전체 | 카테고리는 정한 순서, 태그는 글 수순 |

- '최신순'은 처음 발행한 시각 내림차순, 같으면 나중에 만든 글이 위다. 글을 수정해도 순서는 그대로다.
- 페이지 번호는 10개씩 묶어 보여 주고 이전·다음 버튼을 둔다.
- 한 번에 받는 개수는 1~50만 허용한다.
- 목록과 글 수는 보는 사람이 볼 수 있는 글만 센다.

#### 보안 (원본 4.5)

- 비밀번호는 복원할 수 없는 형태로만 저장한다.
- 글 본문에는 허용한 서식(문단 제목, 굵게·기울임, 목록, 인용, 코드 블록, 링크(http/https만), 직접 올린 이미지)만 남는다. 스크립트, 이벤트 속성, 인라인 스타일은 저장되지도 실행되지도 않는다. 화면을 거치지 않고 요청을 직접 보내도 같다.
- 본문 외 입력(제목, 댓글, 블로그 이름·소개, 닉네임)은 글자 그대로만 보인다.
- 다른 사이트가 로그인한 사용자 대신 행동할 수 없다.

#### 계정과 소셜 연동 (원본 4.6)

- 처음 가입한 방식이 그 회원의 기본 로그인 수단이다. 로그인 수단을 더하는 길은 "로그인한 상태에서 마이페이지에서 소셜 연동" 하나뿐이고, 더할 수 있는 것은 소셜 계정뿐이다. 이메일이 같다는 이유로 회원을 합치지 않는다.

| 상황 | 결과 |
| --- | --- |
| 소셜 로그인, 이미 연결된 소셜 계정 | 연결된 회원으로 로그인 (정지·탈퇴 확인 후) |
| 소셜 로그인, 처음 보는 소셜 계정 | 닉네임 확인 후 새 회원. 제공사 이메일은 저장하지 않고 기존 회원과 비교하지 않는다 |
| 이메일 가입, 같은 사람이 이미 소셜로 가입함 | 별도 회원으로 가입된다 |
| 마이페이지 연동, 처음 보는 소셜 계정 | 연동 |
| 마이페이지 연동, 이미 다른 회원에 연결된 소셜 계정 | 거절. "이미 다른 계정에 연결된 소셜 계정입니다" |
| 마이페이지 연동, 같은 제공사가 이미 연결됨 | 거절 (제공사당 하나) |
| 연동 해제 후 로그인 수단이 하나도 남지 않음 | 거절 |
| 탈퇴 | 로그인 수단을 모두 지우고 소셜 연동도 끊는다. 회원 기록은 남기고, 블로그·글·댓글은 모두 삭제(소프트)한다 |

- 소셜 로그인 후에는 로그인 전에 보던 주소로 돌아가되, 우리 서비스 주소만 허용한다.

### 기능 요구사항 (Functional Requirements)

모든 기능은 위 권한과 공통 규칙을 따른다. 각 줄은 `기능 코드 기능 이름 · 등급: 지켜야 할 동작`이다.

#### AUTH 회원·인증 (원본 5.1)

- **AUTH-01 가입·로그인 · P0**: 이메일, 비밀번호, 닉네임으로 가입한다. 이메일 인증(OWN-01)을 마쳐야 회원이 만들어진다. 이메일·닉네임은 중복을 확인하고, 비밀번호는 8자 이상 영문+숫자이고, 72바이트를 넘으면 받지 않는다(영문·숫자 72자, 한글은 24자까지). 이메일 중복은 이메일로 가입한 회원끼리만 본다. 로그인 실패는 "이메일 또는 비밀번호가 맞지 않습니다"로 통일한다. 카카오·구글 소셜 로그인은 P1로 이어 붙이며 규칙은 계정과 소셜 연동을 따른다.
- **AUTH-02 로그아웃 · P0**: 로그아웃하면 모든 블로그 주소에서 비회원 상태가 된다.
- **AUTH-03 로그인 상태 유지 · P1**: 로그인 유지를 고르면 브라우저를 닫았다 열어도 로그인이 유지된다(14일). 고르지 않으면 브라우저를 닫거나 30분 동안 아무 요청이 없으면 로그아웃된다(활동하는 동안에는 계속 연장, 2026-10-08 지원 결정). 플랫폼 주소에서 로그인하면 블로그 주소(`{주소}.blog.com`)에서도 로그인 상태다.
- **AUTH-04 첫 로그인 후 블로그 개설 안내 · P1**: 블로그가 없는 회원이 글쓰기를 누르면 블로그 개설로, 블로그가 있으면 대표 블로그의 글쓰기로 간다.
- **AUTH-05 회원정보 수정 · P1**: 닉네임, 프로필 사진, 비밀번호를 바꾼다.
- **AUTH-06 회원 탈퇴 · P2**: 본인 확인(비밀번호 또는 소셜 재인증)과 한 번 더 확인을 거쳐 탈퇴한다. 탈퇴 후 처리는 계정과 소셜 연동 표를 따른다. 그 회원의 블로그·글·댓글은 모두 삭제(소프트)하고, 블로그 주소는 영구히 다시 쓸 수 없다. 답글이 달린 댓글은 '삭제된 댓글입니다'로 남는다. 그 회원이 누른 공감과 구독도 사라져 수치가 실제와 맞는다.

#### BLOG 블로그 (원본 5.2)

- **BLOG-01 블로그 개설 · P0**: 주소와 이름을 따로 입력한다. 주소 규칙은 공통 규칙을 따르고, 개설 화면에서 주소를 바꿀 수 없다고 안내한다. 활성 블로그 6번째는 거절한다. 처음 만든 블로그가 대표 블로그다.
- **BLOG-02 블로그 정보 수정 · P0**: 블로그 이름(1~50자), 소개글, 프로필 이미지를 바꾼다.
- **BLOG-03 블로그 메인 · P0**: 프로필, 카테고리 목록, 최신 글 목록(10개씩 페이지), 태그 목록을 보여 준다. 글이 없으면 빈 상태를 보여 준다.
- **BLOG-04 사이드바 · P0**: 기본 구성은 위에서부터 ① 블로그 홈 바로가기(이름·소개) ② 카테고리 트리와 글 수 ③ 태그 목록(TAG-03 이후) ④ 최근 글 5개 ⑤ 최근 댓글 5개. 한 블로그의 모든 화면에 같은 사이드바가 보이고, 주인이 BLOG-05에서 바꾼 순서와 표시 여부를 따른다. 볼 수 없는 글과 그 글의 댓글은 빠진다. 하위 카테고리(CAT-03)가 생기기 전에는 한 단계로 보인다.
- **BLOG-05 블로그 꾸미기 · P2**: 미리 만든 스킨 2~3종과 메인 글 목록 형태(리스트/썸네일)를 고른다. 스킨의 포인트 색을 정해 둔 6색(파랑, 초록, 주황, 분홍, 보라, 회색) 중에서 고른다(기본 파랑). 사이드바 모듈의 순서를 바꾸고 모듈마다 보이기·숨기기를 고른다. 모듈은 정해진 8종(블로그 홈 바로가기, 카테고리, 태그, 최근 글, 최근 댓글, 방문자 수, 인기 글, 구독)뿐이고 블로그마다 한 번씩만 있다. 방문자 수는 오늘·어제·누적, 인기 글은 누적 조회수 상위 5개, 구독은 구독 버튼과 구독자 수다. 새 블로그에서 방문자 수·인기 글·구독은 숨김 상태로 시작한다. 블로그 홈 바로가기는 숨길 수 없고, 모듈마다 개수(최근 글 5개 등)는 바꿀 수 없다. HTML·CSS 직접 편집은 하지 않는다.
- **BLOG-06 블로그 이사 · P2**: 글을 골라 같은 회원의 다른 활성 블로그로 옮긴다. 옮긴 글의 카테고리는 '미분류', 태그는 이름으로 대상 블로그 태그에 다시 연결한다. 옛 블로그에 이사 대상을 정하면 방문자는 새 블로그로 301되고 주인은 옛 블로그 관리 화면에 계속 들어간다. 자기 자신이나 삭제된 블로그는 대상이 될 수 없다. 연쇄 이사는 한 번에 최종 블로그로 가고 순환은 생기지 않는다. 이사 간 새 블로그를 삭제하면 옛 블로그도 없는 블로그가 된다.
- **BLOG-07 블로그 삭제 · P2**: "옮기지 않은 글 N개가 함께 삭제됩니다" 경고와 확인을 거쳐 삭제한다. 주소는 영구히 다시 쓸 수 없고 이사 연결은 유지된다. 대표 블로그는 대표를 바꾼 뒤에만 삭제된다.
- **BLOG-08 대표 블로그 지정 · P2**: 대표 블로그를 바꾼다. '내 블로그' 바로가기와 댓글 작성자 닉네임 링크는 대표 블로그로 간다.

#### POST 글 (원본 5.3)

- **POST-01 글 작성·발행 · P0**: 제목(1~200자, 비면 발행 불가), 주제, WYSIWYG 본문, 카테고리(하나, 기본 '미분류'), 태그(최대 10개), 공개 범위를 정해 발행한다. 발행한 시각이 처음 발행 시각이다. 버튼을 연달아 눌러도 글은 하나다. 본문 에디터는 하나이고, 서식 버튼과 마크다운 문법을 섞어 쓴다. 같은 에디터에서 `## 제목`, `**굵게**`, `- 목록`, `[글자](주소)` 같은 문법을 치거나 마크다운 글을 붙여넣으면 바로 서식으로 바뀐다(2026-10-08 지원 결정).
- **POST-02 글 수정 · P0**: 블로그 주인만 수정한다. 주소, 처음 발행 시각, 목록 순서는 그대로이고 수정 시각이 따로 남는다.
- **POST-03 글 삭제 · P0**: 블로그 주인만 확인 창을 거쳐 삭제한다. 삭제 후 그 주소는 404다. 그 글의 댓글·공감·알림도 함께 사라진다(채움). 삭제는 소프트 삭제다(기록은 남고 사용자에게만 사라짐). 블로그 글 수·공감 수 같은 수치에서도 바로 빠진다.
- **POST-04 글 상세 조회 · P0**: 제목, 작성일, 카테고리, 본문, 태그, 공감 수, 댓글, 이전·다음 글을 보여 준다. 볼 수 없는 글이면 404이고, 주인은 공개 범위와 상관없이 본문을 본다. 판단 순서는 [데이터 모델](./data-model.md)의 글 가시성 판단을 따른다.
- **POST-05 본문 이미지 넣기 · P0**: jpg/png/gif/webp, 파일당 10MB 이하를 쓰는 위치에 넣는다. 그 밖은 이유와 함께 거절하고 본문은 그대로다. 목록에는 작게 줄인 이미지(썸네일)를 쓴다.
- **POST-06 공개·비공개 설정 · P0**: 공개 / 비공개 / 구독자 공개 중 하나이고 발행 후에도 바꾼다. 구독자 공개는 구독(SUB-01)이 생긴 뒤에 고를 수 있다. 그 전에는 공개·비공개만 있다.
- **POST-07 대표 이미지 · P1**: 본문 이미지 중 고른다. 고르지 않으면 본문 첫 이미지가 대표다.
- **POST-08 임시저장 · P1**: 수동 저장과 1분 간격 자동 저장, 임시저장 목록에서 불러오기. 주인에게만 보인다.
- **POST-09 조회수 · P1**: 글을 열면 조회수가 오른다. 같은 사용자가 5분 안에 다시 열면 1회만 센다. 최근 1시간 조회수를 셀 수 있게 조회마다 시각을 남긴다.
- **POST-10 이전·다음 글 · P1**: 같은 블로그 안 발행 순서 기준이고, 볼 수 없는 글은 건너뛴다.
- **POST-11 주제 지정 · P1**: IT·개발, 여행, 맛집·요리, 일상, 리뷰, 취미, 경제·재테크, 건강·운동, 문화·연예, 교육·학습 중 하나. 고르지 않으면 '주제 없음'이다. 주제는 카테고리와 별개다.
- **POST-12 확장 공개 범위 · P2**: 구독자 공개 글은 그 블로그를 구독한 회원과 블로그 주인만 본문을 본다. 구독하지 않은 사람에게는 블로그 목록·검색·홈·인기 글·피드·글 수에서 빠진다. 링크로 직접 열면 404 대신 "구독자 공개 글입니다" 안내와 구독 버튼을 보여 주고 제목·본문은 숨긴다.
- **POST-13 예약 발행 · P2**: 정한 날짜·시각에 공개로 바뀌고, 그 시각이 처음 발행 시각이다.

글 상태: 임시저장 → (공개 · 비공개 · 구독자 공개) 중 하나로 발행. 예약 발행은 정한 시각에 공개로 바뀐다.

#### CAT 카테고리 (원본 5.4)

- **CAT-01 카테고리 추가·이름 변경·삭제 · P0**: 이름은 1~30자. 삭제하면 소속 글은 '미분류'로 옮겨진다.
- **CAT-02 카테고리별 글 목록 · P0**: `{주소}.blog.com/category/{카테고리 번호}`. 상위를 누르면 하위 글도 함께 보이고 글 수를 표시한다.
- **CAT-03 하위 카테고리 · P1**: 상위/하위 2단계.
- **CAT-04 카테고리 순서 변경 · P1**: 드래그 앤 드롭으로 순서와 상하위 관계를 바꾼다.
- **CAT-05 카테고리 비공개 · P2**: 카테고리 단위로 비공개한다.

#### TAG 태그 (원본 5.5)

- **TAG-01 글에 태그 달기 · P0**: 작성·수정 시 최대 10개. 없는 이름은 블로그 태그에 자동 추가된다. 이름은 30자까지이고 `/`는 쓸 수 없다(태그 목록 주소 `/tag/{이름}`이 깨지므로, 2026-10-09 지원 결정). 대소문자·악센트만 다른 이름은 같은 태그다.
- **TAG-02 태그별 글 목록 · P0**: `{주소}.blog.com/tag/{이름}`.
- **TAG-03 태그 목록 · P1**: 블로그 태그와 글 수를 보여 준다. 태그 클라우드는 P2.
- **TAG-04 태그 관리 · P2**: 이름 변경·삭제. 블로그 안 이름 중복 불가, 삭제해도 글은 남는다.

#### CMT 댓글·방명록 (원본 5.6)

- **CMT-01 댓글 쓰기·삭제 · P0**: 회원이 댓글을 쓰고(1~1,000자, 채움) 자기 댓글을 지운다. 연달아 눌러도 댓글은 하나다.
- **CMT-02 블로그 주인의 댓글 삭제 · P0**: 주인은 자기 블로그의 모든 댓글을 지운다.
- **CMT-03 댓글 수정 · P1**: 본인만.
- **CMT-04 방명록 · P1**: 블로그 단위 게시판형 글. 댓글과 같은 규칙(비밀·답글)을 따른다.
- **CMT-05 답글 · P2**: 한 단계. 부모를 지우면 '삭제된 댓글입니다'로 표시하고 답글은 남긴다. 2주차에 앞당겨 만든다.
- **CMT-06 비밀댓글 · P2**: 글 주인과 작성자만 본다.
- **CMT-07 댓글 허용 설정 · P2**: 글 단위로 허용/차단한다.

#### SOC 반응 (원본 5.7)

- **SOC-01 공감 · P0**: 회원만, 글당 1회, 다시 누르면 취소. 공감 수를 보여 준다. 연달아 눌러도 한 번으로 센다.
- **SOC-02 공유 · P1**: 글 주소 복사, SNS 공유 버튼.
- **SOC-03 저장 · P2**: 회원만, 글당 1회, 다시 누르면 취소. 연달아 눌러도 한 번으로 처리한다. 마이페이지 "저장한 글"에서 본인만 저장한 순서의 최신순으로 20개씩 더보기로 보고, 각 항목에서 저장을 취소한다. 저장 후 볼 수 없게 된 글(삭제 포함)은 목록에 남아 저장할 때의 제목·블로그 이름과 "볼 수 없는 글" 표시가 보이고, 누르면 "더 이상 볼 수 없는 글입니다" 안내만 나온다(헌법 원칙 II 예외). 저장 수는 보여 주지 않는다. 탈퇴하면 그 회원의 저장은 사라진다(2026-10-08 지원 결정).

#### SUB 구독·피드·알림 (원본 5.8)

- **SUB-01 블로그 구독·해제 · P1**: 구독과 구독 취소. 연달아 눌러도 한 번으로 센다.
- **SUB-02 구독 피드 · P1**: 구독한 블로그의 새 글 최신순, 더보기 20개.
- **SUB-03 구독자 수 · P1**: 블로그에 구독자 수를 보여 준다.
- **SUB-04 알림 · P2**: 내 글에 댓글·답글·공감, 새 구독자, 제재·해제 시 알림. 읽음 처리.
- **SUB-05 맞구독 · 제외**: 넣지 않는다(2026-10-08 지원 결정). 번호는 다시 쓰지 않는다.
- **SUB-06 추천 블로그 · P2**: 인기 블로거(HOME-04) 순위에서 자기 블로그와 이미 구독한 블로그를 뺀 상위 5개를 구독 피드 화면에 보여 준다. 구독한 블로그가 없을 때도 보인다. 비회원에게는 인기 블로거와 같은 목록이다.

#### SRCH 검색 (원본 5.9)

- **SRCH-01 블로그 내 검색 · P0**: 제목+본문+태그 키워드 검색, 10개씩 페이지.
- **SRCH-02 전체 검색 · P1**: 플랫폼 전체에서 글·블로그를 검색한다.

#### HOME 홈·탐색 (원본 5.10)

- **HOME-01 홈 최신 글 · P0**: 모든 블로그의 공개 글 최신순, 더보기 20개, 중복·누락 없음.
- **HOME-02 인기 글 · P1**: 인기 점수(최근 1시간의 조회 수×1 + 공감 수×3 + 댓글 수×5) 순 공개 글 상위 10개, 5분마다 갱신. 가중치는 Claude가 정한 기본값이다([지원이 확인할 것](./review.md) B).
- **HOME-03 주제별 글 · P1**: 주제 탭을 고르면 그 주제의 글 6개를 HOME-02와 같은 인기 점수 순으로 보여 준다. 6개가 안 되면 그 주제의 최신 글로 채운다.
- **HOME-04 인기 블로거 · P2**: 블로그 점수(최근 7일 동안 그 블로그의 볼 수 있는 글이 받은 조회 수×1 + 공감 수×3 + 댓글 수×5 + 새 구독자 수×10) 순 상위 5개를 홈에 보여 준다. 1시간마다 갱신한다. 공개 글이 없는 블로그, 삭제·이용 제한된 블로그, 주인이 정지·탈퇴한 블로그는 빠진다. 기간·구독자 가중치·갱신 주기는 Claude가 정한 기본값이다([지원이 확인할 것](./review.md) B).
- **HOME-05 랭킹 전체보기 · P2**: 인기 글(HOME-02)·인기 블로거(HOME-04) 탭으로 각 100위까지, 20개씩 더보기. 홈과 같은 기준·같은 시점의 순위이고 기준 시각을 표시한다. 더보기 중에 순위가 갱신되면 안내하고 처음부터 다시 보여 준다.

#### MNG 블로그 관리 (원본 5.11)

블로그 관리 화면은 `{주소}.blog.com/manage/...`이고 블로그 주인만 들어간다.

- **MNG-01 내 글 관리 · P1**: 상태·카테고리 필터, 검색, 공개 범위 일괄 변경·삭제. 20개씩 페이지.
- **MNG-02 댓글 관리 · P1**: 받은 댓글·방명록 목록, 삭제, 답글 바로 쓰기.
- **MNG-03 방문자 수·통계 · P2**: 관리 홈에 오늘/어제/누적 방문자, 최근 댓글·글 요약. 일·주·월별 방문자 그래프, 인기 글 순위(누적·최근 7일), 유입 경로(검색·SNS·직접·블로그 안·기타와 사이트별). 방문자는 블로그·날짜마다 한 사람을 한 번 세고, 블로그 주인 본인의 방문은 세지 않는다. 어제까지의 통계는 매일 새벽에 모은다. 주인 제외와 집계 방식은 Claude가 정한 기본값이다([지원이 확인할 것](./review.md) B).
- **MNG-04 스팸·차단 · P2**: 블로그 주인이 회원을 차단하고 금칙어를 정한다. 차단된 회원은 그 블로그에 댓글·방명록을 쓸 수 없고 구독할 수 없으며, 차단하면 기존 구독도 지워진다. 차단 사실은 따로 알리지 않는다. 금칙어는 블로그당 100개까지, 댓글·방명록을 새로 쓸 때 대소문자를 무시하고 검사한다. 이미 있던 댓글은 그대로 두고 주인이 MNG-02에서 지운다. 개수 한도와 차단 시 구독 삭제는 Claude가 정한 기본값이다([지원이 확인할 것](./review.md) B). IP 차단은 하지 않는다(댓글은 회원만 쓰므로, 2026-10-08 지원 결정).

#### ADMIN 서비스 관리 (원본 5.12)

서비스 관리 화면은 `blog.com/admin`이고 서비스 관리자만 들어간다. 관리자는 남의 내용을 고치거나 지우지 않고 숨기거나 제한만 하며, 모든 제재에는 사유를 남긴다(채움, 헌법 원칙 V). 사유는 신고 사유와 같은 목록(스팸·광고, 음란·유해, 욕설·비방, 저작권 침해, 기타)에서 고르고, 기타면 설명을 쓴다. 제재받은 사람에게는 사유별로 정해 둔 안내 문구를 보여 준다(2026-10-08 지원 결정).

- **ADMIN-01 관리자 역할과 전용 영역 · P0**: 서비스 관리자는 미리 넣어 둔 데이터로만 정한다. 서비스 관리 화면과 API는 서비스 관리자만 쓴다.
- **ADMIN-02 회원 이용 제한 · P1**: 회원 조회(이메일·닉네임 검색, 상태 필터, 상세에서 가입일·보유 블로그·받은 신고 수·제재 이력). 정지 기간 7일/30일/영구와 사유. 기간이 끝나면 자동 해제. 정지 중에는 그 회원의 모든 블로그를 숨긴다. 이미 로그인한 정지 회원은 다음 요청부터 막는다.
- **ADMIN-03 게시물 숨김 · P1**: 글·댓글 블라인드. 작성자에게 사유를 보여 주고, 홈·검색·목록에서 빼며, 작성자는 수정할 수 없고 삭제는 할 수 있다. 다른 사람에게 숨긴 글은 404, 숨긴 댓글은 '관리자가 숨긴 댓글'로 보인다.
- **ADMIN-04 신고 · P2**: 사유(스팸·광고, 음란·유해, 욕설·비방, 저작권 침해, 기타(설명 필수)). 처리 대기 신고를 대상별로 묶어 신고 수 많은 순. 결과는 블라인드, 블로그 이용 제한, 작성자 정지, 기각 중 선택. 처리하면 그 대상의 신고가 모두 처리 완료가 되고 관리 이력에 남는다.
- **ADMIN-05 블로그 이용 제한 · P2**: 회원은 두고 특정 블로그만 숨긴다. 다른 사람에게는 없는 블로그(404), 주인은 관리 화면에서 사유를 본다.
- **ADMIN-06 공지·관리 이력·대시보드 · P2**: 공지는 플랫폼 홈 상단에 최신 1개와 목록 페이지. 관리 이력은 조회만 되고 대상·관리자·기간으로 검색한다. 대시보드에 오늘 가입자 수, 새 글 수, 처리 대기 신고 수, 최근 제재 이력.

#### COM 공통 (원본 5.13)

- **COM-01 접근 제어 · P0**: 모든 행동이 권한 표와 결과 표를 따른다. 주소 직접 입력과 직접 요청에도 같은 결과다.
- **COM-02 오류 처리 · P0**: 404·403 화면, 입력 오류는 어느 항목이 잘못됐는지 안내하고 입력을 유지한다. 예상하지 못한 오류에도 내부 정보를 드러내지 않는다.

#### OWN 자체 기능 (원본 5.14)

- **OWN-01 이메일 인증 · P1**: 가입할 때 이메일로 인증 코드를 보내고, 코드를 확인해야만 회원이 만들어진다. 가입(AUTH-01, P0)에 꼭 필요해서 1주차에 함께 만든다.
- **OWN-02 비밀번호 재설정 · P1**: 이메일로 재설정 링크를 보내고, 링크는 30분 동안 유효하다.
- **OWN-03 소셜 계정 연동·해제 · P1**: 로그인한 회원이 마이페이지에서 카카오·구글 계정을 제공사당 하나씩 연동·해제한다. 규칙은 계정과 소셜 연동 표를 따른다. 연동 화면에 "다른 소셜 계정도 연결해 두면 로그인 수단을 잃었을 때 대비할 수 있어요"를 보여 준다. 소셜로 가입한 회원에게 이메일 로그인을 추가하는 기능은 없다.
- **OWN-04 비회원 댓글 · 제외**: 넣지 않는다(2026-10-07 지원 결정). 댓글은 회원만 쓴다. 번호는 다시 쓰지 않는다.
- **OWN-05 같은 카테고리의 다른 글 · P2**: 글 상세 아래에 같은 카테고리 글 목록.
- **OWN-06 비슷한 글 추천 · P2**: 글 상세 아래에 내용이 비슷한 글을 추천한다. 2주 안에 도전한다.

### 비기능 요구사항 (원본 4.5)

- **반응형**: 휴대폰 화면(360px)부터 데스크톱까지 가로 스크롤 없이 쓴다.
- **공유 미리보기**: 글 주소를 공유하면 제목·요약·대표 이미지가 미리보기로 보인다.
- **성능**: 목록은 페이지 단위로 불러오고, 목록에는 작은 이미지를 쓰며, 홈의 무거운 섹션(인기 글, 주제별 글)은 5분 동안 같은 결과를 다시 쓴다.
- **신뢰성**: 발행·댓글·공감·구독은 같은 요청이 두 번 와도 한 번만 처리한다. 공감 수, 댓글 수, 구독자 수, 글 수는 새로고침하면 실제 값과 같다.
- **시간**: 날짜·시각은 한국 시간이다(채움).

### 핵심 개체 (Key Entities)

- **회원**: 이메일(이메일 가입만), 닉네임, 프로필 사진, 역할(일반 / 서비스 관리자), 상태(활동 / 정지 / 탈퇴), 정지 기한. 정지 사유는 제재 기록에 있다.
- **소셜 계정**: 회원에 연결된 카카오·구글 계정. 회원당 제공사마다 하나, 소셜 계정 하나는 회원 하나에만.
- **블로그**: 주소(불변, 영구 예약), 이름, 소개, 프로필 이미지, 스킨·포인트 색·목록 형태, 사이드바 모듈 순서·표시 여부, 주인, 대표 여부, 이사 대상, 이용 제한 상태, 삭제 여부.
- **글**: 소속 블로그, 번호(플랫폼 전체에서 하나), 제목, 본문, 요약, 처음 발행 시각, 수정 시각, 공개 범위, 상태(임시저장 / 발행 / 예약), 카테고리, 태그(0~10), 주제, 대표 이미지, 조회수, 숨김 상태, 댓글 허용 여부.
- **조회 기록**: 누가 언제 어떤 글을 열었는지. 인기 점수와 중복 조회 판정에 쓴다.
- **카테고리**: 소속 블로그, 이름, 상위 카테고리(2단계까지), 순서, 공개 여부. '미분류'는 고정.
- **태그**: 소속 블로그, 이름. 글과 다대다.
- **댓글 / 방명록**: 글 또는 블로그, 작성자, 내용, 작성 시각, 부모 댓글(한 단계), 비밀 여부, 삭제 표시, 숨김 상태.
- **공감 / 구독**: 회원-글, 회원-블로그 쌍마다 하나.
- **저장**: 회원-글 쌍마다 하나. 저장 시각, 저장할 때의 글 제목·블로그 이름.
- **순위 스냅숏**: 인기 글·인기 블로거 순위와 계산 시각. 홈과 랭킹 전체보기가 같은 스냅숏을 본다.
- **이미지**: 저장 위치, 원본 파일명, 크기, 썸네일.
- **방문 기록·방문 통계**: 블로그·날짜·방문자마다 하나인 방문 기록(7일 보관)과, 매일 모은 일별 방문자 수·유입 경로.
- **차단 회원 / 금칙어**: 블로그마다 주인이 정한 차단 회원과 금칙어.
- **제재 기록**: 관리자의 모든 조치와 사유. 숨김·정지·이용 제한의 사유는 여기에만 있다.
- **알림, 신고, 공지**: 확장 기능의 개체.

## 성공 기준 (Success Criteria) *(필수)*

- **SC-001**: 2주 안에 P0 24개만으로 유저 스토리 1~4를 막힘 없이 끝낼 수 있다.
- **SC-002**: 볼 수 없는 글·블로그에 대한 모든 직접 접근이 404이고, 어떤 목록·글 수에도 나오지 않는다. 예외는 구독자 공개 글 안내(Q4)와 본인 저장 목록의 "볼 수 없는 글" 항목(SOC-03)뿐이며, 저장 목록에서도 저장 시점 이후의 정보는 드러나지 않는다.
- **SC-003**: 권한 표의 모든 ✕ 칸을 직접 요청으로 시도하면 401, 403, 404 중 결과 표대로 막힌다.
- **SC-004**: 발행·댓글·공감·구독을 빠르게 연속 요청해도 중복 생성이 0건이다.
- **SC-005**: 글을 수정하거나 옮기거나 블로그를 이사한 뒤에도 이전에 공유한 글 주소가 그 글로 열린다.
- **SC-006**: 사용자 입력 칸 전체에 스크립트를 넣어도 실행되는 곳이 0곳이다.
- **SC-007**: 휴대폰 화면(360px)에서 모든 P0 기능을 가로 스크롤 없이 쓴다.

## 명확화 (Clarifications)

### 확정 사항

원본에서 정했거나, 원본이 기다리던 결정을 원본의 설계대로 확정한 것이다.

- 볼 수 없는 글·블로그는 403이 아니라 404다. 숨긴 글·제한 블로그에도 따로 안내 문구를 쓰지 않는다(원본 9장). 구독자 공개 글을 링크로 연 경우(Q4)와 본인 저장 목록의 볼 수 없는 글(SOC-03, 2026-10-08)만 예외로 안내를 보인다.
- 정지 기간 동안 그 회원의 모든 블로그를 숨긴다(원본 9장).
- 글자 수는 제목 200자, 블로그 이름 50자, 카테고리 이름 30자다(원본 8장).
- 답글(CMT-05, P2)은 2주차에 앞당겨 만든다(원본 9장).
- 연타 방지: 공감·구독은 회원-대상 쌍마다 하나만 저장하고, 발행·댓글은 같은 요청이 두 번 와도 한 번만 처리한다(원본 10장 ④, 2026-10-07 지원 결정).
- 글쓰기 화면은 블로그 주소 아래 관리 화면(`{주소}.blog.com/manage/...`)에 둔다(원본 4.2와 6장이 달라서 6장을 따름, [지원이 확인할 것](./review.md) 2).
- 이메일 인증(OWN-01)은 회원을 만들기 전에 끝나므로 "인증 전 글 발행 제한"은 두지 않는다(원본 4.6과 5.14가 달라서 4.6을 따름, [지원이 확인할 것](./review.md) 1).
