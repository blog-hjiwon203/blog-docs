**Status**: Draft

> 이 문서는 **What**(사용자가 확인할 수 있는 동작)만 다룬다. **How**(스택, 화면, 문구, 수치)는 각자의 `plan.md`에 둔다. 원칙은 [constitution](../../.specify/memory/constitution.md)을 따른다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 가입하고 내 블로그 열기 (Priority: P1)

비회원이 가입·로그인한 뒤 주소와 이름을 정해 자기 블로그를 만들고, 블로그 메인과 사이드바를 확인한다.

**Why this priority**: 블로그가 없으면 다른 어떤 기능도 시작할 수 없다. MVP 한 바퀴의 출발점이다.

**Independent Test**: 새 계정으로 가입 → 블로그 개설 → 블로그 메인에서 빈 상태와 사이드바(블로그 이름, 카테고리 목록)를 확인 → 로그아웃까지 진행한다.

**Acceptance Scenarios**:

1. **Given** 비회원, **When** 가입하고 로그인한다, **Then** 일반 회원이 되고 로그인 전에 보던 화면(없으면 홈)으로 돌아간다.
2. **Given** 블로그가 없는 회원, **When** 주소 `my-blog`와 이름을 입력해 개설한다, **Then** 블로그가 생기고 개설 화면에서 "주소는 나중에 바꿀 수 없다"는 안내를 봤다.
3. **Given** 다른 블로그가 쓰는 주소나 예약어(`admin` 등), 규칙에 어긋난 주소(`-ab`, 3자, 대문자), **When** 개설을 시도한다, **Then** 입력 단계에서 이유와 함께 거절된다.
4. **Given** 글이 없는 새 블로그, **When** 블로그 메인을 연다, **Then** 아직 글이 없다는 빈 상태와, 블로그 이름·프로필·카테고리 목록('전체 글')이 있는 사이드바가 보인다.
5. **Given** 블로그 주인, **When** 블로그 이름·소개·프로필 이미지를 바꾼다, **Then** 바뀐 값이 보이고 주소는 그대로다. 소개가 비면 소개 자리가 숨겨진다.
6. **Given** 로그인한 회원, **When** 로그아웃한다, **Then** 비회원 상태가 되고 글쓰기·관리 화면에 들어갈 수 없다.

### User Story 2 - 글 쓰고 발행·수정·삭제하기 (Priority: P1)

블로그 주인이 제목·본문·이미지를 넣어 글을 쓰고, 카테고리·태그·공개 범위를 정해 발행하고, 수정·삭제한다.

**Why this priority**: 글이 블로그의 핵심 콘텐츠다.

**Independent Test**: 블로그 주인으로 이미지가 든 글을 카테고리·태그와 함께 발행 → 상세 확인 → 수정 후 주소·순서 불변 확인 → 비공개 전환 → 삭제까지 진행한다.

**Acceptance Scenarios**:

1. **Given** 블로그 주인, **When** 제목·본문·카테고리·태그 3개·공개로 발행한다, **Then** 글 상세로 이동하고 공감·댓글·조회수는 0이다.
2. **Given** 제목이 공백뿐이고 본문도 빈 글, **When** 발행한다, **Then** 첫 번째 문제(제목)만 알리고 입력은 그대로 남는다.
3. **Given** 카테고리를 고르지 않은 글, **When** 발행한다, **Then** '미분류'에 들어간다.
4. **Given** 발행 버튼을 빠르게 두 번 누름, **When** 요청이 처리된다, **Then** 글은 하나만 생긴다.
5. **Given** 발행된 글, **When** 제목과 본문을 고친다, **Then** 글 주소, 처음 발행일, 공감·댓글·조회수, 목록 순서는 그대로다.
6. **Given** 이미지 3장을 고름, **When** 본문에 넣는다, **Then** 고른 순서대로 들어간다. 이미지가 아닌 파일은 거절되고 본문은 그대로다.
7. **Given** 공개 글, **When** 비공개로 바꾼다, **Then** 다른 사람에게는 목록·검색·홈·글 개수에서 사라지고 주소로 열면 404다.
8. **Given** 댓글·공감이 달린 글, **When** 확인을 거쳐 삭제한다, **Then** 댓글·공감·저장·알림이 함께 사라지고 그 주소는 404다.
9. **Given** 카테고리 'A'에 글 2개, **When** 'A'를 삭제한다, **Then** 두 글은 '미분류'로 옮겨진다. '전체 글'과 '미분류'는 이름 변경·삭제가 안 된다.
10. **Given** 태그 'java'가 붙은 글, **When** 태그를 누른다, **Then** 같은 블로그에서 'java'가 붙은 글만 보이고 그 목록에도 고유 주소가 있다.

### User Story 3 - 독자가 홈에서 발견하고 읽고 반응하기 (Priority: P1)

다른 회원(또는 비회원)이 홈 최신 글에서 글을 발견해 읽고, 블로그 안에서 검색하고, 회원이면 댓글과 공감을 남긴다.

**Why this priority**: P0 한 바퀴의 끝. 이것이 돌아야 "티스토리 같은 블로그"다.

**Independent Test**: 계정 A가 글 발행 → 비회원으로 홈에서 그 글 발견·열람 → 계정 B로 로그인해 댓글·공감 → A가 B의 댓글 삭제.

**Acceptance Scenarios**:

1. **Given** 여러 블로그의 공개·비공개 글, **When** 비회원이 홈을 연다, **Then** 공개 글만 최신순으로 제목·블로그 이름·발행일·요약과 함께 보인다.
2. **Given** 홈에서 더 불러오기 중 새 글이 올라옴, **When** 다음 묶음을 불러온다, **Then** 같은 글이 두 번 나오거나 빠지지 않는다.
3. **Given** 본문에 `<script>`가 든 글, **When** 글 상세를 연다, **Then** 스크립트는 실행되지 않는다.
4. **Given** 블로그 안 검색창, **When** " Java "를 검색한다, **Then** 앞뒤 공백은 무시되고 대소문자 구분 없이 제목·본문·태그가 일치하는 볼 수 있는 글만 최신순·페이지 단위로 나온다. 결과 주소를 새로고침해도 같다.
5. **Given** 결과가 없는 검색어, **When** 검색한다, **Then** 결과가 없다고 알리고 검색어는 입력창에 남아 있다.
6. **Given** 비회원, **When** 댓글을 쓰거나 공감을 누른다, **Then** 로그인으로 안내되고 로그인 후 원래 글로 돌아온다.
7. **Given** 회원, **When** 댓글을 쓴다, **Then** 닉네임과 작성 날짜·시각이 보이고 댓글은 작성순, 글의 댓글 수가 1 오른다. 등록을 연달아 눌러도 한 번만 올라간다.
8. **Given** 회원, **When** 공감을 누르고 다시 누른다, **Then** 공감 수가 바로 +1, -1 되고 새로고침해도 실제 값과 같다.
9. **Given** 블로그 주인, **When** 자기 글에 달린 남의 댓글을 지운다, **Then** 지워진다. 남의 댓글을 수정할 수는 없다.

### User Story 4 - 접근 제어, 오류, 관리자 전용 영역 (Priority: P1)

누가 무엇을 할 수 있는지가 화면뿐 아니라 직접 요청에서도 지켜지고, 서비스 관리자만 들어가는 영역이 있다.

**Why this priority**: 다른 P1 스토리들의 안전장치다. 이게 없으면 비공개·권한 규칙이 무의미하다.

**Independent Test**: 회원 B로 회원 A의 글 수정 주소·비공개 글 주소·관리자 영역 주소를 직접 입력하고, 비회원으로 글쓰기 주소를 직접 연다.

**Acceptance Scenarios**:

1. **Given** 비회원, **When** 글쓰기 주소를 직접 연다, **Then** 로그인으로 안내되고 로그인 후 그 화면으로 돌아간다.
2. **Given** 회원 B, **When** A 블로그의 관리·수정 주소로 요청을 보낸다, **Then** 403이다.
3. **Given** 회원 B, **When** A의 비공개 글 주소를 연다, **Then** 403이 아니라 404다.
4. **Given** A 블로그 글 번호를 B 블로그 주소에 붙인 주소, **When** 연다, **Then** 404다.
5. **Given** 일반 회원, **When** 서비스 관리 영역 주소를 연다, **Then** 403이다. 서비스 관리자로는 들어가진다.
6. **Given** 예상하지 못한 서버 오류, **When** 화면에 오류가 보인다, **Then** 오류 위치·서버 구성 같은 내부 정보 없이 잠시 후 다시 시도하라는 안내와 돌아갈 길만 보인다.

---

### User Story 5 - 글쓰기와 블로그 정리를 편하게 (Priority: P2)

블로그 주인이 임시저장, 대표 이미지, 하위 카테고리·순서, 태그 목록, 주제 지정, 조회수와 이전·다음 글을 활용한다. 회원은 로그인 유지, 개설 안내, 회원정보 수정을 쓴다.

**Why this priority**: 없어도 한 바퀴는 돌지만, 있어야 실제로 쓸 만하다.

**Independent Test**: 글을 임시저장 → 새 글 쓰기에서 이어쓰기 제안 확인 → 발행 후 임시저장 소멸 확인 → 하위 카테고리를 만들어 상위 목록에 합산되는지 확인.

**Acceptance Scenarios**:

1. **Given** 임시저장된 글, **When** 새 글 쓰기를 연다, **Then** 이어 쓸지 묻는다. 발행하면 그 임시저장은 사라진다. 다른 사람에게는 보이지 않는다.
2. **Given** 대표 이미지를 고르지 않고 이미지가 든 글, **When** 목록을 본다, **Then** 본문 첫 이미지가 대표 이미지다. 이미지가 없으면 대표 이미지 없이 보인다.
3. **Given** 상위 'A'와 하위 'A-1', **When** 'A'를 누른다, **Then** 'A-1' 글도 함께 나오고 글 수도 합친 값이다. 하위가 있는 'A'는 바로 지울 수 없다.
4. **Given** 같은 블로그 공개 글 1·2·3과 남의 시각에서 비공개인 2, **When** 다른 사람이 1에서 다음 글로 간다, **Then** 3으로 간다.
5. **Given** 블로그가 없는 회원, **When** 글쓰기를 누른다, **Then** 블로그 개설로 안내된다.
6. **Given** 로그인한 회원, **When** 브라우저를 닫았다 연다, **Then** 로그아웃 전까지 로그인 상태다.

---

### User Story 6 - 구독하고 피드로 모아 읽기 (Priority: P2)

회원이 마음에 드는 블로그를 구독하고, 구독한 블로그의 새 글을 피드로 모아 보고, 글 주소를 공유한다.

**Why this priority**: 재방문을 만드는 핵심 기능이지만 MVP 한 바퀴에는 없어도 된다.

**Independent Test**: B가 A 블로그 구독 → A 새 글 발행 → B 피드에 노출 → A 구독자 수 1 확인 → 구독 해제 후 피드에서 빠짐.

**Acceptance Scenarios**:

1. **Given** 회원 B, **When** A 블로그를 구독한다, **Then** 버튼이 구독 중으로 바뀌고 A의 구독자 수가 1 오르며 새로고침해도 같다.
2. **Given** 블로그 주인, **When** 자기 블로그를 구독하려 한다, **Then** 할 수 없다.
3. **Given** 구독한 블로그가 없는 회원, **When** 피드를 연다, **Then** 빈 상태를 알리고 다른 블로그를 둘러볼 길을 준다.
4. **Given** 구독한 블로그의 비공개 글, **When** 피드를 본다, **Then** 그 글은 빠진다.
5. **Given** 글 상세, **When** 주소를 복사한다, **Then** 수정해도 바뀌지 않는 글 주소가 복사된다.

---

### User Story 7 - 인기·주제·통합 검색으로 탐색하고 소통 넓히기 (Priority: P2)

방문자가 인기 글, 주제별 글, 플랫폼 통합 검색으로 새 글과 블로그를 찾고, 회원은 댓글을 고치고 방명록을 남긴다.

**Why this priority**: 발견 경로를 넓히는 권장 기능.

**Independent Test**: 주제가 지정된 공개 글이 주제별 목록에 나오고, 통합 검색에서 글(소속 블로그 표시)과 블로그가 함께 찾아지는지 확인. 방명록 작성·삭제 확인.

**Acceptance Scenarios**:

1. **Given** 선택 7.6에서 고른 기준, **When** 인기 글을 연다, **Then** 공개 글만 그 기준으로 순위가 매겨진다. 인기 글이 없으면 빈 상태 또는 최신 글이 보인다.
2. **Given** 주제 'IT' 글과 주제 없는 글, **When** 'IT'를 고른다, **Then** 'IT' 공개 글만 최신순으로 보이고, 주제마다 고유 주소가 있다.
3. **Given** 통합 검색, **When** 검색한다, **Then** 공개 글과 이용 제한되지 않은 블로그(이름·소개)만 나오고, 글 결과에는 소속 블로그가 보인다.
4. **Given** 내 댓글, **When** 수정한다, **Then** 바뀐다. 남의 댓글에는 수정이 없다.
5. **Given** 회원, **When** 남의 블로그에 방명록을 쓴다, **Then** 남고, 블로그 주인은 모든 방명록을 지울 수 있다.

---

### User Story 8 - 내 블로그를 한곳에서 관리하기 (Priority: P2)

블로그 주인이 관리 화면에서 내 글(공개·비공개·임시저장)과 내 블로그에 달린 댓글·방명록을 모아 보고 처리한다.

**Why this priority**: 글과 댓글이 쌓이면 꼭 필요하다.

**Independent Test**: 관리 화면에서 세 상태의 글이 구분돼 보이는지, 그 자리에서 공개 범위 변경·삭제가 되는지, 댓글이 어느 글 소속인지 보이는지 확인.

**Acceptance Scenarios**:

1. **Given** 공개·비공개·임시저장 글, **When** 내 글 관리를 연다, **Then** 세 상태가 구분돼 보이고 수정·삭제·공개 범위 변경을 할 수 있다.
2. **Given** 관리자가 숨긴 내 글, **When** 내 글 관리를 연다, **Then** 숨김 상태와 사유가 보인다.
3. **Given** 여러 글의 댓글과 방명록, **When** 댓글 관리를 연다, **Then** 최신순으로 어느 글에 달렸는지와 함께 보이고 지울 수 있다.
4. **Given** 블로그를 여러 개 가진 회원, **When** 관리 화면을 쓴다, **Then** 블로그마다 따로 관리된다.

---

### User Story 9 - 서비스 관리자가 회원과 게시물을 제재하기 (Priority: P2)

서비스 관리자가 문제 회원의 이용을 기간을 정해 제한하고, 문제 글·댓글을 사유와 함께 숨기고 되돌린다.

**Why this priority**: 운영 가능한 서비스의 최소 조건이지만 MVP에는 영역 보호(US4)만 필수다.

**Independent Test**: 관리자로 회원 C를 3일 제한 → C 로그인 시 사유·기한 안내 → 관리자가 C의 글을 숨김 → 다른 사람에게 404, C에게는 사유 표시 → 해제 후 원래 위치·수치로 복귀.

**Acceptance Scenarios**:

1. **Given** 관리자가 회원 C를 사유와 기한을 정해 제한함, **When** C가 로그인한다, **Then** 막히고 사유와 기한이 보인다. 이미 로그인 중이었다면 다음 행동부터 막힌다.
2. **Given** 제한 기한이 지남, **When** C가 로그인한다, **Then** 자동으로 풀려 있다.
3. **Given** 관리자가 글을 숨김, **When** 다른 사람이 목록·검색·홈·피드를 보거나 주소로 연다, **Then** 빠지거나 404다. 글쓴이는 숨김 사실과 사유를 본다.
4. **Given** 관리자가 댓글을 숨김, **When** 다른 사람이 글을 본다, **Then** '관리자가 숨긴 댓글'로 보이고 답글은 남는다.
5. **Given** 숨김 해제, **When** 다시 본다, **Then** 위치, 수치, 주소가 원래대로다.
6. **Given** 서비스 관리자, **When** 다른 서비스 관리자를 제재하거나 남의 글 내용을 고치려 한다, **Then** 할 수 없다.

### User Story 10 - 블로그 여러 개, 이사, 꾸미기, 탈퇴 (Priority: P3)

회원이 블로그를 여러 개 운영하고(선택 7.2), 대표 블로그를 정하고, 블로그를 이사·삭제하고, 스킨·배경을 바꾸고, 탈퇴한다.

**Why this priority**: 확장 기능. 선택 7.2에서 "1개"를 고른 서비스는 이사·삭제·대표 지정 중 블로그 여러 개 전용 부분을 만들지 않는다.

**Independent Test**: 블로그 A의 글을 B로 이사 → A의 옛 글 주소가 B의 같은 글로 연결 → A 메인이 B로 안내 → A 삭제 후 주소 `a`로 새 블로그 개설 불가 확인.

**Acceptance Scenarios**:

1. **Given** 같은 회원의 블로그 A·B, **When** A의 글을 B로 옮긴다, **Then** 댓글·공감도 함께 옮겨지고 카테고리는 '미분류'가 되며 옛 주소는 B의 같은 글로 연결된다.
2. **Given** A→B, B→C 이사, **When** A 주소로 들어온다, **Then** C로 연결된다.
3. **Given** 블로그 삭제, **When** 누군가 같은 주소로 개설하려 한다, **Then** 할 수 없다.
4. **Given** 대표 블로그, **When** 삭제하려 한다, **Then** 다른 블로그를 대표로 바꾼 뒤에만 된다.
5. **Given** 상단 배경 이미지를 지움, **When** 블로그를 본다, **Then** 스킨 기본 배경이다.
6. **Given** 탈퇴, **When** 진행한다, **Then** 한 번 더 확인한다. 탈퇴 후 블로그·글·댓글 처리는 [NEEDS CLARIFICATION: Q2].

### User Story 11 - 글과 댓글의 세부 공개 제어 (Priority: P3)

블로그 주인이 보호글·구독자 공개(선택 7.8), 예약 발행, 카테고리 비공개, 태그 관리, 답글·비밀댓글·댓글 막기를 쓰고, 회원은 글을 저장해 둔다.

**Why this priority**: 확장 기능.

**Independent Test**: 예약 발행한 글이 시각 전에는 주인에게만 보이고 시각 후 발행일이 실제 공개 시각인지 확인. 답글이 달린 댓글 삭제 시 '삭제된 댓글' 표시 확인.

**Acceptance Scenarios**:

1. **Given** 내일 10시 예약 글, **When** 그 전에 다른 사람이 본다, **Then** 보이지 않는다. 10시 이후 공개되고 발행일은 실제 공개 시각이다.
2. **Given** 확장 공개 범위 글, **When** 본문을 볼 수 없는 사람이 검색·홈·인기 글·피드를 본다, **Then** 빠진다.
3. **Given** 답글이 달린 댓글, **When** 삭제한다, **Then** '삭제된 댓글'로 표시되고 답글은 남는다. 답글은 한 단계까지만 단다.
4. **Given** 비밀댓글, **When** 제3자가 본다, **Then** 내용이 보이지 않는다. 블로그 주인과 작성자만 본다.
5. **Given** 댓글을 막은 글, **When** 회원이 댓글을 쓰려 한다, **Then** 쓸 수 없고 기존 댓글은 남는다.
6. **Given** 저장한 글이 비공개로 바뀌거나 삭제됨, **When** 저장 목록을 본다, **Then** 그 글은 빠져 있다.

### User Story 12 - 알림, 맞구독, 추천, 랭킹 (Priority: P3)

회원이 내 활동에 대한 서비스 안 알림을 받고, 맞구독 상태를 보고, 추천 블로그와 인기 블로거·랭킹 전체보기를 본다.

**Why this priority**: 확장 기능.

**Independent Test**: B가 A 글에 댓글 → A에게 알림 1개, 읽지 않은 수 표시 → 눌러서 해당 글로 이동하고 읽음 처리. A가 자기 글에 댓글을 달면 알림 없음.

**Acceptance Scenarios**:

1. **Given** 내 글에 댓글·공감, 나를 구독, 구독 블로그 새 글, **When** 발생한다, **Then** 알림이 생기고 읽지 않은 수가 보인다. 내가 한 행동으로는 알림이 오지 않는다.
2. **Given** 서로 구독, **When** 버튼을 본다, **Then** 네 상태(서로 안 함 / 상대만 / 나만 / 서로) 중 '서로 구독'으로 보인다. 해제하면 확인 후 내 구독만 취소되고 상대에게 알림은 없다.
3. **Given** 추천 블로그, **When** 본다, **Then** 아직 구독하지 않은 블로그만 나오고 자기 블로그는 빠진다.
4. **Given** 홈 랭킹 상위 일부, **When** 전체보기를 연다, **Then** 같은 기준·같은 시점의 순위가 이어진다. 공개 글이 없는 블로그는 인기 블로거에서 빠진다.

### User Story 13 - 방문 통계와 스팸 차단 (Priority: P3)

블로그 주인이 방문자 수와 인기 글을 보고, 특정 회원을 차단하거나 금칙어를 정한다.

**Why this priority**: 확장 기능.

**Independent Test**: 회원 D 차단 → D가 댓글·방명록을 쓸 수 없고 사유 없이 "쓸 수 없다"는 사실만 안내 → 금칙어 포함 댓글 거절.

**Acceptance Scenarios**:

1. **Given** 방문이 있음, **When** 통계를 연다, **Then** 오늘·어제·전체 방문자 수와 기간 내 인기 글이 보이고, 사이드바 방문자 수와 같은 값이다.
2. **Given** 차단된 회원, **When** 이 블로그에 댓글·방명록을 쓰려 한다, **Then** 쓸 수 없다는 사실만 안내된다. 차단은 풀 수 있다.
3. **Given** 금칙어 '광고', **When** '광고'가 든 댓글을 등록한다, **Then** 등록되지 않는다.

### User Story 14 - 신고, 블로그 제한, 공지, 관리 이력 (Priority: P3)

회원이 글·댓글을 신고하고, 서비스 관리자가 신고를 처리하고, 블로그 단위로 제한하고, 공지를 올리고, 모든 제재 이력과 운영 현황을 본다.

**Why this priority**: 확장 운영 기능.

**Independent Test**: 회원이 글 신고 → 관리자가 숨김 처리 → 신고 목록에 결과 기록 → 관리 이력에 누가·언제·무엇을·왜가 남고 수정·삭제 불가.

**Acceptance Scenarios**:

1. **Given** 같은 글을 이미 신고함, **When** 다시 신고한다, **Then** 안 된다. 자기 글은 신고할 수 없다.
2. **Given** 신고가 여러 건 쌓임, **When** 관리자가 처리하지 않았다, **Then** 자동으로 숨겨지지 않는다.
3. **Given** 블로그 E 이용 제한, **When** 다른 사람이 E의 메인·글을 연다, **Then** 404다. 주인의 다른 블로그와 댓글 활동은 영향이 없다.
4. **Given** 제재와 해제, **When** 관리 이력을 본다, **Then** 누가·언제·무엇을·왜가 남아 있고 고치거나 지울 수 없다.
5. **Given** 대시보드, **When** 연다, **Then** 회원 수, 블로그 수, 글 수, 처리 대기 신고 수가 보인다.

---

### Edge Cases

- 마지막 페이지를 넘는 페이지를 요청하면 오류가 아니라 빈 목록이다.
- 발행 시각이 같은 글은 나중에 만든 글이 위에 온다. 글을 수정해도 목록 순서는 바뀌지 않는다.
- 더보기·무한 스크롤 목록(홈, 피드)에서 중간에 새 글이 생겨도 중복·누락이 없다.
- 공백만 입력한 검색어는 검색하지 않는다. 글자 수는 앞뒤 공백을 뺀 뒤 잰다.
- 이미지로 위장한 파일은 거절한다. 업로드 실패 시 기존 이미지·본문은 그대로다. GIF는 움직임이, 모든 이미지는 비율이, 휴대폰 사진은 찍힌 방향이 유지된다.
- 다른 블로그 주소에 글 번호를 붙여 접근하면 404다. 단, 이사로 옮긴 글은 현재 블로그 주소로 이동한다.
- 로그인이 만료된 채 글을 저장하면 다시 로그인한 뒤 원래 화면으로 돌아오고 쓰던 내용을 잃지 않는다.
- 글 삭제·카테고리 삭제·블로그 이사가 중간에 실패하면 일부만 처리된 상태로 남지 않는다.
- 미분류 글이 없으면 사이드바에서 '미분류'를 숨긴다.
- 같은 단계에서는 카테고리 이름이 겹칠 수 없지만, 상위가 다르면 하위 이름은 같아도 된다.
- 제목 기반 글 주소(선택 7.5)에서 같은 제목의 글도 서로 다른 주소를 가지며, 한글 제목도 깨지지 않고 열린다.
- 이용 제한된 회원이 이미 로그인 중이면 다음 행동부터 막힌다.

### Functional Requirements

#### 공통 정책 (모든 기능에 적용)

- **FR-001**: 모든 글은 공개 또는 비공개여야 하며 기본값은 공개다. 발행 후에도 바꿀 수 있어야 한다. [4.1]
- **FR-002**: 비공개 글은 블로그 주인 외 모든 사람에게 블로그 목록, 카테고리·태그 목록, 검색, 홈, 인기 글, 피드, 사이드바, 이전·다음 글, 글 개수에서 빠져야 하며, 주소로 열면 404여야 한다. [4.1]
- **FR-003**: 블로그 주소는 영문 소문자·숫자·하이픈만, 4~32자, 하이픈으로 시작·끝 불가여야 한다. 사용 중인 주소, 예약어(login, admin, api 등), 삭제된 블로그가 썼던 주소는 거절하고 이유를 알려야 한다. [4.2]
- **FR-004**: 블로그 주소는 개설 후 바꿀 수 없어야 하고, 블로그 이름은 언제든 바꿀 수 있어야 한다. [4.2]
- **FR-005**: 글 주소는 처음 발행할 때 정해지고 수정해도 바뀌지 않아야 한다. 글이 소속되지 않은 블로그 주소로 접근하면 404여야 한다(이사한 글은 현재 블로그로 이동). [4.3]
- **FR-006**: 글 목록은 처음 발행 시각 기준 최신순이어야 하며, 같은 시각이면 나중에 만든 글이 위다. 페이지 목록(권장 10개), 마지막 페이지 초과 시 빈 목록, 빈 목록 안내를 지원해야 한다. [4.4]
- **FR-007**: 더보기·무한 스크롤 목록은 같은 글이 두 번 나오거나 빠지지 않아야 한다. [4.4]
- **FR-008**: 글자 수는 앞뒤 공백을 뺀 뒤 재야 한다. 기준: 글 제목 1~100자 [NEEDS CLARIFICATION: Q1], 본문 필수, 댓글 1~1,000자, 블로그 이름 1~40자 [Q1], 카테고리 이름 1~20자 [Q1], 글당 태그 최대 10개. [4.5]
- **FR-009**: 이미지(jpg, png, gif, webp)만 업로드할 수 있어야 하고, 이미지가 아니거나 위장 파일이거나 크기 상한을 넘으면 거절하고 이유를 알려야 한다. 실패해도 기존 이미지·본문은 유지돼야 한다. 비율, GIF 움직임, 사진 방향이 유지돼야 한다. [4.6]
- **FR-010**: 모든 삭제는 확인을 한 번 더 받아야 한다. 대상별 함께 처리되는 것은 글 FR-028, 댓글 FR-052, 카테고리 FR-039·041, 태그 FR-047, 블로그 FR-023, 탈퇴 FR-016을 따르고, 관리자 제재는 삭제가 아닌 숨김이다(FR-076). [4.7]

#### 회원·인증 (AUTH)

- **FR-011**: 사용자는 가입·로그인할 수 있어야 하며 가입하면 항상 일반 회원이다. 로그인 성공 시 이전 화면(없으면 홈)으로, 실패·취소 시 아무것도 바뀌지 않고 이유를 알린다. 로그인 방식은 선택 V1. 회원마다 닉네임을 가진다. [AUTH-01 · P0]
- **FR-012**: 로그아웃하면 비회원 상태가 되고 홈이나 보던 공개 화면으로 가야 한다. [AUTH-02 · P0]
- **FR-013**: 로그아웃 전까지 브라우저를 닫았다 열어도 로그인이 유지돼야 한다(기간 자율). 만료 시 재로그인 후 원래 위치로 돌아온다. [AUTH-03 · P1]
- **FR-014**: 블로그가 없는 회원이 글쓰기를 누르면 블로그 개설로 안내하고, 블로그가 있으면 글쓰기로 바로 가야 한다. [AUTH-04 · P1]

#### 블로그 (BLOG)

- **FR-017**: 회원은 주소와 이름을 입력해 블로그를 개설할 수 있어야 한다(소개는 선택). 주소 중복은 입력 단계에서 알리고, 개설 화면에서 주소 변경 불가를 안내하며, 회원당 블로그 수 한도(선택 V2)를 넘으면 막는다. 개설 후 새 블로그나 글쓰기로 간다. [BLOG-01 · P0]
- **FR-018**: 블로그 주인은 이름·소개·프로필 이미지를 바꿀 수 있어야 한다. 프로필 이미지가 없으면 기본 이미지, 소개가 비면 소개 자리를 숨긴다. [BLOG-02 · P0]
- **FR-019**: 블로그 메인은 그 블로그의 글을 최신순으로 제목·발행일·카테고리·본문 요약과 함께 보여야 하며, 글이 없으면 빈 상태를, 없는 블로그면 404를 보여야 한다. [BLOG-03 · P0]
- **FR-020**: 블로그의 모든 화면에 같은 사이드바가 있어야 한다. 필수: 블로그 이름·프로필(누르면 메인), 카테고리 목록과 카테고리별 글 수('전체 글' 맨 위, '미분류' 맨 아래, 미분류 글이 없으면 숨김). 선택(P1 이후): 태그, 최근 글, 최근 댓글, 인기 글, 방문자 수. [BLOG-04 · P0]
- **FR-021**: 블로그 주인은 미리 만든 스킨을 고르고 상단 배경 이미지를 올리고 지울 수 있어야 한다(지우면 스킨 기본 배경). [BLOG-05 · P2]
- **FR-022**: 블로그 주인은 같은 회원의 다른 블로그로 글을 옮길 수 있어야 한다. 댓글·공감은 함께 옮겨지고 카테고리는 '미분류', 옛 글 주소는 새 글로, 옛 블로그 메인은 새 블로그로 연결되며 연쇄 이사(A→B→C)도 최종 블로그로 연결된다. 선택 V2가 "여러 개"일 때만. [BLOG-06 · P2]
- **FR-023**: 블로그 주인은 확인을 거쳐 블로그를 삭제할 수 있어야 한다. 옮기지 않은 글이 함께 사라짐을 알리고, 주소는 영구 예약되며 이사 안내는 계속 동작한다. 대표 블로그는 다른 블로그를 대표로 바꾼 뒤에만 삭제된다. 블로그 1개를 고른 경우 재개설 허용 여부는 [NEEDS CLARIFICATION: Q6]. [BLOG-07 · P2]
- **FR-024**: 처음 만든 블로그가 대표 블로그이며 바꿀 수 있어야 한다. '내 블로그' 바로가기와 댓글 작성자 링크는 대표 블로그로 간다. 선택 V2가 "여러 개"일 때만. [BLOG-08 · P2]

#### 글 (POST)

- **FR-025**: 블로그 주인은 빈 상태에서 새 글을 시작해 제목·본문을 쓰고 카테고리(하나, 기본 '미분류'), 태그(여러 개), 공개 범위를 정해 발행할 수 있어야 한다. 발행 시 제목 → 본문 순으로 확인해 첫 문제만 알린다. 발행 후 글 상세로 가고 공감·댓글·조회수는 0이다. 연달아 눌러도 글은 하나다. [POST-01 · P0]
- **FR-026**: 본문은 문단 제목, 굵게, 목록, 인용, 코드 블록, 링크, 이미지를 표현할 수 있어야 하며, 다시 수정하러 열어도 서식이 그대로여야 한다. 에디터 방식은 선택 V4. [POST-01 · P0]
- **FR-027**: 블로그 주인만 글을 수정할 수 있어야 하며, 수정해도 주소, 처음 발행일, 공감·댓글·조회수, 목록 순서는 그대로다. 발행 때와 같은 확인을 거친다. [POST-02 · P0]
- **FR-028**: 블로그 주인만 확인을 거쳐 글을 삭제할 수 있어야 한다. 댓글·공감·저장·알림이 함께 사라지고, 그 주소는 404이며, 삭제 후 블로그 메인이나 글 관리로 간다. [POST-03 · P0]
- **FR-029**: 글 상세는 제목, 발행일, 카테고리, 본문, 태그, 공감 수, 댓글을 보여야 하며 본문 스크립트는 실행되지 않아야 한다. 존재 → 소속 → 주인 여부 → 공개 범위 순으로 판단해 볼 수 없으면 404다. 주인에게만 수정·삭제가 보인다. [POST-04 · P0]
- **FR-030**: 쓰는 위치에 이미지를 넣을 수 있어야 하며 여러 장은 고른 순서대로 들어간다. [POST-05 · P0]
- **FR-031**: 글마다 공개·비공개를 정할 수 있어야 한다(FR-001, FR-002). [POST-06 · P0]
- **FR-032**: 대표 이미지를 본문 이미지 중 고르거나 따로 올릴 수 있어야 하며, 없으면 본문 첫 이미지, 그것도 없으면 대표 이미지 없이 보인다. [POST-07 · P1]
- **FR-033**: 쓰던 글을 임시저장하고 이어 쓸 수 있어야 한다(주인에게만 보임). 새 글 쓰기 시 임시저장 글이 있으면 이어 쓸지 묻고, 발행하면 그 임시저장은 지워진다. [POST-08 · P1]
- **FR-034**: 글을 열면 조회수가 올라야 한다. 같은 사람의 짧은 시간 내 재열람 처리는 [NEEDS CLARIFICATION: Q3]. [POST-09 · P1]
- **FR-035**: 같은 블로그 안에서 발행 순서로 이전·다음 글을 보여야 하며, 보는 사람이 볼 수 없는 글은 건너뛴다. [POST-10 · P1]
- **FR-036**: 플랫폼 주제 목록에서 주제를 하나 고를 수 있어야 하며, 고르지 않으면 '주제 없음'으로 주제별 글에서 빠진다. 지정 단위는 선택 V7, 주제 목록 공유 여부는 [NEEDS CLARIFICATION: Q9]. [POST-11 · P1]
- **FR-037**: 선택 V8에서 고른 확장 공개 범위를 지원해야 한다. 본문을 볼 수 없는 사람에게는 검색, 홈, 인기 글, 피드에서 빠진다. [POST-12 · P2]
- **FR-038**: 정한 날짜·시각에 자동 공개되는 예약 발행을 지원해야 한다. 그 전에는 주인에게만 보이고, 발행일은 실제 공개 시각이다. [POST-13 · P2]

#### 카테고리 (CAT)

- **FR-039**: 블로그 주인은 카테고리를 추가·이름 변경·삭제할 수 있어야 한다. 같은 단계에서 이름 중복 불가, 삭제 시 소속 글은 '미분류'로, '전체 글'·'미분류'는 변경·삭제 불가. 새 블로그는 카테고리 없이 시작한다(기본 카테고리 생성은 자율). [CAT-01 · P0]
- **FR-040**: 카테고리를 누르면 그 카테고리 글만 최신순으로 보여야 하고, 카테고리마다 고유 주소가 있어야 한다. 상위 카테고리는 하위 글까지 포함하고 글 수도 합산한다. [CAT-02 · P0]
- **FR-041**: 하위 카테고리를 한 단계까지만 둘 수 있어야 한다. 하위가 있는 상위는 바로 삭제할 수 없고, 상위가 다르면 같은 이름을 쓸 수 있다. [CAT-03 · P1]
- **FR-042**: 블로그 주인이 정한 순서대로 사이드바에 카테고리가 보여야 한다. [CAT-04 · P1]
- **FR-043**: 카테고리를 비공개로 하면 그 카테고리와 글은 주인에게만 보여야 한다. [CAT-05 · P2]

#### 태그 (TAG)

- **FR-044**: 글 하나에 태그를 최대 10개, 같은 태그는 한 번만 달 수 있어야 한다. 태그는 블로그 단위로 관리되며 새 이름은 새 태그가 된다. [TAG-01 · P0]
- **FR-045**: 태그를 누르면 같은 블로그에서 그 태그가 붙은 글만 보여야 하고, 태그마다 고유 주소가 있어야 한다. [TAG-02 · P0]
- **FR-046**: 블로그에서 쓴 태그를 모아 보여야 하며 누르면 태그별 글 목록으로 간다. [TAG-03 · P1]
- **FR-047**: 블로그 주인은 태그 이름을 바꾸거나 지울 수 있어야 하며, 지워도 글은 남는다. [TAG-04 · P2]

#### 댓글·방명록 (CMT)

- **FR-048**: 회원만 댓글을 쓸 수 있어야 한다(비회원은 로그인 안내). 닉네임과 작성 날짜·시각을 보여 주고, 작성순으로 정렬하며, 글마다 댓글 수를 보여야 한다. 자기 댓글은 확인 후 지울 수 있다. 연달아 등록해도 한 번만 올라간다. [CMT-01 · P0]
- **FR-049**: 블로그 주인은 자기 블로그 글의 모든 댓글을 지울 수 있어야 하지만 남의 댓글을 수정할 수는 없다. [CMT-02 · P0]
- **FR-050**: 회원은 자기 댓글만 수정할 수 있어야 한다. [CMT-03 · P1]
- **FR-051**: 회원은 블로그에 방명록을 남기고 지울 수 있어야 하며(규칙은 댓글과 같음), 블로그 주인은 모든 방명록을 지울 수 있다. [CMT-04 · P1]
- **FR-052**: 댓글에 한 단계까지 답글을 달 수 있어야 하며, 답글이 달린 댓글을 지우면 '삭제된 댓글'로 표시하고 답글은 남긴다. [CMT-05 · P2]
- **FR-053**: 비밀댓글은 블로그 주인과 작성자만 볼 수 있어야 한다. [CMT-06 · P2]
- **FR-054**: 글마다 댓글을 막을 수 있어야 하며, 막으면 새 댓글은 안 되고 기존 댓글은 남는다. [CMT-07 · P2]

#### 반응 (SOC)

- **FR-055**: 회원은 글마다 한 번 공감하고 다시 눌러 취소할 수 있어야 한다. 공감 수는 바로 반영되고 새로고침해도 실제 값과 같다. 비회원은 로그인 안내. 자기 글 공감 허용 여부는 [NEEDS CLARIFICATION: Q4]. [SOC-01 · P0]
- **FR-056**: 바뀌지 않는 글 주소를 복사할 수 있어야 한다(SNS 보내기는 자율). [SOC-02 · P1]
- **FR-057**: 회원은 글을 저장·해제하고 저장한 글만 모아 볼 수 있어야 하며, 비공개 전환·삭제된 글은 저장 목록에서 빠진다. [SOC-03 · P2]

#### 구독·피드·알림 (SUB)

- **FR-058**: 회원은 다른 블로그를 구독·해제할 수 있어야 하며(자기 블로그 불가), 버튼에 구독 여부가 보이고, 구독 목록에서 해제할 수 있다. [SUB-01 · P1]
- **FR-059**: 구독한 블로그의 볼 수 있는 새 글을 최신순으로 모아 보여야 하며, 구독이 없으면 빈 상태와 둘러볼 길을 준다. [SUB-02 · P1]
- **FR-060**: 블로그의 구독자 수를 보여야 하며 새로고침해도 실제 값과 같다. [SUB-03 · P1]
- **FR-061**: 내 글의 댓글·공감, 나를 구독, 구독 블로그 새 글에 대해 서비스 안 알림을 만들어야 한다. 읽지 않은 수를 보여 주고, 누르면 해당 화면으로 가며 읽음 처리된다. 내 행동으로는 나에게 알림이 오지 않는다. [SUB-04 · P2]
- **FR-062**: 서로 구독하면 요청·수락 없이 맞구독이며, 구독 버튼은 네 상태를 구분한다. 맞구독 해제는 확인 후 내 구독만 취소하고 상대에게 알리지 않는다. [SUB-05 · P2]
- **FR-063**: 아직 구독하지 않은 인기 블로그를 추천해야 하며 자기 블로그는 빠진다(기준은 plan에 밝힘). [SUB-06 · P2]

#### 검색 (SRCH)

- **FR-064**: 한 블로그 안에서 제목·본문·태그로 글을 찾을 수 있어야 한다. 영문 대소문자 무시, 앞뒤 공백 제거, 공백만이면 검색 안 함. 결과는 최신순·페이지 단위, 볼 수 없는 글 제외, 결과 없음 안내와 검색어 유지, 결과 주소는 새로고침·공유해도 같다. [SRCH-01 · P0]
- **FR-065**: 플랫폼 전체에서 공개 글과 이용 제한되지 않은 블로그(이름·소개)를 찾을 수 있어야 하며, 글 결과에 소속 블로그를 보여야 한다. 검색어·빈 결과 처리는 FR-064와 같고 정렬은 자율. [SRCH-02 · P1]

#### 홈·탐색 (HOME)

- **FR-066**: 홈은 비회원도 볼 수 있어야 하며, 플랫폼 전체 공개 글(숨긴 글·블로그 제외)을 최신순으로 제목·블로그 이름·발행일·요약과 함께 보여 주고 누르면 글 상세로 간다. [HOME-01 · P0]
- **FR-067**: 선택 V6 기준으로 공개 글의 인기 순위를 보여야 하며, 없으면 빈 상태나 최신 글로 대신한다. [HOME-02 · P1]
- **FR-068**: 주제를 고르면 그 주제의 공개 글을 최신순으로 보여야 하며, 주제마다 고유 주소가 있다. [HOME-03 · P1]
- **FR-069**: 블로그 단위 인기 순위를 보여야 하며 공개 글이 없는 블로그는 빠진다(기준은 plan에 밝힘). [HOME-04 · P2]
- **FR-070**: 홈은 랭킹 상위 일부만, 전체보기는 나머지를 같은 기준·같은 시점으로 보여야 한다. [HOME-05 · P2]

#### 블로그 관리 (MNG) — 블로그 주인 전용, 블로그마다 따로

- **FR-071**: 내 블로그의 발행 글(공개·비공개)과 임시저장 글을 상태 구분해 모아 보고 수정·삭제·공개 범위 변경을 할 수 있어야 한다. 관리자가 숨긴 글은 숨김 상태와 사유가 보인다. [MNG-01 · P1]
- **FR-072**: 내 블로그의 모든 댓글과 방명록을 최신순으로, 어느 글 소속인지와 함께 모아 보고 지울 수 있어야 한다. [MNG-02 · P1]
- **FR-073**: 오늘·어제·전체 방문자 수(사이드바와 같은 값)와 기간 내 인기 글을 보여야 한다(반복 방문 집계 방식은 plan에 밝힘). [MNG-03 · P2]
- **FR-074**: 특정 회원을 차단·해제할 수 있어야 하며, 차단된 회원은 이 블로그에 댓글·방명록을 쓸 수 없다는 사실만 안내받는다. 금칙어가 든 댓글은 등록되지 않는다. [MNG-04 · P2]

#### 서비스 관리 (ADMIN)

- **FR-075**: 서비스 관리자 역할과 관리자만 들어가는 영역이 있어야 한다. 일반 회원은 403, 비회원은 로그인 안내이며 주소 직접 입력도 같다. 서비스 시작 시 관리자 계정이 하나 이상 있다. P0에서는 역할과 영역 보호까지만 필수. [ADMIN-01 · P0]
- **FR-076**: 모든 ADMIN 기능은 다음을 지켜야 한다: 관리자는 가입·화면으로 될 수 없음, 제재는 숨김·제한이며 해제 시 원상 복구, 남의 내용 수정 불가, 사유 필수·당사자 열람 가능, 관리자끼리 제재 불가. [ADMIN 공통]
- **FR-077**: 관리자는 기간(날짜 또는 영구)과 사유를 정해 회원 이용을 제한하고 미리 해제할 수 있어야 한다. 제한된 회원은 로그인 시 사유·기한을 안내받고, 이미 로그인 중이면 다음 행동부터 막히며, 기한이 지나면 자동 해제된다. 제한 기간 중 그 회원의 블로그 노출은 [NEEDS CLARIFICATION: Q5]. [ADMIN-02 · P1]
- **FR-078**: 관리자는 사유를 정해 글·댓글을 숨기고 되돌릴 수 있어야 한다. 숨긴 글은 목록·검색·홈·피드·글 개수에서 빠지고 다른 사람에게 404, 글쓴이에게는 사실과 사유가 보인다. 숨긴 댓글은 '관리자가 숨긴 댓글'로 표시되고 답글은 남는다. [ADMIN-03 · P1]
- **FR-079**: 회원은 남의 글·댓글을 사유를 골라 한 번만 신고할 수 있어야 하며(자기 것 불가), 관리자는 숨김 또는 기각으로 처리하고 결과가 신고 목록에 남는다. 신고 누적으로 자동 숨김하지 않는다. [ADMIN-04 · P2]
- **FR-080**: 관리자는 회원은 두고 특정 블로그만 제한할 수 있어야 한다. 그 블로그 메인과 글은 다른 사람에게 404, 주인에게는 사실과 사유가 보이며, 그 회원의 다른 블로그와 댓글 활동에는 영향이 없다. [ADMIN-05 · P2]
- **FR-081**: 관리자 공지는 모든 사용자가 볼 수 있어야 한다. 모든 제재·해제는 누가·언제·무엇을·왜가 기록되며 수정·삭제할 수 없다. 대시보드는 회원 수, 블로그 수, 글 수, 처리 대기 신고 수를 보여야 한다. [ADMIN-06 · P2]

#### 공통 (COM)

- **FR-082**: 모든 행동은 위 권한표를 따르고, 권한이 없으면 위 처리표대로 처리해야 한다. 주소 직접 입력·직접 요청에도 같은 결과여야 하고, 로그인 안내를 거치면 원래 화면으로 돌아간다. [COM-01 · P0]
- **FR-083**: 없는 주소는 404, 권한 없음은 403으로 알리고 홈이나 이전 화면으로 돌아갈 길을 줘야 한다. 입력 오류는 어느 항목이 왜 잘못됐는지 알리고 입력을 유지한다. 예상치 못한 오류에도 내부 정보를 드러내지 않고 다시 시도하라고 안내한다. [COM-02 · P0]

#### 비기능 요구사항

- **NFR-001 (보안)**: 사용자 입력(글 제목·본문, 댓글, 블로그 이름·소개, 닉네임)의 스크립트는 어디서도 실행되지 않아야 한다. 다른 사이트가 로그인한 사용자 대신 행동할 수 없어야 한다. 로그인 정보와 비밀번호는 주소창·화면·오류 메시지에 드러나지 않아야 한다. [8.1]
- **NFR-002 (성능)**: 목록은 페이지 단위로 불러오고, 목록에는 작은 이미지만, 원본은 글 상세에서만 불러와야 한다. 공감·구독 버튼은 누르는 즉시 바뀐 상태를 보여야 한다. 목록과 글 상세는 기다린다는 느낌 없이 열려야 한다(목표 수치는 plan에 밝힘). [8.2]
- **NFR-003 (신뢰성)**: 발행·댓글·공감·구독은 중복 요청에도 한 번만 처리해야 한다. 각종 수치는 새로고침 시 실제 값과 같아야 한다. 저장 실패·로그인 만료에도 쓰던 내용을 잃지 않아야 한다. 여러 단계 작업은 원자적이어야 한다. 재시작 후에도 글·이미지·댓글이 남아야 한다. [8.3]
- **NFR-004 (사용성)**: 휴대폰 폭에서 가로 스크롤 없이 모든 P0 기능을 쓸 수 있어야 한다. 처리 중 상태와 결과를 알려야 한다. 날짜·시각은 한국 시간이다. 최신 크롬·사파리·엣지에서 같은 기능이 동작해야 한다. [8.4]

### Key Entities

- **회원(Member)**: 닉네임, 프로필 이미지, 역할(일반 회원 / 서비스 관리자), 이용 제한 상태(사유, 기한).
- **블로그(Blog)**: 주소(불변, 영구 예약), 이름, 소개, 프로필 이미지, 스킨·배경, 주인(회원 1명), 대표 여부, 이사 대상 블로그, 이용 제한 상태.
- **글(Post)**: 소속 블로그, 제목, 본문, 주소(불변), 처음 발행 시각, 수정 시각, 공개 범위, 카테고리(0~1), 태그(0~10), 주제, 대표 이미지, 조회수, 상태(발행 / 임시저장 / 예약), 숨김 상태, 댓글 허용 여부.
- **카테고리(Category)**: 소속 블로그, 이름, 상위 카테고리(최대 1단계), 순서, 공개 여부. '전체 글'과 '미분류'는 고정.
- **태그(Tag)**: 소속 블로그, 이름. 글과 다대다.
- **주제(Topic)**: 플랫폼이 정한 분류. 글 또는 블로그에 지정(V7).
- **댓글(Comment)**: 글, 작성자, 내용, 작성 시각, 상위 댓글(답글, 1단계), 비밀 여부, 삭제 표시, 숨김 상태.
- **방명록(Guestbook Entry)**: 블로그, 작성자, 내용, 작성 시각.
- **공감(Like) / 저장(Bookmark)**: 회원과 글의 쌍, 회원·글마다 하나.
- **구독(Subscription)**: 구독하는 회원과 구독 대상 블로그. 맞구독은 양방향 구독으로 판단.
- **알림(Notification)**: 받는 회원, 종류(댓글, 공감, 구독, 새 글), 대상, 읽음 여부.
- **차단(Block) / 금칙어(Banned Word)**: 블로그 단위.
- **신고(Report)**: 신고자, 대상(글·댓글), 사유, 처리 결과(숨김 / 기각).
- **제재 기록(Moderation Log)**: 관리자, 시각, 대상, 행동, 사유. 수정·삭제 불가.
- **공지(Notice)**: 관리자가 작성, 모든 사용자에게 보임.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: P0 기능(FR 중 `· P0` 24개 기능)만으로 "가입 → 블로그 개설 → 글 발행 → 다른 사람이 홈에서 발견 → 읽기·댓글·공감" 시나리오(US1~US3)를 막힘 없이 끝낼 수 있다.
- **SC-002**: 남의 비공개 글·숨긴 글·제한된 블로그에 대한 모든 직접 접근(주소 입력, 직접 요청)이 100% 404로 응답하고, 어떤 목록·개수에도 노출되지 않는다.
- **SC-003**: 권한표의 모든 ✕ 칸을 직접 요청으로 시도했을 때 100% 로그인 안내 또는 403/404로 막힌다.
- **SC-004**: 발행·댓글·공감·구독을 빠르게 연속 요청해도 중복 생성이 0건이다.
- **SC-005**: 공감 수, 댓글 수, 구독자 수, 글 수가 새로고침 후 실제 값과 100% 일치한다.
- **SC-006**: 글을 수정한 뒤에도, 블로그를 이사한 뒤에도, 이전에 공유한 글 주소가 100% 그 글로 열린다.
- **SC-007**: 사용자 입력 필드 전체에 스크립트를 넣었을 때 실행되는 곳이 0곳이다.
- **SC-008**: 휴대폰 화면 폭에서 모든 P0 기능을 가로 스크롤 없이 쓸 수 있고, 최신 크롬·사파리·엣지에서 같은 결과가 나온다.
- **SC-009**: 세 서비스가 이 문서의 Acceptance Scenarios로 서로의 서비스를 교차 테스트할 수 있다(선택 항목 V1~V8에 따른 차이 제외).
