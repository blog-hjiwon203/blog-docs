# 스텝 23. 주 DB를 PostgreSQL로: 스키마·코드·테스트

> 작업: T123~T128 · 코드 브랜치: `step-23-postgres` (스텝 24까지 이어서, 코드 PR은 하나) · 날짜: 2026-10-13 · 결정: research.md R-02(주 DB를 PostgreSQL로 합침), 2026-10-13 지원 결정

## 한눈에 보기

주 DB(MySQL)와 추천 DB(PostgreSQL)를 **PostgreSQL 하나**(pgvector)로 합쳤다. 기능과 화면은 그대로이고 DB만 바뀌었다. 이 스텝은 코드·개발·테스트까지다. 운영 데이터를 옮기고 배포하는 것은 스텝 24다.

결정 세 가지(2026-10-13 지원 결정):

- 대소문자 무시 비교는 **citext**. 악센트는 가린다(Café ≠ cafe).
- 백업은 하지 않는다(과제 규모).
- 운영 PostgreSQL은 이미 떠 있는 `aigj017-recommend-db` 컨테이너를 쓰고, 서버 포트는 열지 않는다(스텝 24).

## 요청 흐름

```
[의미 검색] GET /api/search?q=로그인 보안&mode=semantic   (블로그면 X-Blog-Address)
[SemanticSearchService]
  검색어 정리 → QueryEmbeddings.embed (Redis 캐시, 없으면 Ollama)  ── 실패하면 503
  → PostEmbeddingRepository.countNear  : 볼 수 있고 유사도 ≥ 0.40인 글 수 (최대 100으로 자름)
  → PostEmbeddingRepository.findNear   : 그 페이지 몫
      SELECT p.*, b.*, c.*, (e.embedding <=> cast(? as vector))
      FROM post p JOIN blog b … LEFT JOIN category c …, post_embedding e
      WHERE e.post_id = p.id AND (visibleTo 또는 listedIn 조건) AND 거리 <= 0.60
      ORDER BY 거리, p.id DESC OFFSET ? FETCH FIRST ? ROWS ONLY
  ← 200 { content: [{ post, similarity }], totalElements, … }

[비슷한 글] GET /api/posts/{id}/similar
  이 글을 볼 수 있나(404·403) → 이 글의 임베딩 → findNear(visibleTo, 자기 글 빼고, size개)
```

## 막혔던 점

- **citext인데 대소문자를 가렸다**: 시작하기 전에 psql로 확인해 보니 `citext칸 = 'x'::varchar`가 거짓이었다. PgJDBC는 자바 `String`을 `varchar`로 보내므로, 칸만 citext로 바꾸면 JPA 쿼리는 대소문자를 가린다. 접속 설정 `stringtype: unspecified`로 막았다([PostgreSQL vs MySQL](./concepts/2-데이터/03-PostgreSQL-vs-MySQL.md) 3.6). 이 설정을 끄면 `TagIntegrationTest` 3개가 500으로 실패하는 것도 확인했다.
- **처음 돌린 테스트가 전부 실패**: 지운 V3 파일이 `target/classes`에 남아 Flyway가 실행했다(MySQL 문법이라 오류). `./mvnw clean test`로 다시 돌리니 409개 중 9개 실패였다.
- **cosine_distance가 float[]를 거절**: Criteria에서 `cb.literal(float[])`로 넘기니 hibernate-vector가 "인자는 vector여야 한다"며 쿼리를 만들지 않았다. 공개 API(`HibernateCriteriaBuilder`)에 "칸의 타입을 물려받는 값"이 없어서, Hibernate 구현 클래스(`SqmCriteriaNodeBuilder.value(값, 칸)`)를 썼다. Hibernate를 올릴 때 다시 확인할 자리다.
- **의미 검색이 0개**: 쿼리는 도는데 결과가 비었다. `show-sql`로 본 SQL에 `join category`가 있었다. `fetch("category")`는 INNER JOIN이라 미분류 글이 모두 빠졌다. `JoinType.LEFT`로 고쳤다.
- **503과 500**: 전에는 추천 DB가 따로라서 그 DB 오류도 503으로 바꿨다. 이제 임베딩이 주 DB에 있어서, 읽기 트랜잭션 안에서 DB 예외를 잡으면 트랜잭션이 롤백 표시가 되어 커밋할 때 다른 예외가 난다. 503은 임베딩 서버(Ollama)에 닿지 않을 때만, DB 오류는 다른 API처럼 500으로 했다(contracts 고칠 곳, 스텝 24).
- **태그 응답 순서**: "Café와 cafe는 다른 태그" 테스트의 기대값을 처음엔 입력 순서로 적었는데, 응답의 태그는 이름순(`Post.tagNames`, 코드 포인트 순: 대문자가 소문자보다 앞)이었다.
- **`CAST(x AS CHAR)`가 한 글자**: PostgreSQL의 `CHAR`는 `char(1)`이라 `'2026-01-01 …'`이 `'2'`로 잘렸다. `TEXT`로 고쳤다.
- **임베딩 정리 테스트와 외래 키**: "없는 글(999999999)의 임베딩을 넣고 sync가 지우나" 테스트가 외래 키에 막혔다. 이제 없는 글의 임베딩은 들어갈 수 없다. 대신 "이벤트 없이 지운 글"(SQL로 `deleted_at`만 넣은 글)의 임베딩을 sync가 지우는지로 바꿨다.
- **실제 서버(8081)에서 확인한 것**: 개발 PostgreSQL에 `blog` DB를 새로 만들고 서버를 띄우니 Flyway가 V1·V2를 적용했다. 관리자로 로그인(이메일 대문자로도 됨) → 블로그·글 3개 → 진짜 Ollama로 임베딩 3개(`text_version` 2). "로그인 보안" 의미 검색에 "스프링 시큐리티 필터 체인"(0.48), 블로그 안 "휴가"에 "제주도 바다 여행"(0.43). 비슷한 글도 나왔고, 글자 검색 `SPRING`이 "스프링…" 글을 찾았다(태그 Spring, ILIKE). 그 글을 비공개로 바꾸자 비회원 의미 검색에서 사라지고 주인에게만 보였다.
- **전체 테스트**: 백엔드 `./mvnw test` 409개 통과. 프론트는 바꾸지 않았다.

## 명세와 다르거나 아직 채우지 않은 것

- **악센트를 가린다**: MySQL에서는 Café와 cafe가 같은 태그였는데 이제 다른 태그다. 지원 결정으로 받아들였다(R-02). 한글에는 영향이 없다.
- **의미 검색 503의 범위가 좁아졌다**: contracts는 "Ollama·추천 DB에 닿지 않으면 503"인데, 추천 DB가 없어져 "임베딩 서버에 닿지 않으면 503"이 되었다. 스텝 24에서 contracts를 고친다.
- **운영은 아직 MySQL**: 이 스텝의 코드는 배포 스크립트(스텝 24)가 바뀌기 전에는 운영에 나갈 수 없다. 그래서 코드 PR은 스텝 24까지 한 브랜치에 이어 커밋한 뒤 하나로 올린다.
- **문서의 기준 DB**: CLAUDE.md, plan, data-model, ERD(`erd/schema.sql`은 아직 MySQL DDL), quickstart는 스텝 24(T132)에서 고친다.
- **로컬 `blog-mysql` 컨테이너**: docker compose에서 뺐지만 이미 떠 있는 컨테이너는 그대로다. 지원의 8080 서버가 옛 코드로 쓰고 있을 수 있어 지우지 않았다. 필요 없으면 `docker compose up -d --remove-orphans`로 지운다(데이터 볼륨 `blog_mysql-data`는 남는다).

## 직접 해 보기

1. **개발 DB 준비**: 이미 떠 있는 `blog-postgres`에는 `recommend` DB만 있었다. `docker exec blog-postgres psql -U blog -d recommend -c "CREATE DATABASE blog"`(이번에 만들어 두었다). 처음부터 띄우는 사람은 docker compose가 `blog` DB를 만든다.
2. **서버**: `./mvnw spring-boot:run` → 로그에 `Migrating schema "public" to version "1 - init"`. 개발 DB가 새것이라 글·회원이 비어 있다(관리자 `admin@blog.test`만).
3. **대소문자**: 가입한 닉네임을 대문자로 바꿔 다른 계정으로 가입 → 409 `NICKNAME_TAKEN`. 태그 `Spring`을 단 글을 쓰고 `/@{주소}/tag/SPRING` → 같은 태그.
4. **한 쿼리**: `./mvnw test -Dtest=SimilarPostIntegrationTest -Dspring.jpa.show-sql=true 2>&1 | grep -m1 'cast(? as vector)'`로 글·임베딩·가시성이 한 SQL에 있는 것을 본다.
5. **psql**: `docker exec -it blog-postgres psql -U blog -d blog -c "\d member"` → `email | citext`, `ck_member_email_length`.
6. **테스트**: `./mvnw test -Dtest='SemanticSearch*,SimilarPost*,PostEmbedding*,TagIntegrationTest'`
