# 스텝 21. 블로그 주소를 경로로 (`blog.com/@주소`)

> 작업: T116, T117, T118, T119 · 코드 브랜치: `step-21-path-address` · 날짜: 2026-10-12 · 결정: research.md R-03(쿠키 Domain), R-04(블로그 주소 해석), 2026-10-12 지원 결정

## 한눈에 보기

배포할 학교 서버(nginx, `now-log.java21.net`)는 이름이 하나뿐이고 와일드카드 DNS가 없다. 그래서 스텝 3부터 써 온 서브도메인 블로그 주소(`alpha.blog.com`)를 열 수 없다. 블로그 주소를 **플랫폼 주소 아래 경로**(`blog.com/@alpha`)로 바꿨다.

API에게 "어느 블로그인지"를 알리는 방법은 두 안을 견줬다. ① API 경로는 그대로 두고 블로그 화면이 `X-Blog-Address: alpha` 헤더를 붙인다. ② `/api/blogs/{주소}/…`로 경로에 넣는다. ②는 블로그 API 59개의 경로·계약·테스트를 모두 바꿔야 해서 ①을 골랐다. 블로그 API가 모두 `@CurrentBlog` 한 곳에서 블로그를 받으므로, 그곳이 Host 대신 헤더를 읽게 바꾸는 것으로 끝났다.

| 작업 | 만든 것 | 핵심 파일 |
| --- | --- | --- |
| T116 서버: 블로그를 헤더로 | `BlogHostResolver`·`RequestHost`를 `BlogAddressResolver`·`RequestBlog`로. 헤더가 없으면 플랫폼, 규칙·예약어에 어긋나면 404. 서버가 만드는 블로그 링크(알림, 이사 301, `og:url`, 글 저장 응답 `url`)는 `http(s)://{플랫폼}/@{주소}/…`. 로그인·기기·방문자·state 쿠키는 `Domain` 없이(host-only). 소셜 로그인 뒤 돌아갈 곳은 플랫폼 호스트만. `GET /api/search`는 헤더가 있는지로 블로그 검색·전체 검색을 나눔 | `global/host/BlogAddressResolver`, `RequestBlog`, `CurrentBlogArgumentResolver`, `DomainProperties`, `auth/presentation/AuthCookieManager`, `global/web/VisitorKeys`, `auth/application/SocialAuthService`, `search/presentation/SearchController`, `notification/presentation/NotificationController` |

| T119 테스트 | 블로그 API 테스트를 `Host: {주소}.blog.test`에서 `X-Blog-Address`로, 화면 주소 테스트를 `/@주소`로, 쿠키는 `Domain=` 없음 확인, 링크·301 기대값은 `/@주소/…` | `support/TestBlogs`(`HEADER`, `url()`), `global/host/BlogAddressResolverTest`, `global/config/SpaForwardIntegrationTest`(`platformPage`·`blogPage`), `QuickstartScenarioIntegrationTest`, `auth/LoginIntegrationTest`, `host.test.ts`, `client.test.ts` |

API 경로(`/api/...`)와 응답 모양은 바뀌지 않았다. 바뀐 것은 "블로그를 정하는 곳"과 "주소를 만드는 곳"이다.

## 요청 흐름

```
[화면] GET blog.com/@alpha/manage/write      (Cookie: access_token, Domain 없음)
   → SpaForwardController: 경로 디코딩 → "/@"로 시작 → 주소 alpha, 블로그 안 경로 /manage/write
   → findBlog("alpha") 규칙·DB → 없음·예약어 404 / 이사 301 /@새주소/manage/write(주인은 200) / 200 index.html
[브라우저] App: parseLocation → blog alpha → <BrowserRouter basename="/@alpha"> → 라우트 /manage/*
   <Link to="/12"> → 주소창 /@alpha/12        플랫폼·다른 블로그는 <a href={platformUrl|blogUrl}>로 새로 열기
[API] POST blog.com/api/posts   X-Blog-Address: alpha   X-Requested-With: XMLHttpRequest
   → CsrfHeaderFilter → @CurrentBlog: 헤더 → BlogAddress(alpha) → DB → 볼 수 있나·이사 → Blog → 주인 확인
   ← 201 { id: 33, url: "http://blog.com/@alpha/33" }
[플랫폼 API] GET blog.com/api/home/posts  (헤더 없음) → 플랫폼
[검색] GET /api/search?q=…   헤더 있음 → 그 블로그 안 / 없음 → 전체 검색
[공유 미리보기] GET /@alpha/33 (봇) → og:url http://blog.com/@alpha/33, og:image http://blog.com/uploads/…
[로그인 복귀] /login?redirect=http://blog.com/@alpha/manage → 같은 출처면 돌아감(프론트), 플랫폼 호스트면 돌아감(소셜, 서버)
```

## 막혔던 점

- **옛 Domain 쿠키가 남은 브라우저(검토 중 발견, 고침)**: 스텝 21 전 쿠키는 `Domain=.{플랫폼}`이었다. 새 쿠키(Domain 없음)와 이름이 같아 브라우저가 둘 다 보내고, 서버는 앞(옛) 값을 읽고, 로그아웃은 새 쪽만 지워서 옛 Refresh 쿠키로 다시 로그인될 수 있었다. 같은 이름이 둘이면 뒤 값을 읽고 옛 쿠키를 지우라고 응답하게 했다(`AuthCookieManager`, `LogoutIntegrationTest.legacyDomainCookieIsIgnoredAndExpired`). 운영에도 이미 Domain 쿠키가 나가 있어 필요한 처리다.

- **경로 패턴에 `/`를 넣었더니 서버가 뜨지 않았다**: 태그 화면 패턴을 `/@주소/tag/{이름}`으로 바꾸며 첫 칸 정규식 안에 `/`가 들어간 모양으로 썼더니, 서버가 시작하다 `Expected close capture character after variable name }`로 멈췄다. Spring 경로 패턴은 `/`로 칸을 나누며 읽어서 중괄호 안의 `/`를 칸 끝으로 본다. `{…}`는 원래 한 칸만 맞추므로 `/`가 필요 없었다. `{s1:@[^.]+}`로 고쳤다([63](./concepts/63-블로그-주소를-경로로.md) 6장 함정 1).
- **`%40`으로 오는 주소**: `@`는 경로에 그대로 써도 되는 글자지만 도구에 따라 `/%40alpha`로 보낼 수 있다. `request.getRequestURI()`는 디코딩하지 않은 원문이라 `UrlPathHelper.getPathWithinApplication`(디코딩한 경로)으로 읽었다.
- **이사 301에 경로가 두 번 붙을 뻔했다**: 예전에는 `getRequestURI()`가 곧 블로그 안 경로였다. 지금은 `/@old/category/3` 전체라 그대로 새 블로그 주소에 붙이면 `/@new/@old/category/3`이 된다. `@주소` 뒤 블로그 안 경로만 넘기게 바꾸고, `movedBlogRedirectsWithSamePathExceptOwnersManagePages`가 확인한다.
- **공유 미리보기 사진 주소가 404였다**: `og:image`를 `og:url`처럼 `blogUrl`로 만들어 `…/@alpha/uploads/….png`가 나갔다. 사진은 블로그와 관계없이 `/uploads/…`에서 나간다. 학습 자료를 쓰며 다시 읽다가 찾아 `platformUrl`로 고쳤다(커밋 `efe5aab`). 서브도메인 때는 "블로그 주소 + 경로"가 화면과 파일 모두에 맞았지만, 경로 방식에서는 `/@주소`가 화면에만 붙는다([63](./concepts/63-블로그-주소를-경로로.md) 3.6, 5.3).
- **운영에서 깨졌을 링크를 피했다**: 예전 프론트는 플랫폼 주소를 `import.meta.env.VITE_PLATFORM_DOMAIN ?? 'blog.test'`에서 읽었는데, 배포용 Docker 빌드는 이 값을 정한 적이 없다. 그대로 배포했다면 운영의 로그인·블로그 링크가 모두 `http://blog.test/…`로 갔을 것이다. 이제 모든 주소를 `location.origin` 기준으로 만들어 설정이 필요 없고, 변수를 없앴다.
- **공유 주소가 플랫폼 경로가 될 뻔했다**: `ShareButtons`의 `${window.location.origin}/${postId}`는 서브도메인에서는 맞았지만 지금은 `/12`(블로그 없는 경로)다. `blogUrl(지금 블로그, '/12')`로 바꿨다. `origin`에 경로를 바로 붙이던 자리를 찾아 고쳤다.
- **실제 서버(8081)에서 확인한 것**: `/@주소`, `/@주소/{글}`, `/@주소/category/0`, `/@주소/tag/node.js`, `/@주소/guestbook`, `/@주소/manage` → 200. `/@nobody-here-x`, `/@admin`, `/@주소/99999999` → 404. `GET /api/blog`는 `X-Blog-Address`가 있으면 200, 없으면 404. 글 저장 응답 `url`과 `og:url`이 `http://blog.test:8081/@주소/33`. 화면이 쓰는 빌드 파일은 `/assets/…` 절대 경로라 `/@주소/…` 아래에서도 불러진다.
- **브라우저로 눌러 보는 확인은 아직 못 했다**: 이번에는 브라우저 도구가 없어 basename 링크를 실제로 눌러 보지 않았다. 서버 응답과 프론트 단위 테스트로만 확인했다. 아래 "직접 해 보기" 2에서 해 본다.
- **전체 테스트**: 백엔드 `./mvnw test` 398개, 프론트 `npx vitest run` 83개 통과(`og:image` 고침 전 기준).

## 직접 해 보기

```bash
./mvnw test -Dtest='BlogAddressResolverTest,SpaForwardIntegrationTest,CurrentBlogIntegrationTest,QuickstartScenarioIntegrationTest,LoginIntegrationTest'
cd frontend && npx vitest run src/app/host.test.ts src/api/client.test.ts
```

준비: `/etc/hosts`는 `127.0.0.1 blog.test` 한 줄이면 된다(블로그마다 줄을 더하거나 dnsmasq를 쓸 필요가 없다). 예전에 `blog.test`에서 로그인한 브라우저라면 개발자 도구 → Application → Cookies에서 `blog.test` 쿠키를 지운다(옛 `Domain=.blog.test` 쿠키와 새 쿠키가 둘이 되면 헷갈린다, [63](./concepts/63-블로그-주소를-경로로.md) 6장 함정 7).

1. **curl로 주소와 헤더**: [63](./concepts/63-블로그-주소를-경로로.md) 7장 실습 1, 2. 화면 주소의 200·404, `X-Blog-Address`가 있을 때와 없을 때, `Host: alpha.blog.test`가 이제 아무 일도 하지 않는 것.
2. **브라우저로 눌러 보기**(이번에 못 한 확인): `http://blog.test:8080/@{내 블로그}` → 글·카테고리·태그·방명록 링크가 `/@주소/…`로 가는지, 새로고침해도 같은지 → 관리 → 글쓰기 → 발행 후 주소창이 `/@주소/{번호}`인지 → Network 탭의 `/api/…` 요청에 `X-Blog-Address`가 있는지, 플랫폼 홈의 요청에는 없는지 → 머리글 "마이페이지"·로고가 `/me`·`/`로 가는지 → "주소 복사"가 `/@주소/{번호}`인지 → 로그아웃 상태로 `/@주소/manage` → 로그인 → 다시 `/@주소/manage`로 오는지([63](./concepts/63-블로그-주소를-경로로.md) 7장 실습 4).
3. **쿠키**: 로그인 응답 `Set-Cookie`에 `Domain=`이 없고, Cookies 표의 Domain이 `blog.test`(앞 점 없음)인지([63](./concepts/63-블로그-주소를-경로로.md) 7장 실습 3).
4. **공유 미리보기**: `curl -s http://blog.test:8080/@{주소}/{공개 글} | grep -o '<meta property="og:[a-z]*"[^>]*>'` → `og:url`은 `/@주소/{번호}`, `og:image`는 `/uploads/…`(`/@주소` 없음).
5. **운영(배포 뒤)**: `http://now-log.java21.net/@{주소}`를 열고 글 저장 응답 `url`·알림 링크에 `:8460`이 붙지 않았는지 본다([63](./concepts/63-블로그-주소를-경로로.md) 7장 실습 6).
6. **패턴 함정 재현**: [63](./concepts/63-블로그-주소를-경로로.md) 7장 실습 7.
