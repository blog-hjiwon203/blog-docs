## 왜
PR #29 병합 뒤 배포 워크플로에서 `HomePopularIntegrationTest.rankingIsCachedButPostsThatBecameHiddenDropOutAtOnce`가 실패했다(다시 돌리니 통과). 실패한 결과는 캐시를 비우기 **전** 순위와 같았다.

## 원인
Spring Data Redis 4의 `RedisCache.clear()`는 연결이 비동기를 지원하면(Lettuce) 지우기 명령을 보내고 **기다리지 않고** 돌아온다(`DefaultRedisCacheWriter.clear` → `AsyncCacheWriter.clear`). 반면 `invalidate()`는 다 지운 뒤 돌아온다. 테스트가 `clear()` 바로 뒤에 요청을 보내면 옛 순위를 읽을 수 있다. 느린 CI에서 가끔 드러났다.

임시 테스트로 2000번씩 재 본 결과(로컬):
| 동작 | 직후 읽기 |
|---|---|
| `clear()` 직후 | 1865번 옛 값 |
| 넣기가 끝난 뒤 `invalidate()` 직후 | 0번 |
| `get(key, 계산)`(앱의 `@Cacheable(sync = true)`가 쓰는 길) 직후 | 0번 빠짐 |

앱 코드는 캐시를 직접 지우지 않고, 인기·주제 순위는 `sync = true`라 넣기가 바로 반영된다. 바뀌는 것은 테스트뿐이다.
