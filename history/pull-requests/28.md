## 요약
학교 실습 서버(s2, 개인 포트 8460~8469)에 1차 배포하기 위한 설정. main에 병합하면 GitHub Actions가 테스트 → 이미지 빌드 → 서버 배포까지 자동으로 한다.

## 바뀐 것
- `.github/workflows/deploy.yml`: main push(또는 Run workflow) 시 `./mvnw test` → `docker build` → scp로 서버 `~/now-log`에 전송 → ssh로 `deploy/deploy.sh` 실행
- `Dockerfile`, `.dockerignore`: 프론트(node) → jar(JDK 21) → 실행(JRE 21) 3단계 빌드
- `deploy/deploy.sh`: 서버에서 `aigj017-redis`(같은 docker 네트워크 안에서만, 비밀번호 걸림, 볼륨 유지)와 `aigj017-app`(8460, `~/uploads` 연결)을 띄우고 시작될 때까지 기다림. 실패하면 로그를 남기고 실패로 끝남
- `app.recommend.enabled` 추가(기본 켬). 끄면 추천 DB·임베딩 부품을 만들지 않고 `GET /api/posts/{id}/similar`는 빈 배열(contracts의 "추천이 준비 안 됐으면 빈 배열"과 같음). 운영은 1차 배포라 끔 → PostgreSQL·Ollama 없이 뜸
- `application-prod.yml`: 포트 8460, `forward-headers-strategy: native`(nginx 뒤 실제 IP), 플랫폼 `now-log.java21.net`, http라 Secure 쿠키 끔
